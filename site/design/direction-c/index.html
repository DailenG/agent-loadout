Open source · MIT · Windows and Linux

Every agent's config, on the record.

Loadout keeps your MCP servers, skills and secret references in one versioned, offline store, and writes them into each AI coding client's own config file. Every change is a commit. Every apply can be undone. Entries it didn't write are never touched.1

§ 1

One entry, many dialects.

You write a server once. Loadout renders it into each client's own file, in that client's own syntax, down to how it spells a secret reference. Comments and key order in the file stay as they were.

Source store/servers/github.toml

id = "github"
transport = "stdio"
command = "npx"
args = ["-y", "@modelcontextprotocol/server-github"]

[env]
GITHUB_PERSONAL_ACCESS_TOKEN = "${secret:GITHUB_PAT}"

[enable]
clients = ["omp", "cursor", "opencode"]

omp ~/.omp/agent/mcp.json

"github": {
  "command": "npx",
  "args": ["-y", "@modelcontextprotocol/server-github"],
  "env": { "GITHUB_PERSONAL_ACCESS_TOKEN": "${GITHUB_PAT}" }
}

Cursor ~/.cursor/mcp.json

"github": {
  "command": "npx",
  "args": ["-y", "@modelcontextprotocol/server-github"],
  "env": { "GITHUB_PERSONAL_ACCESS_TOKEN": "${env:GITHUB_PAT}" }
}

OpenCode opencode.jsonc

"github": {
  "type": "local",
  "command": ["npx", "-y", "@modelcontextprotocol/server-github"],
  "environment": { "GITHUB_PERSONAL_ACCESS_TOKEN": "{env:GITHUB_PAT}" }
}

Where a client can't expand a reference, Loadout starts the server through loadout exec, which fetches the value from the keyring or 1Password at launch and never writes it to disk.

§ 2

Terms of engagement.

What Loadout promises your config files, and the people who wrote them.

  1. I

    It owns only what it wrote.

    A ledger on your machine records every entry Loadout wrote. Anything else is foreign: shown, never edited or removed unless you adopt it.

  2. II

    Secrets stay references.

    Env vars, the OS keyring or 1Password. A leak scanner checks every commit, so no value reaches the store, a snapshot or a remote.

  3. III

    Every change is a commit.

    History, semantic diffs, named tags and restore, all in a local git repository. Remotes are optional: any git URL or a plain folder.

  4. IV

    Projects ask first.

    A project manifest can run commands, so it stays read only until you review its diff and trust it.
