How a loadout ships

  1. Define it once

    Add a server or skill to the store. It lives as plain TOML in a local git repository, fully offline. Secrets go in as references like ${secret:GITHUB_PAT} that point at an environment variable, the OS keyring or 1Password.

    01

  2. Review the plan

    Loadout shows exactly which file changes for which client, entry by entry. Entries you wrote by hand are foreign: they are listed, never edited or deleted.

    02

  3. Apply, with an undo

    Edits keep your comments and key order. Every write backs up the file first and lands as one commit, so Undo this apply is always one click away.

    03

One kit, every case

Each client keeps its own file format. Loadout speaks JSON, JSONC, JSON5, TOML and YAML, edits in place, and writes only the entries it owns.

Ship to

Windows 11

Signed per-user installer. No admin rights; puts loadout on your PATH and updates itself.

Download installer (.exe)
winget install DailenG.AgentLoadout

winget and Chocolatey: pending approval.

Ship to

Linux

AppImage (updates itself), .deb or .rpm. Built for Arch on Hyprland and the usual suspects.

Download for Linux
yay -S agent-loadout-bin

AUR packages: pending publication.

Ship to

macOS and CLI only

No macOS app yet. The loadout command line builds anywhere Rust does.

cargo install agent-loadout

Every release lists SHA-256 sums for each asset.
