# M26 Sidebar scope switcher: completion note

Not committed (the maintainer commits). Implements issue #7. Part a (shell, slice S1) is below; part b (Skills, MCP and Tools follow the sidebar, and the System-to-User rename everywhere) is wave 2. SPEC 13.1 (shell), 13.3 (Add folder, trust review), 17 (trust).

## Part a: the scope switcher in the shell

### What was built

- **One active scope for the shell.** `src/app/scope/ActiveScope.tsx` (contract C1): `ActiveScope` (`{ kind: "user" } | { kind: "project"; id }`, the shape of `SkillScope`), `ActiveScopeProvider` (optional `initial`) and `useActiveScope()` returning `{ scope, setScope, project }`, where `project` is the selected project's `ProjectRow` from `list_projects` (`storeQueryKeys.projects`). The provider wraps `AppContent`. It loads the project list only while a project is selected (the sidebar loads it anyway). When the selected id leaves the list, the scope falls back to User in the same render, and the state follows. The scope lives in the shell only and isn't persisted: a restart opens User (maintainer decision Q1). `useProjectList` and `projectListQuery` are the one definition of the project list query; the Projects page uses them too.
- **The sidebar switcher** (`src/app/scope/ScopeSwitcher.tsx`, replacing the System-only `ScopeSwitcher` in `App.tsx`):
  - **User (all your projects)** first (closed: **User**);
  - one entry per project: its name, a trust icon (shield with a check for trusted, an exclamation for not trusted yet or manifest changed, a cross for folder missing or manifest unusable; the icon's accessible name is the trust label) and a tooltip with its placeholder path and trust (`~/code/app (Trusted)`);
  - with no projects, a one-line disabled hint ("No projects yet. Add a folder to configure it on its own.");
  - **Add folder...** last, as an action item with a separator.
  - An untrusted project can be selected (its pages show M24's read-only state once they follow the scope in part b).
- **Collapsed sidebar.** The switcher is hidden as before; in its place an icon (person for User, folder for a project) whose tooltip and accessible name are "Scope: User (all your projects)" or "Scope: NAME". Clicking it expands the sidebar.
- **Add folder flow.** `src/app/routes/projects/AddFolderFlow.tsx` (`useAddFolderFlow`) is the pick, `FolderDialog`, `TrustReviewDialog` sequence extracted from the Projects page; it also opens the trust review of a listed project (the card's Review). After an add or init, it fetches the project list (even with no list on screen) and then reports the new project, so selecting it can't race the fallback; a project that isn't trusted yet opens its review next. The sidebar's Add folder and the Projects page's Add folder and Init manifest select the new project as the active scope. The sidebar renders the flow's dialogs in a portal on `document.body`.
- **Projects page.** Uses the flow; the empty state has an **Add folder** button (the #1 empty-state finding).
- **`AppSelect`** options take an optional leading `icon`, a `tooltip` (`data-tooltip`) and `onSelect`, which makes the option an action: choosing it runs `onSelect` instead of `onChange`, and it's never shown as selected. Existing selects are unchanged.
- **`list_scopes` is gone.** `Scope` and `list_scopes` were deleted from `src-tauri/src/commands/mod.rs` and unregistered in `main.rs`; the switcher reads `list_projects`, whose JSON is already covered by `assert_no_root` (`init_is_private_by_default_trusted_and_one_commit`). The mock transport drops `listScopes` and its `scopes` option and gains `projects` (what `listProjects` answers).
- **Strings.** New `scope.*` block (`scope.user`, `scope.userOption`, `scope.addFolder`, `scope.noProjects`, `scope.projectTooltip`, `scope.collapsed`). `scopeLabels` and `scopeOptionLabels` were deleted; their only other uses (the MCP card's scope chip and its Scope detail, `McpPage.tsx`) now say `t("scope.user")`, "User". The rest of the rename is part b.

### Decisions

1. **Closed and open labels differ**, as before: the closed switcher says "User" (the sidebar is narrow), the menu says "User (all your projects)".
2. **Every add selects the new project**, from the sidebar or the Projects page, so "after an add, the new project becomes active" holds wherever the add started.
3. **The provider queries projects only for a project scope.** A User-scoped page rendered alone (tests, `renderWithProviders`) makes no extra `list_projects` call; in the app the sidebar's query keeps the list current, and the provider shares its cache.
4. **A fallback is a real switch.** When the selected project leaves the list, the scope becomes User and stays User if the project comes back.

## Part b: pages follow the sidebar, and User replaces System

### What was built

- **Skills, MCP and Tools follow `useActiveScope()`.** `SkillsPage.tsx` and `McpPage.tsx` no longer keep a scope of their own; they read the sidebar's scope. A switch closes the open card and, on MCP, the store and project editors; Skills also returns to its Store tab. The reset happens during render (the page keeps the scope it last showed and compares), so no frame shows the old card against the new scope.
- **`ScopeSelect` is deleted** (`src/app/components/ScopeSelect.tsx` and its `skills-scope-select` rule). No page renders a scope select; the now-unused `skills.scope.aria|user|project` and `mcp.scope.aria|user|project` strings are gone.
- **Tools at project scope.** The cards name the active project's files under its placeholder path ("Files in web": `<P>/.mcp.json` becomes `~/Code/web/.mcp.json`; user files keyed by project stay as sent). The Manage dialog follows the scope:
  - at User, unchanged (store servers, `set_server_clients`);
  - at project scope it lists the project's manifest entries from `list_project_servers` (suppressions and invalid entries have no switch) and toggles the client through `set_project_server_clients` with M24's rules: the content hash the list showed, the entry's edit layer, the manifest's written client list as the base (or, for `all-detected`, the clients the pills show selected), and one edit at a time (every switch waits while an edit runs or the list refetches); after an edit the project list is refetched;
  - the store servers the project inherits are listed read only under "From your user scope", each with **Open on MCP page** (closes the dialog and navigates; the scope stays the project, so the MCP page shows the same project);
  - an untrusted or changed project shows M24's notice with **Review & trust** (the trust review opens on top; Escape closes only it), and every switch is disabled;
  - the title carries `RecommendedBadge` (C3); the cards' order is S2's (detected first, then omp).
  - `ToolsPage` takes `onOpenMcp`; `App.tsx` passes `onNavigate("mcp")` (one line, with Main's approval).
- **History filter `System` becomes `User`.** Rust `HistoryScope::System` is now `HistoryScope::User` (serialized `user`; it still maps to the core's `TrailerScope::System`, the commit trailer value is unchanged). `HistoryPage.tsx` and `labels.ts` offer All / User / Projects. History stays cross-scope and does not follow the sidebar.
- **Wording.** `history.scope.system` is `history.scope.user` ("User"), `matrix.layer.system` is `matrix.layer.user` ("User") and the matrix letter S is U ("U user" in the legend), the MCP project view's inherited heading is "From your user scope", `cannot_suppress_in_project` says "user-scope server". Only OS strings keep "System" ("System git credentials", the theme's "Follow System").
- **Docs.** SPEC 13.1 (diagram: User, projects with trust, Add folder; a paragraph on what follows the scope, what a switch resets, no persistence, History's filter), 13.2 (User chip and layer, project scope through the sidebar), 13.3 (matrix U letters and legend), 13.5 (the filter), 13.7 (Tools paths and the scope-aware Manage dialog, Skills through the sidebar). `docs/user-guide.md` (the switcher, the pages that follow it, Tools Manage at project scope, History's filter, "user-scope server", the MCP project section). README status (M26; M6 "user-scope").

### Decisions

1. **Core names stay.** `LayerKind::System`, `TrailerScope::System` and the CLI's `--scope system` are core and CLI contracts (the CLI keeps its flag); only the GUI IPC filter enum and every user-facing string changed.
2. **Suppressions have no switch in Manage.** For a suppression "selected" means hidden; a per-client on/off switch would read backwards. They are managed on the MCP page.
3. **Drift pills toggle in Manage** as the store-scope dialog always did (the dialog has no route to the Pending drawer); the MCP page keeps sending drift to Pending.
4. **Tests drive the scope through a stand-in for the sidebar.** `src/test/ScopeDriver.tsx` renders buttons that call `setScope`, so a test can switch a page while it is shown; tests that start in a project use C2's `scope` option.
