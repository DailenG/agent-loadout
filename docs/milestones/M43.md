## #16 Skills install, enable and listing at scale

- `link::DetectedClients` (replaces `link::selected_clients`): client detection for the skill-folder clients, probed once on first need and kept for one operation. `sync` (desired state), `next_selection` and `list_skills` (the per-skill `clients`, the tool pills, the project scope's clients) share one per call. Before, every skill enabled for `all-detected` ran every client's detection.
- `sync`: desired entries are deduplicated and stale ledger entries found with `HashSet`s of path keys instead of O(n^2) `same_path` scans; `list_skills` computes the project's `[skills]` once instead of per skill.
- `skills/install.rs` is untouched (M39/M40 own it); it benefits through `store::list`.

## #17 Long GUI lists

- `src/app/components/useVirtualSlots.tsx` (`useVirtualList` + `VirtualSlot`): every item keeps a slot element (one host element: keys, order and list semantics stay; an `li` slot keeps its accessible name), and only slots near the scroll viewport (800 px margin) render their content. An `IntersectionObserver` rooted at the list's scroll container decides; each slot subscribes to its own state (`useSyncExternalStore`), so a scroll re-renders only the slots that cross the margin, never the page. A slot whose content is not rendered keeps the height it had when last seen, or an estimate, and holds the item's name as a visually hidden heading (a hidden span in an `li`), so screen readers and find-in-page reach every item. The first 24 items render before the observer first answers (no blank first paint). Pinned items always render, and so does a slot holding the focus; an item that stops being pinned forgets its height, and a new `layout` (view mode) forgets all heights. Without `IntersectionObserver` (jsdom, old engines) every slot renders.
- Skills (list, grid rows, grouped lists; the expanded card, a busy card and their grid rows pinned) and MCP (list and grid; the expanded, delete-confirming, deleting and bulk-toggling cards pinned) use the virtual list. History does not (see "List decision" below): plain rows, 200 a page, "Load more" with a `before` cursor.
- CSS: `/* M43 */` block at the end of `src/styles/tokens.css` (`.virtual-slot`).
- `scripts/perf/chromium-lists.mjs`: the Chromium measurement as a script (DOM counters, task ms, a scripted 3 s scroll per page).

Test `an_unreadable_store_file_is_listed_and_adopt_skips_its_id` (`tests/skills_adopt.rs`; Windows: a deny-read-data ACE through `icacls`, Unix: mode 000; skips where the file still reads): failed without the open probe (`has_content` stayed true). 2. Per-slot subscriptions (above); History rows are `memo` with stable callbacks taking the entry. Test `re-renders only the slots whose state a scroll changed, never the list`; not observed failing against the old hook, which this replaced whole. Chromium re-measured: perf section 11.
3. Placeholder names: test `names every placeholder...` (failed with the name removed) and the Skills page test below.
4. Skills grid rows are keyed `row:<index>`: test `keys grid rows by position...` (`SkillsPage.virtual.test.tsx`; failed with the old key).
5. `VirtualList.pin` drops the height of an id that leaves `pinned`; `setLayout` clears heights and reports and observes every slot again. Test `forgets heights on a layout change and for an item that stops being pinned` (failed with both removed).

## List decision (Main, after the review)

Measured in Chromium, variants alternated in one run, 3 rounds each (perf section 11):

- **Skills and MCP keep the virtual list.** `content-visibility: auto` without unmounting scrolled about the same (medians 719 vs 854 ms Skills, 682 vs 770 ms MCP, within the spread) but held 3.3 to 5.6x the DOM at rest, past the 2x bound. The measurement switch (`?cv`) is removed.
- **History drops the virtual list and does not use `content-visibility`** (a deviation from the requested CSS, on the numbers): rows with `content-visibility: auto` scrolled at 1,109 to 1,960 ms of main-thread time in 3 s, plain rows at 115 to 336 ms (0.2.0: 70 to 146). History now loads 200 rows a page; "Load more" sends `before` = the last shown commit, so a page never refetches the loaded ones; the button keeps the focus while loading (`aria-disabled`) and a polite status says "N commits shown". Rows stay memoized with stable callbacks.
- Tests: `history_filters_by_entity_scope_and_limit` (core, `before` pages and an unreached cursor; passed), `a_limit_lists_the_newest_commits_as_a_first_page` (app: next page after the cursor, an invalid cursor refused; not run: the app crate does not compile because of siblings' edits), `loads the list a page at a time after the last shown commit, and keeps the focus on Load more` (`HistoryPage.test.tsx`; passed).
