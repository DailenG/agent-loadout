- `Plan { targets: Vec<TargetPlan>, warnings }`; `TargetPlan { clients, scope, file, container, pointer, before, after, entries, problem, warnings }` with `diff()`, `counts()`, `unresolved()`; `EntryPlan { name, client, server_id, state: EntryState, action: Action, unresolved, problem, desired, observed, written, delivery }`.
- `ApplyReport { apply_id, trigger, outcome, targets: Vec<TargetResult>, warnings, imported, recorded }`; `TargetResult` adds `counts`, `outcome`, `error`, `written`, `backup`.
- `render::DesiredState::{load(&dyn StoreRead, machine_id), empty(), apply_mode(), prefs()}`; `render::system_entries`, `render::render`, `render::native_to_template`.
- `ledger::{Ledger, LedgerEntry, EntryKind, Origin, LedgerKey, container_pointer}`; `LedgerKey::{load, load_or_create, hash}`.

- CLI: `loadout status [--client C]... [--check]`, `diff [--client C]... [--exit-code]`, `apply [--client C]... [--dry-run] [--on-conflict ask|skip|overwrite|import]`, `rollback <APPLY-ID|last>`, `import [--scan] [--client C]... [--only] [NAME]...`, `adopt [CLIENT/NAME]... ## Spec ambiguities resolved

1. **Entry states for rows without one.** AdoptSilently is `synced` with action `adopt`; DropLedger is `synced` with action `forget`; DriftedOrphan is `drifted`. The (D,O,L) "conflict" row is `drifted` when desired is unchanged since the write (`h(D) == L.hash`) and `conflict` otherwise, matching the 8.2 definitions.
2. **Resolutions (`--on-conflict`).** `ask` (default) leaves the entry and counts it unresolved (exit 4); `skip` leaves it as resolved; `overwrite` writes desired (a collision becomes `origin = adopted`; a drifted orphan is removed); `import` turns the native entry into the store definition, releases a drifted orphan, and for a `missing` entry respects the deletion by dropping the client from the server's enable list. `missing` re-creates by default.
3. **"Per user preference" for native disable.** `clients.toml` gains `native_disable = true` per client. Only clients with an in-entry mechanism (omp, Pi, Codex `enabled = false`) disable; the others remove.
4. **"An apply with zero writes makes no commit".** A standalone run (`loadout apply`, `adopt` without `--theirs`) commits only when a client file was written; ledger-only work (adopt, forget) is not a write. When the transaction commits anyway (an instant-mode edit, an import, a rollback, an `import` resolution) the run is always recorded in that one commit.
5. **`store_revision` in `applied.toml`.** The commit the run started from (HEAD before its commit). In instant mode the applied state includes the edit in the same commit, which cannot name itself; the commit holding the record is the one carrying the `Loadout-Apply` trailer.
6. **Rollback target.** "The parent of the apply commit" is generalized to the nearest earlier apply commit of this machine, or the initial commit. In instant mode those coincide; in review mode the parent already holds the edits the run applied, so the parent would undo nothing. Only the files the run changed (between those two commits) are restored, so later edits to other entities survive; `machines/*.applied.toml` and other machines' overlays are never restored. "Later applies touched the same entries" is checked per file; the latest run never asks. A rollback of a run whose desired state did not change (an `adopt` overwrite) restores nothing; exact bytes come from `backups/files`.
7. **Tags.** `auto/pre-rollback/<ts>` is a lightweight tag on the commit before the rollback (`-2`, `-3` when taken). Annotated tags and pruning are M11.
8. **Placeholders in `applied.toml`.** Files outside `~` (for example `CODEX_HOME` or a redirected `%APPDATA%`) could not be written with `~/` or `<P>/`. The validator now accepts `%NAME%/` and `$NAME/` roots; Loadout picks the longest of `~`, `%APPDATA%`, `%LOCALAPPDATA%`, `$XDG_CONFIG_HOME` and the adapters' override variables in force, else `%EXTERNAL%/<file name>` (`$EXTERNAL` off Windows).
9. **Delivery before M8.** `${env:NAME}` is written in the client's syntax where it expands that field (`env` mode, SPEC 11.4 rule 1); Codex forwards `NAME = "${env:NAME}"` env values, bearer and header references. Every other reference (`${secret:..}`, an env reference in a field the client does not expand, `delivery.mode` `launch`/`command`/`inline`) blocks the entry with `delivery_unavailable`; nothing falls back to plain text. A literal `${` in a field the client expands is blocked too, since no Tier A client documents an escape.
10. **Tool filters on clients without native fields** stay blocked (`unsupported_field`, M5 note 9) rather than dropped with a warning.
11. **Shared files (SPEC 6.5).** Clients whose targets resolve to the same file and container (omp and Pi under one `PI_CODING_AGENT_DIR`) form one target; the entries are the union, and one name desired differently by two clients is blocked (`collision`).
12. **Invalid server files** are reported as warnings; entries the ledger records for those servers are left alone (`blocked`, `parse_error`), never removed.
13. **Self check "byte-identical".** After an edit, owned entries must read back canonically equal to desired, and every other entry of the container and the whole document outside it must be equal as values. Byte identity of untouched text is the editors' guarantee (M3 property tests) and is asserted end to end by `foreign_entries_and_unrelated_keys_stay_byte_identical`.
14. **Files are never deleted.** Removing the last owned entry leaves the container (`"mcpServers": {}`) and the file; deleting files Loadout created would need a ledger record of file creation.
15. **Import before secret extraction (SPEC 11.7, M7).** An entry imports only when every `env` and `headers` value holds a reference and no argument or URL query names a credential (a keyword subset of the classifier) or the URL has userinfo; otherwise `needs_secret_extraction`. Client variable syntax converts to `${env:NAME}` (`${NAME:-d}` and `headersHelper` are `unsupported_field`). The server id is the entry name in lower case, with `native_name` when they differ. Differing definitions across clients are skipped with `collision` until imported with `--client`.
16. **Triggers and ops.** `loadout apply` and `adopt` record trigger `review`; edits (`server add|rm`, `import`) `instant`; rollback `rollback`. Ops: `apply`, `apply.rollback`, `server.import`, `entry.adopt`. Apply commits do not add a `machine/<id>` entity; `history --entity machine/<id>` finds them through the record's path.
17. **Container pointer** in the ledger is an RFC 6901 JSON pointer of the resolved keys (`/mcpServers`), so project keys holding `/` stay unambiguous.

## Deviations

- **No `ReplaceFileW`.** The workspace forbids `unsafe`, and no maintained safe wrapper exists. On Windows the temp file is created with the original's attributes (hidden, system, archive, not-indexed) and, when the original has a protected DACL or explicit ACEs, its DACL; then `rename` replaces the file. A DACL made only of inherited entries is already what the temp file in the same folder gets. AP-2 checks this on a real profile.
- **System scope only.** `loadout apply [PATH]`, `--scope` and project targets arrive with M9; the ledger already records `scope` and `project_id`.
- **Ledger key in `state/ledger.key` only**; the OS keyring option arrives with the keyring provider (M7).
- **No masking** in `diff`: no delivery mode writes secret values yet.
- **No `loadout restore --files`** (M11); backups are written and pruned (50 runs or 30 days).
- **`restart_required`** (Claude Desktop) is not surfaced in CLI output yet (AP-6).
- **No skill-link ledger kind** (M18); unknown ledger kinds fail to parse instead of being dropped, so ownership is never lost silently.
- **Unfinished journals** are reported by `loadout status`, not yet by `doctor`.
- **`all-detected`** uses path and `PATH` probes only; the CLI still has no registry probe (M4 deviation).
- `cargo deny check` and CI were not run (no cargo-deny locally, no push).
