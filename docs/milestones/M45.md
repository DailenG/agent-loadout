# M45 Catalogs GUI: Install > Browse and Settings > Catalogs (0.6.0, #26)

Status: implemented. Not committed (the maintainer commits). Built on the M44 contract
(`docs/milestones/M44.md`, including its "Changes since publication": `open_catalog_link`, added for this
slice). No IPC of its own; `src/ipc/bindings.ts` is regenerated with `npm run bindings`.

## What was built

### Install > Browse (`src/app/routes/install/catalog`)

- A third category in the Install header, **Browse**, next to Skill and MCP (`InstallPage.tsx`).
- **First use**: until the user answers, Browse shows only the question "Turn on online catalogs?" with one
  sentence naming the hosts it would contact (`CatalogsOverview.contacts`) and when ("only when you open Browse,
  search, open an entry or install ... your search words and nothing else"). Before the answer the only command
  called is `catalogs_overview` (local); no search, show, refresh, review or link command runs. **Not now**
  records "off" (`set_online_catalogs(false)`), so the question is not asked again.
- **Off**: a note says nothing is contacted and results are saved ones only, with **Turn on online catalogs**.
  Searches still run (the backend answers from the cache with status `off`); installs say online catalogs need to
  be on and offer the switch instead of a Review button.
- **Search**: one `search_catalog` per enabled, searchable catalog (link-only ones are never searched), each in
  its own section with its own `useInfiniteQuery`, so a slow or failing catalog never holds up the others.
  Opening Browse runs the empty search (taps list their entries; registries say "Type at least 3 characters").
  `staleTime: Infinity`: a remount or tab switch reads what was answered; requests happen only on the user's
  search, **Try again** (`refresh_catalog`, then the search again) or **More results** (`nextCursor`).
- **Per-catalog status** (one `role="status"` line per section, `catalogText.ts#statusLine`): searching, "N
  results" (fresh), "N results, saved 2 hours ago" (cached), "Stale: N results saved 1 day ago. Couldn't refresh:
  ..." (stale with age and reason), "Offline: N results saved ..." / "Timed out: N results saved ..." (stale
  while `navigator.onLine` is false / after a timeout), "Online catalogs are off: N results saved 3 days ago" or
  "... nothing is saved for this search" (off), query too short, and errors worded as "Timed out: X took too
  long to answer.", "Offline: X can't be reached." or "Couldn't search X: <reason> (<detail>)". **Try again**
  appears on stale and failed catalogs while online.
- **Results** (cards, plain text only): name, kind (MCP server, skill, plugin), the entry id when it differs,
  description, publisher, version, pinning, last update, and **Official** / **Deprecated** / **Can't be
  installed** marks. Registry sections carry the attribution "Data from the Official MCP Registry" (from the
  backend's `attribution`). No catalog icon or image is ever rendered (the IPC entry has no icon field; the test
  asserts no `img`, `image`, `object` or `iframe`).
- **Wording per research**: publisher "Publisher: <namespace> (namespace ownership checked by the registry)" when
  `publisher.checked` is set, else "Publisher: <name>"; **Official** only where `entry.official` (an
  `github.com/anthropics` tap) and on the catalog heading when `CatalogInfo.official`; never for registry
  entries. Pinning: registry servers "Pinned to version <v>" or "Not pinned"; tap entries "Pinned to <sha7>"
  (a `sha` or a pinned commit), "Follows branch <ref>", or "Not pinned".
- **Detail view** (`EntryDetail.tsx`, an `article` replacing the list; focus moves to its heading, **Back to
  results** returns focus to the entry's Details button): `show_catalog_entry` for the full entry (the listed
  one shows meanwhile; a stale or off answer is labeled "Details saved 1 day ago; couldn't refresh: ..." /
  "Online catalogs are off: details saved ..."), source and catalog kind, entry id, publisher, version,
  pinning, last update, transports, required secret names ("None listed" when empty; never values), license
  when known, folder and commit for tap entries, repository and website with **Open** (`open_catalog_link`: the
  URL is looked up by the backend, never sent by the app), packages (with a "Not pinned" mark per package),
  remote endpoints, a plugin's skills, MCP servers ("known after the review" for non-relative plugins) and the
  parts not imported, the deprecation message, the reserved-name warning and the registry attribution.
- **Install handoff** (never a shortcut):
  - **Review MCP server** -> `review_catalog_mcp(catalog, entry, null)` and the M41/M42 review, rendered in place
    by the shared `McpSourceReviewView` (drafts, trust question, scan gate, client picker, Save). The review shows
    "From the catalog <title>: catalog:<source>/<id>", and its source facts gain "MCP registry" as the kind, the
    catalog entry and the version (`McpSourceInfo.catalog`/`version`).
  - **Review skill** -> `review_catalog_skill(catalog, entry, skill)` and the skill install review
    (`useReviewInstall`, now its own module), with the same origin line. A plugin with several skills shows a
    radio pick list and the button stays off until one is picked ("Review skill pptx"); one skill is picked for
    the user.
  - `entry.problem` (npm/archive/command plugin sources, deleted entries) shows "Can't be installed: <reason>"
    and no Review button.
  - The review in place disables Back and the Review buttons while it saves, so a save in flight is never
    discarded by leaving.
- **skills.sh** (`kind = "link"`): a card with **Open skills.sh** (`open_catalog_link(id, null, "catalog")`) and
  a field for a pasted `https://skills.sh/<owner>/<repo>/<skill>` address, reviewed through `review_git_skill`
  (M44 accepts these URLs) with the origin line. A `skills.sh/site/...` address or a malformed one is refused
  in place with a message, before any command.

### Settings > Catalogs (`src/app/routes/settings/catalogs/CatalogsSection.tsx`)

- **Online catalogs** checkbox with the hosts it contacts (on) or "nothing is contacted" (off).
- The list (`sources-list` styling): title, catalog kind, **Built in**, **Official**, URL and ref; a "Use <title>"
  checkbox per catalog (`set_catalog_enabled`); **Remove** (with a confirmation) only for user-added ones.
- **Add catalog...**: kind (MCP registry or Git tap, radios with hints), address, branch/tag/commit (taps only),
  optional name and id; errors from `add_catalog` show in the dialog. Nothing here contacts a catalog.
- `catalogs_overview` is a store query key (`storeQueryKeys.catalogs`), so pulls, restores and other store
  changes refetch it; mutations write the returned overview into the cache.

### Shared changes

- `McpSourcePanel.tsx`: the review part is now `McpSourceReviewView` (props: `review`, `clients`, `origin`,
  `onDiscard`, `onSaved`, `onSavingChange`; keyed by token) plus `useDiscardOnLeave`; the From Git or folder
  panel uses it unchanged in behavior (Find servers stays off while saving).
- `SkillReviewDialog` gains `origin`; `useReviewInstall(onView)` moved to `install/useReviewInstall.tsx` and its
  `review(load, id, onDone, origin?)` takes the origin line.
- `en.ts` (M45 block), errors `catalogs_off` and `catalog_unreachable`. `tokens.css` (M45 block): theme tokens only
  (`--heading`, `--muted`, `--success-text`, `--warning-text`, `--danger-text`, surfaces and lines); the two pairs
  M45 adds (`--heading` on `--surface-muted` and on `--warning-soft`) are in `tokens.contrast.test.ts`; visible
  focus on the detail and install headings.
- Mock transport: `src/test/catalogData.ts` (built-ins, two user catalogs, entries for every state: fresh,
  cached, stale, off, query too short, timeout error, deprecated, unpinned, refused npm plugin, multi-skill
  plugin, pinned GitHub plugin, branch-following tap skill) behind a stateful mock (online, decided, list
  changes). `createMockTransport({ catalogs })` seeds it; the demo dataset adds the user catalogs with a cached,
  a stale and a timed-out catalog. `review_catalog_*` answers are recorded for the trust/scan gates like the
  other reviews.

## Accessibility

Every control is a native button, input, checkbox or radio with a visible label or an `aria-label` naming its
entry ("Details of Weather", "Open the repository of Weather in your browser", "Search Team skills again", "Use
Official MCP Registry", "Remove Team skills"). Sections and result cards are named by their headings
(`aria-labelledby`), statuses are `role="status"` live regions, refusals are `role="note"`/`alert`, the search
form is `role="search"`. Opening an entry moves focus to its heading; Back returns it to the entry's button.
