# M44 Catalogs: core, CLI and app commands (0.6.0, #26)

Status: implemented (see Completion notes). Not committed (the maintainer commits). The GUI slice (M45, Install >
Browse) starts from the Contract below; changes after publication are listed at the end of that section.

Catalogs let the user search and browse places that list MCP servers and skills, then install an entry through the
paths that already exist: an MCP server goes to the M41 review (drafts, trust M39, scan M40), a skill goes to the
git skill install review. A catalog never installs anything on its own and never bypasses those gates.

## Contract

### Catalog sources (`store/catalogs.toml`, synced)

Built-ins are always present and can be turned off; the user adds MCP registries and git taps.

| Id | Kind | What | Notes |
|---|---|---|---|
| `mcp-registry` | `mcp_registry` | `https://registry.modelcontextprotocol.io` (`/v0.1`) | Attribution "Data from the Official MCP Registry". No "verified" badge: publishers show as `Publisher: <namespace> (namespace ownership checked by the registry)`. |
| `anthropic-skills` | `git_tap` | `https://github.com/anthropics/skills` | Skill folders `skills/*/SKILL.md` plus its `.claude-plugin/marketplace.json`; `template/` and `spec/` are left out. Official (a `github.com/anthropics/*` tap). |
| `skills-sh` | `link` | `https://skills.sh` | Link-out only (no API call). A pasted `https://skills.sh/<owner>/<repo>/<skill>` URL becomes the git skill install of `https://github.com/<owner>/<repo>` with `<skill>` picked. `https://skills.sh/site/...` (non-GitHub) entries are refused with a message. |

```toml
schema = 1

[catalogs.mcp-registry]          # a built-in: only `enabled` may be set
enabled = false

[catalogs.acme]                  # user-added MCP registry (any server of the MCP Registry API)
kind = "mcp_registry"
url = "https://registry.acme.example"   # https (http only for localhost/127.0.0.1/[::1]); no userinfo, query or fragment
title = "Acme registry"          # optional display name
enabled = true                   # optional, default true

[catalogs.team-skills]           # user-added git tap (skill folders and/or a Claude Code marketplace)
kind = "git_tap"
url = "https://github.com/acme/skills"   # any git URL `loadout skills add` takes (https, ssh, file://)
ref = "main"                     # optional branch, tag or 7-40 hex commit (a commit pins the tap)
```

Ids: 1 to 64 characters of `a-z 0-9 . _ -`, starting with a letter or digit; never `/`. Built-in ids are
reserved (a built-in's table may only hold `enabled`). Validation errors are `invalid_value`/`missing_field` with
the key path, like `sources.toml`. JSON Schema: `docs/schema/catalogs.schema.json`.

### The "Online catalogs" setting (machine-local)

`state/local-settings.toml`: `online_catalogs = true|false`. **Absent means off.** While it is off, nothing
contacts any catalog: search returns each catalog's cached results (any age) with status `off`, `show` answers only
from the cache, refresh and installs from a catalog fail with `catalogs_off`. The GUI asks once, when the user first
opens Browse, with one sentence naming what is contacted (`contacts`: the hosts of the enabled catalogs). The
CLI turns it on with `loadout catalog online on`. Nothing runs in the background, ever.

### Network rules

- HTTP only from core `catalog::http` (`ureq` 3, rustls with the platform verifier, gzip; no OpenSSL), behind the
  `Http` trait. Per request: 10 s connect timeout, 20 s overall, 8 MiB body cap, `User-Agent: Loadout/<version>`,
  proxies from `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` (and `NO_PROXY`). Redirects: at most 3, never from https to
  http.
- Git taps use the system git (shallow, `--filter=blob:none` for remote URLs, sparse: only `SKILL.md`,
  `.mcp.json`, `.claude-plugin/`, `LICENSE*` are checked out), the same clone helpers as `skills add` (commit
  refs fetched as M41 does). No GitHub REST API.
- Each catalog is searched on its own; one slow or failing catalog never blocks the others (the app calls
  `search_catalog` once per catalog; the CLI runs them in parallel threads and reports each).
- Cache: `LOADOUT_HOME/cache/catalogs/<id>/` (registry searches and entries by query/name hash, a tap's index),
  24 h TTL. A fresh cache answers without a request; an expired one is refetched, and when that fails the old
  results come back labeled `stale` with their age and the error. A changed URL or ref ignores the old cache.
- Queries go only to enabled catalogs; no telemetry.

### MCP Registry client

- Search: `GET <base>/v0.1/servers?search=<q>&version=latest&limit=50[&cursor=<c>]`; `/v0` when `/v0.1` answers
  404. A query needs at least 3 characters after trimming (`query_too_short` for registries; taps still answer).
  Results are filtered on the client too (name, title, description; case-insensitive), so a registry that ignores
  `search` still works, and one that rejects the parameter (400/422 with a valid query) is listed and filtered.
  De-duplicated by name (the entry marked latest, else the last one seen).
- Show/install: `GET <base>/v0.1/servers/<url-encoded name>/versions/<latest|version>`.
- Accepts `server.json` from schema `2025-07-09` on (camelCase and snake_case keys), wrapped (`{server, _meta}`) or
  bare items. `status: deleted` entries are hidden and refused for install; `deprecated` entries show with their
  `statusMessage`. `isLatest` alone is not trusted. Icons are never fetched or rendered (no `icon` field).
- Required secret names: `packages[].environmentVariables[]`, `remotes[].headers[]`, and remote `variables` with
  `isSecret` (or required with no default). Names only.
- Pinning: a package is unpinned when it has no version, an npm dist-tag (not a concrete version), or an OCI image
  without a digest/tag version; `pinned` is false when any package is unpinned.
- Trust key (M39) of an entry: `repository.url`, else the first remote URL, else the package page (npm, PyPI,
  NuGet, crates.io, the OCI image, an MCPB URL). An entry with none of these is refused (`invalid_value`).

### Git taps

- Skill entries: `skills/*/SKILL.md`, a root `SKILL.md` (a single-skill repository), and each relative marketplace
  plugin's skills (the entry's `skills` list, `plugin.json` `skills`, else `<plugin>/skills/*/SKILL.md`, else
  `<plugin>/SKILL.md`). Id = the folder name (`-2`, `-3` on a clash); one folder listed once.
- Plugin entries (`.claude-plugin/marketplace.json`): id `plugin/<name>`. Sources: `./path` (inside the tap; `..`,
  absolute paths and links out are refused), `github {repo, ref?, sha?}`, `url {url, ref?, sha?}`, `git-subdir
  {url, path, ref?, sha?}` are supported; `npm`, `archive` and `command` are listed but not installable
  (`problem`: "plugins from npm/archive/command sources are not supported"). A `sha` pins (`pinned: true`), a `ref`
  follows a branch or tag. MCP servers: names from `<plugin>/.mcp.json` (with or without the `mcpServers` wrapper)
  and inline `mcpServers` (relative plugins only; others are known after the review). Never imported: `hooks`,
  `commands`, `agents`, `bin`, `monitors`, `workflows`, `output-styles` (listed in `notImported`).
- `official` only for a tap under `github.com/anthropics/`. A marketplace whose name is reserved for Anthropic
  (or a look-alike: case, `.`/`_` for `-`, non-ASCII) in a tap elsewhere gets `warning` on the catalog and its
  entries; it is still listed.

### Install handoff and provenance

- `loadout server add --from catalog:<source>/<id> [--ref <version|ref>]` and the app's `review_catalog_mcp`:
  - registry entry: `server.json` of the version (latest unless `--ref`) goes through M41's `registry` converter as
    a `registry` source;
  - tap plugin: an M41 git review of the plugin's repository and folder (its `.mcp.json`, with
    `${CLAUDE_PLUGIN_ROOT}` read as the folder, so such servers run from a checkout).
  Everything after that is the M41 review, trust and scan, unchanged.
- `loadout skills add catalog:<source>/<id> [--ref <ref>]` and the app's `review_catalog_skill`: the git skill
  install review of the tap at the skill's folder (a plugin with several skills needs a `skill` pick: `--path`
  in the CLI). `https://skills.sh/<owner>/<repo>/<skill>` works in the same places.
- Provenance, synced:

```toml
# store/servers/<id>.toml
[meta]
origin = "catalog:mcp-registry"           # catalog:<source>

[meta.source]
kind = "registry"                         # new kind (a tap plugin stays kind = "git" with `catalog`)
url = "https://registry.modelcontextprotocol.io"
catalog = "mcp-registry/io.github.acme/weather"
version = "1.2.0"                         # the registry entry's version
ref = "1.2.0"                             # only when pinned with --ref
file = "server.json"
converter = "registry"
entry = "packages[0]"

# store/skill-meta/<id>.toml
[source]
kind = "git"
url = "https://github.com/anthropics/skills"
path = "skills/pdf"
catalog = "anthropic-skills/pdf"
```

- `loadout server update` (and `check_mcp_source_update`) re-reads a `registry` server's entry (`versions/latest`,
  or nothing to follow when pinned): `latest` is the version; needs online catalogs (`catalogs_off` in the check's
  error otherwise).

### New error codes

`catalogs_off` (online catalogs are off; nothing was contacted), `catalog_unreachable` (a catalog could not be
reached or answered with an error: timeout, HTTP status, rate limit, body too large, not JSON).

### Entry (core `CatalogEntry`, IPC `CatalogEntry`)

```ts
type CatalogKind = "mcp_registry" | "git_tap" | "link";
type CatalogEntryKind = "server" | "skill" | "plugin";
type CatalogResultStatus = "fresh" | "cached" | "stale" | "off" | "disabled" | "query_too_short" | "link" | "error";
type CatalogPublisher = { name: string; checked: string | null };   // checked: "namespace ownership checked by the registry"
type CatalogPackage = { registryType: string; identifier: string; version: string | null;
                        transport: string | null; pinned: boolean };
type CatalogRemote = { transport: string; url: string };            // url may hold {variables}
type CatalogPluginSource = { kind: "relative" | "github" | "url" | "git_subdir" | "npm" | "archive" | "command" | "unknown";
                             url: string | null;   // git URL to clone (masked)
                             path: string | null;  // folder in that repository
                             gitRef: string | null; sha: string | null };
type CatalogEntry = {
  catalog: string;            // source id
  id: string;                 // entry id: registry name, skill folder name, or "plugin/<name>"
  ref: string;                // "catalog:<catalog>/<id>", for server add --from / skills add
  kind: CatalogEntryKind;
  name: string;               // title or name
  description: string | null; // untrusted text: render as plain text
  version: string | null;
  updatedAt: string | null;   // RFC 3339 as the source gave it
  deprecated: boolean;
  statusMessage: string | null;
  publisher: CatalogPublisher | null;
  official: boolean;          // only where verifiable (anthropics taps)
  warning: string | null;     // reserved marketplace name outside github.com/anthropics
  repository: string | null;
  website: string | null;
  license: string | null;
  transports: string[];       // "stdio", "streamable-http", "sse"
  packages: CatalogPackage[];
  remotes: CatalogRemote[];
  requiredSecrets: string[];  // names only
  pinned: boolean;            // registry: every package pinned; tap: a sha
  gitRef: string | null;      // tap entries: the branch/tag followed
  commit: string | null;      // tap entries: the commit indexed (or the pin)
  path: string | null;        // tap entries: folder in the tap
  skills: string[];           // plugin: skill folder names (relative plugins)
  servers: string[];          // plugin: MCP server names (relative plugins)
  notImported: string[];      // plugin: hooks, commands, agents, bin, ...
  source: CatalogPluginSource | null;   // plugin
  installMcp: boolean;        // review_catalog_mcp applies
  installSkill: boolean;      // review_catalog_skill applies
  problem: string | null;     // why it cannot be installed (npm/archive/command source, deleted, ...)
};
```

### IPC (`src-tauri/src/commands/catalogs.rs`; camelCase in TypeScript)

`review_git_skill` also accepts a `https://skills.sh/<owner>/<repo>/<skill>` URL. `McpSourceInfo.kind` gains
`"registry"`, and `McpSourceInfo` gains `catalog: string | null` and `version: string | null`. No absolute path,
no secret value and no credential crosses IPC (URLs masked as in M41).

### CLI

```
loadout catalog ls                               # catalogs, enabled, the online setting
loadout catalog add <URL> [--kind registry|tap] [--id ID] [--ref REF] [--title TEXT]
loadout catalog rm <ID>
loadout catalog enable <ID> | disable <ID>
loadout catalog online [on|off]                  # no argument: show
loadout catalog search <QUERY> [--catalog ID] [--cursor C]
loadout catalog show <SOURCE>/<ID>
loadout catalog refresh [ID]
loadout server add --from catalog:<SOURCE>/<ID> [--ref VERSION|REF] [M41 flags]
loadout skills add catalog:<SOURCE>/<ID> [--ref REF] [--path DIR] [skills add flags]
loadout skills add https://skills.sh/<owner>/<repo>/<skill>
```

`--kind` defaults to `tap` for ssh/scp-like/`file://` URLs, `.git` URLs and github.com/gitlab.com/bitbucket.org,
else `registry`. `--json` documents (schema 1): `catalog ls` `{schema, online, decided, contacts, catalogs: [{id,
kind, title, url, ref, enabled, builtin, official, attribution}]}`; `search`/`refresh` `{schema, query, results:
[{catalog, status, fetched_at, age_secs, error, next_cursor, link, attribution, entries: [entry]}]}`; `show`
`{schema, status, age_secs, error, entry}`; entry keys are the IPC keys in snake_case. Exit 1 when every catalog
failed (`search`), or on errors; `catalogs_off` exits 1.

### Changes since publication

- `open_catalog_link(catalog: string, entry: string | null, link: "repository" | "website" | "catalog"): null`
  (requested by M45): opens the entry's repository or website (from the cached or shown entry), or with `entry`
  null and `link: "catalog"` the catalog's own page (skills.sh), in the browser. The URL is looked up in the
  backend, never passed by the caller; only https URLs open (review fix); `not_found` / `invalid_value` otherwise; no
  network request.
- Core only (no IPC effect): `McpHandoff` is a struct `{ entry, request: McpRequest }` (the entry is shown in
  notes), `skill_request` also returns the entry, and `cached_entry` reads an entry without a request (for
  `open_catalog_link`).
- IPC names as generated: the entry type is `CatalogEntry` (field `ref`), `add_catalog`'s kind is
  `NewCatalogKind` (`"mcp_registry" | "git_tap"`), `open_catalog_link`'s `link` is `CatalogLink`, the plugin
  source kind is `CatalogPluginSourceKind` and the status `CatalogResultStatus`; `ageSecs` is a `u32`.
- `review_catalog_skill`'s `skill` is the id of a skill entry of the same catalog (a plugin lists them in
  `skills`); null for a skill entry or a plugin with one skill.

Review fixes (local://review-M44.md, Main's decisions):

- **Trust keyed on what runs (P1).** `registry::trust_of` is replaced by `registry::trust_keys(server_json)`, one
  key per definition: the package on its registry (`registry.npmjs.org/<id>` with `@` written `%40`,
  `pypi.org/<name>`, `api.nuget.org/<id>`, `crates.io/<name>`, `<oci host>/<namespace>/<repo>`, an MCPB release's
  repository) or a remote's host (`SourceRef::whole_host`, key `host/*`). `RegistryRequest` has no `trust`;
  `McpHandoff::trust_source()` returns `Ok(None)` for a registry entry. `Draft.trust_source` carries a draft's key,
  `Pick.trust` its answer; IPC `McpDraft.trust: SourceTrustInfo | null` and `McpDraftPick.trust`.
- **Update token (P3-10).** A registry server's `UpdateCheck.latest` is a hash of its `server.json`; the version
  is `UpdateCheck.version` (new).
- **Update check gate (P3-1).** `registry_latest(read, sx, source)` needs the catalog in the store, turned on, with
  the same URL, and validates the URL with `registry_url_problem` (so does `ServerSource` validation); otherwise
  the check is `unreachable` with a message and no request.
- **Cache (P3-8).** `remove(store, sx, id)` takes `sx` and clears the catalog's cache; `cached_entry` reads only
  pages of the catalog's current URL; old cache files and stray clones are pruned on write.
- **Plugin `mcpServers` (P3-4).** `CatalogEntry.mcp_servers` (core only: the marketplace entry's `mcpServers`
  as JSON) is passed as `ResolveRequest::mcp_servers`; the M41 converters read it and `.claude-plugin/plugin.json`
  `mcpServers` (inline or a path in the folder) besides `.mcp.json`. An update reads it again from the cached
  entry. Taps check out the files a string `mcpServers` names.
- **Tap URLs (P2-4) and pins (P3-3).** `CatalogsFile::validate` refuses a user name or token in an http(s) tap URL
  (and a password in any), pointing to the git credential helper (`model::catalogs::tap_url_problem`); CLI output
  redacts catalog URLs. A commit ref is a full 40-character commit; a short one is refused with a message
  (`is_commit_ref` is 40 hex only).
