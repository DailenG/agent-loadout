## Overview

SkillSpector 2.13.7 becomes the optional external scanner: a local second opinion on skills, beside the built-in scan,
never instead of it. Off by default. Loadout never installs it: it runs the pinned uvx form
(`uvx --python 3.13 --from skillspector==2.13.7 skillspector ...`) when uv is on PATH, or a `skillspector` the user
installed on PATH. Snyk Agent Scan stays disabled (`scan::external::snyk::AVAILABLE = false`); its code stays, moved
into `scan::external::snyk`.

### Core API (`agent_loadout_core::scan::external`)

Shared by both scanners:

```rust
/// Which external scanner made a report. Serialized as its id.
pub enum Scanner { SkillSpector, SnykAgentScan }   // as_str(): "skillspector" | "snyk-agent-scan"
                                                   // name(): "SkillSpector" | "Snyk Agent Scan"
pub struct ExternalReport {
    pub scanner: Scanner,
    pub version: String,                // the version that ran (SkillSpector: metadata.skillspector_version)
    pub status: ExternalStatus,         // Scanned | NotScanned | NotUnderstood
    pub reason: Option<NotScanned>,     // Some iff status == NotScanned
    pub verdict: Verdict,               // from findings; never read it alone: check status and incomplete
    pub findings: Vec<Finding>,         // Finding::scanner = scanner.as_str()
    pub incomplete: bool,               // NEW: the scanner did not fully scan the content (never "clean" then)
    pub content_hash: Option<String>,   // skills::content_hash of what was scanned
    pub detail: Option<String>,         // English, one line, no paths or values
}
pub enum NotScanned {                   // as_str() snake_case
    NotAvailable,   // NEW: neither uv nor a usable skillspector on PATH
    NotPrepared,    // NEW: uv is on PATH but the pinned SkillSpector is not downloaded yet (run Prepare)
    Timeout, Canceled, Failed,
    // Snyk only (kept): NotInstalled, UnsupportedPlatform, NoToken, TokenUnavailable, TokenRejected,
    // LimitReached, TooLarge, Unreachable, WouldStartServer
}
/// Ok unless verdict == Dangerous and !allow_dangerous: scan_blocked (unchanged from 0.7.0)
/// ("SkillSpector found N dangerous findings: ..."). NotScanned / NotUnderstood never block.
pub fn gate(report: &ExternalReport, allow_dangerous: bool) -> Result<(), CoreError>;
pub enum Choice { Default, On, Off }    // --external / --no-external; the app always uses Default
```

### Command line and environment

Scan (exactly these arguments, after the runtime's prefix):

```text
uvx --offline --python 3.13 --from skillspector==2.13.7 skillspector scan --no-llm --format json --fail-on-incomplete -- <staged skill dir>
uv tool run --offline --python 3.13 --from skillspector==2.13.7 skillspector scan ...   (no uvx, only uv)
<skillspector on PATH> scan --no-llm --format json --fail-on-incomplete -- <staged skill dir>
```

`--offline` (uv's own flag) means a scan never downloads anything; only Prepare does. Never passed: `--output`,
`--transitive*`, `--inspect-dependencies`, `--use-shipped-baseline`, `--baseline`, `--mcp-registry*`,
`--yara-rules-dir`, `--recursive`, a URL, or any LLM flag. Stdin is closed. JSON is read from stdout.

Child environment (`env_clear`, then only): `PATH`, `PATHEXT`, `SYSTEMROOT`, `WINDIR`, `COMSPEC`, `HOME`,
`USERPROFILE`, `USERNAME`, `APPDATA`, `LOCALAPPDATA`, `XDG_CACHE_HOME`, `XDG_DATA_HOME`, `XDG_CONFIG_HOME`, `LANG`,
`LC_ALL`, the proxy variables (`HTTPS_PROXY`, `HTTP_PROXY`, `ALL_PROXY`, `NO_PROXY`, any case), `SSL_CERT_FILE`,
`SSL_CERT_DIR`, `REQUESTS_CA_BUNDLE`, `UV_CACHE_DIR`, `UV_PYTHON_INSTALL_DIR`, `UV_TOOL_DIR` when set; `TEMP`, `TMP`,
`TMPDIR` = the run's own `tmp` folder; `PYTHONIOENCODING=utf-8`, `PYTHONUTF8=1`, `LANGSMITH_TRACING=false`,
`LANGCHAIN_TRACING_V2=false`, `NO_COLOR=1`. Never a provider key or any other variable (`OPENAI_*`, `ANTHROPIC_*`,
`AWS_*`, `NVIDIA_*`, `LANGSMITH_*`, `LANGCHAIN_*` other than the two above, `GOOGLE_*`, `SKILLSPECTOR_*`, ...).
The same environment is used for the `--version` probes and Prepare.

### Mapping (exit code, then JSON)

- Exit 0 or 1: parse stdout. Anything else (2: error), or a kill by a signal: `not_scanned` / `failed` with the last
  stderr line as `detail` (the staged path replaced by `<skill>`); for the uvx form, uv refusing because the package
  is not cached (`--offline`) is `not_prepared`. Timeout: `timeout`; cancel: `canceled`.
- `not_understood` ("scanner output not understood (version X)", never clean) when stdout is not a JSON object,
  `execution_successful` is not `true`, `metadata.llm_requested` is not `false`, `risk_assessment.recommendation`
  is not `SAFE` / `CAUTION` / `DO_NOT_INSTALL`, `issues` is not an array, an issue has no `id` or a severity other
  than `LOW` / `MEDIUM` / `HIGH` / `CRITICAL`, or `analysis_completeness.is_complete` is not a boolean; stdout over
  16 MiB too.
- Each issue is a finding (`scanner = "skillspector"`): `CRITICAL` = `dangerous`, `HIGH` and `MEDIUM` = `warning`,
  `LOW` = `info`; rule = `id` (`E2`, `SC4`, ...), message = `explanation` (else `pattern`; one line, at most 400
  characters), `file` = `location.file` relative to the skill (absolute or escaping paths dropped), `line` =
  `location.start_line`, excerpt = `finding` masked like built-in excerpts. The OSV.dev-unreachable `SC4` `LOW`
  finding is shown as is (`info`).
- `recommendation == DO_NOT_INSTALL` with no `CRITICAL` issue adds a `dangerous` finding, rule `DO_NOT_INSTALL`,
  "SkillSpector recommends not installing this skill (risk score N of 100)", so the verdict is `dangerous`.
- `analysis_completeness.is_complete == false` sets `incomplete` and adds an `info` finding, rule `incomplete`,
  "not fully scanned (<status>, <coverage>% coverage)". The CLI summary then reads "not fully scanned" instead of
  "clean".
- `verdict` = the worst finding.

### Gating

Unchanged gates (M47): a `scanned` + `dangerous` report needs the same `--allow-dangerous` / "Install anyway" /
"Update anyway" as the built-in scan; `not_scanned` and `not_understood` never block. `external_scan_required`
applies again, while SkillSpector is on and Ready: an install or update of any review (local folders and archives
too, now: nothing is uploaded) must carry its report; `install_git_skill` (no review) refuses in that state.

  | "not_installed" | "unsupported_platform" | "no_token" | "token_unavailable" | "token_rejected"
  | "limit_reached" | "too_large" | "unreachable" | "would_start_server";

  scanner: ExternalScanner;     // "skillspector"
  version: string;              // the version that ran
  status: ExternalScanStatus;
  reason: ExternalNotScanned | null;

type ScannerRuntime = "uvx" | "path";

### Network disclosure (exact; `DISCLOSURE`, docs/security.md and the GUI say the same)

SkillSpector runs on this computer and never uploads the skill. Nothing leaves this machine except the names and
versions of the skill's dependencies, sent to OSV.dev (api.osv.dev) to look up known vulnerabilities, when the skill
has a dependency manifest (requirements.txt, package.json, pyproject.toml or Pipfile). Preparing the uvx form once
downloads SkillSpector 2.13.7 and its dependencies (a few hundred MB) from PyPI, and a Python 3.13 build when uv has
none; scans themselves never download anything. No account, no token, no upload of skill content. Loadout runs it
only on skills, never on MCP servers (SkillSpector does not read MCP client configs), and only when you turn it on
(or pass --external).

## Changes since publication

- CLI (CliScanner): `scanner status --json` `setup` is the setup text only when `not_available` (else `null`);
  `program` is the uv path when `needs_prepare`. `scanner prepare --json` prints the same status document plus
  `prepared` (`true` after a download, `false` when uv is missing and a ready `skillspector` is on PATH); the uv
  lookup this needs is `skillspector::find_uv` (now `pub`). `scanner ls --json`: `scanners: [{name, enabled,
  availability, local}, {name: "skillspector", enabled, availability, runtime, version, local: true}]`. The CLI
  does not call `required`: it runs SkillSpector per `--external` / `--no-external` / the switch, and
  `prepare_run` gives the not-scanned report when it is on but not Ready. Ctrl+C / SIGTERM / SIGHUP during a scan
  or `scanner prepare` cancels it (process tree killed, run folder removed, exit 130).
- Core (CoreTests): new pub `skillspector::find_uv(env) -> Option<PathBuf>` (`uvx`, else `uv`, on PATH; what
  `prepare` runs) and `skillspector::MAX_TIMEOUT` (59 min): `Settings::timeout()` caps `timeout_secs` there, below
  the one-hour stale-run sweep. Staging creates each file new, so names colliding on the file system (case or
  Unicode form) give `not_scanned` / `failed`, never a scan of a partial copy. On Windows the child now starts
  suspended, joins the kill-on-close job, then resumes (new dependency `process-wrap`, replacing `win32job` in the
  core; the CLI's `loadout exec` keeps `win32job`); a kill terminates the job and waits (bounded) until it is
  empty, so the run folder is removed before the call returns after a timeout or cancel too. `<skill>` also
  replaces the backslash-doubled form of the staged path. Testkit stub: `StubConfig::stderr` replaces `{skill}`
  and `{skill_escaped}`, `early_heartbeat` starts a child first thing, and heartbeats are written atomically.
- App (AppScanner): no IPC deviation. `turned_off` (switch off) cancels external scans but not a running Prepare
  (only `cancel_external_scan(null)` does). `install_reviewed` no longer exempts local reviews. App tests build
  the `skillspector-stub` once through the root workspace (`target/app-test-stubs`) and copy it beside the app's
  test binary, since the app workspace does not build testkit binaries. Review fixes: `install_local_skill` (no
  review) refuses like `install_git_skill` while on and Ready. `cancel_external_scan(null)` with no Prepare
  registered is kept and cancels the next `prepare_scanner` (`canceled`) before it starts; the GUI retries once
  when it gets that without the user having clicked Cancel. A switch-off generation counter: a review or update
  scan that began before a switch-off attaches/remembers nothing and returns `scanner_unavailable`;
  `external_scan_review` drops the review's earlier report first. The GUI holds Install / Update while the
  scanner is on and Ready but the review has no result (a failed run), and the switch can be turned off during
  Prepare. `scrub` also replaces the home folder with doubled backslashes.
