## Commands (typed IPC)

`list_projects` (layout, trust state, server/client/pending counts, placeholder path), `pick_project_folder` (OS dialog in Rust; the folder is validated per SPEC 17 and kept in the backend; the frontend gets a token, the placeholder path, the folder name and the manifest it holds, if any), `add_project(token)`, `init_project(token, shared, name)`, `review_project(id)` (each manifest file against the trusted mirror: content of a new file, unified diff of a changed one, masked, headers under `<P>`; plus the content hash), `trust_project(id, hash)` (refuses with `trust_required` when the manifests changed after the review), `remove_project(id)`, `apply_project_files(id)`, `reveal_project_folder(id)`, `effective_matrix(project_id)` (rows by server, one cell per client entry: winner layer and file, source, loaded, shadowed entries, also visible to, plan state, warnings, masked native snippet), `resolver_detail(entry)` and `resolve_entry(entry, action)`.

Folder validation (`validate_folder`): absolute, no `.`/`..` parts, not a drive or file-system root, not the home folder, not inside `LOADOUT_HOME`, an existing folder. Every other project command takes an id and resolves the folder from this machine's overlay.

Resolver actions per state (`ResolveAction`, mapped to the planner's `OnConflict`): drifted and conflict: Overwrite, Import theirs into store, Release ownership, Skip; drifted entry no longer desired: Remove anyway, Release ownership, Skip; missing: Re-create, Respect deletion, Skip; collision: Overwrite (adopt), Import theirs into store, Skip. Project entries offer no import, release or respect deletion (their definition is the manifest). Skip changes nothing. An action the state does not allow is refused (`invalid_value`).

## Spec ambiguities resolved

1. **Release ownership of a desired entry.** Dropping only the ledger row would make the next plan a collision. Release therefore also removes the client from the server's enable list (a store edit in the same commit); the entry stays as the user left it and is foreign afterwards. A server enabled for "all detected clients" cannot leave one out and reports why.
2. **Last written.** The ledger keeps only a keyed hash. Drifted: last written equals desired (the planner compared the hashes). Conflict/missing: the entry is rendered again from the commit after the ledger's `store_commit` (an instant apply writes what that commit holds) and from `store_commit` itself, and shown only when it hashes to the ledger's value; otherwise "not recoverable". Project entries come from current manifests, so theirs is usually not recoverable.
3. **Resolving applies the file.** A resolution plans that file alone with the decision, so other pending changes of the same file apply with it; the dialog says so.
4. **Add folder** binds a manifest found in the picked folder itself (not one above it) and opens the trust review; Init on a folder with a manifest offers Add instead.
5. **Matrix columns**: clients with an entry in the folder, then other detected clients, in table order. Snippets show the entry under the innermost container key only (Claude Code's per-project map is keyed by the folder path).
6. **Messages over IPC**: core messages that name the project folder or the home folder are rewritten to `<P>`/`~` in the new commands.
