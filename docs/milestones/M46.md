# M46 Loadout skill for agents (0.6.0, #8 narrowed): completion note

Not committed (the maintainer commits). Wave 0 slice of 0.6.0 ("Catalogs and a Loadout skill for agents"). Scope
narrowed per the plan: a read-only skill, its install per client, and the update rule. `loadout mcp serve`, the
approval queue and the generated "catalog of your store skills" (#9 C) stay in #8.

## Contract

- **Skill content**: `crates/agent-loadout-core/agent-skill/loadout/` (`SKILL.md`, `references/commands.md`,
  `references/errors.md`, `references/playbooks.md`), LF line endings (`.gitattributes`). Embedded by
  `agent_loadout_core::agent::FILES` (`include_str!`); the app also bundles the folder as a Tauri resource
  (`bundle.resources` maps it to `agent-skill/loadout/`). Adding a file means adding it to `FILES` too.
- **Other slices citing commands in the skill** (M44 catalogs): `catalog search|show` and the playbook "find an MCP
  server for X in the catalogs" are **not** in the skill yet, because the commands did not exist when it was
  written. Add them to `references/commands.md` (read table) and `references/playbooks.md` once `loadout catalog`
  exists; the CLI test `every_command_the_skill_cites_exists` (`crates/agent-loadout/src/main.rs`) then checks each
  cited command and long flag against clap, and `decision_flags_appear_only_in_never_guidance` fails on any line
  holding `--yes`, `--trust-source`, `--allow-dangerous`, `--on-conflict`, `--remove-old-backups`, `--all-identical`
  or `--theirs` without the word "never". Install commands (`loadout server add --from catalog:...`) go in the
  "Commands to hand to the user" table only.
- **Store representation**: a normal store skill, id `loadout`, `skill-meta/loadout.toml` with a new `[bundled]`
  table (`SkillMeta.bundled: Option<BundledCopy { version, hash }>`) and **no** `[source]` (review P2-2: 0.5.x
  rejects an unknown `kind`; there is no `SkillSourceKind::Bundled`). `agent::is_bundled(meta)` decides the origin:
  IPC `SkillOrigin::Bundled` (`"bundled"`), shown as "Bundled with Loadout"; CLI `skills ls --json`
  `source: {kind: "bundled", version}`.
- **Local settings**: `state/local-settings.toml` `agent_skill_notice` (the bundled version already reported as
  customized on this machine).

## Core (`agent_loadout_core::agent`)

- `bundled_files()` (CRLF normalized), `bundled_hash()`, `BUNDLED_VERSION` (`CARGO_PKG_VERSION`), `SKILL_ID`,
  `RESOURCE_DIR`.
- `status(store, sx) -> AgentStatus { bundled_version, copy: Option<StoreCopy { version, state }>, taken, clients }`,
  `CopyState::{Current, Outdated, Customized, Newer}`. A copy whose content hash differs from `[bundled] hash` (or
  cannot be read) is `Customized`; otherwise the recorded version against the bundled one decides. Clients: every
  client with a skill folder (table 7.6), omp first, with `detected` and `enabled` (the selection resolved through
  `DetectedClients`).
- `install(store, sx, clients)`: clients checked against table 7.6 (`unknown_client`, `scope_not_supported`); none
  given means every detected client with a skill folder, as an explicit list (`invalid_value` when none is
  detected). Missing: one commit `skill: add loadout (bundled with Loadout <v>) for <clients>` (content, meta with
  `enable.clients`), then `link::sync`. Present and bundled: `refresh` first, then `link::set_enabled`. Present and not
  bundled: `already_exists`.
- `remove(store, sx, clients)`: with clients `link::set_enabled(false)`; without, `skills::remove`. Not installed: no
  change. Not bundled: `invalid_value`.
- `refresh(store, sx)`: `Outdated` is replaced (one commit `skill: update loadout to the copy bundled with Loadout
  <v>`, meta re-read under the lock, then `link::sync`) -> `Refresh::Updated`; `Customized` with an older recorded
  version -> `Refresh::Customized`; else `None`.
- `startup_refresh(store, sx)`: only when `written_older` (a read of `skill-meta/loadout.toml`, no store open), and
  `Customized` only once per bundled version (`agent_skill_notice`).
- `materialize(fs, home)`: `cache/agent-skill/loadout`, rewritten (stale files removed) when it differs from the
  bundled files. `is_bundled_copy(fs, dir)` (newline-insensitive). `compare_versions` (semver order, build ignored,
  unreadable numbers as 0).

## CLI

- `loadout agent install|remove [--client C]...`, `agent status`, `agent skill-path` (`cmd/agent.rs`). JSON:
  install/remove `{commit, removed, refreshed: {kind: updated|customized, ...} | null, links}` (exit 4 when a link
  needs a decision); status `{skill, bundled_version, copy: {version, state} | null, taken, clients[{client,
  detected, enabled}]}`; skill-path `{path}`.
- Startup refresh (`cmd::agent::startup_refresh`) before every command except `exec`, `secret`, `secret-header`,
  `git-credential` and `env`; notes and failures go to stderr, never changing the command's result.
- `cmd::skills` exposes `skills_env`, `report_json`, `print_links`, `exit_for` to `cmd::agent`.

## Review fixes (local://review-M46.md, Main's decisions)

- **P2-1 read commands never write.** The update moved from a pre-command hook in `main.rs` to
  `Context::open_store_for_change` (`cmd::agent::refresh_before_change`), `agent install` and app start. `agent
  status` reports `outdated` with `action: "loadout agent install"` (`customized`: `loadout agent install --reset`).
  The internal-command exclusion list is gone. Test `read_commands_never_write_and_a_store_change_updates_an_older_copy`
  (CLI): with an outdated copy and the store lock held by the test, every read command parsed from commands.md
  (status, effective, listings, scans, catalog, history, show, diff, apply --dry-run, agent status, ...) leaves the
  whole temp root byte-identical, prints no note and takes under 5 s; then `skills add` updates. Observed failing
  before: yes (the old hook updated at `agent status` already, and the reviewer measured 10.08 s under a held lock).
- **P2-2 0.5.x compatibility.** See the Contract. Test `the_store_copy_metadata_validates_under_the_0_5_0_schema`
  validates the written metadata against `fixtures/schema-v0.5.0/skill-meta.schema.json` (`git show
  v0.5.0:docs/schema/skill-meta.schema.json`) with a small JSON Schema checker, which also refuses `kind = "bundled"`
  (so the test fails on the old metadata).
- **P2-3 cited fields.** `aliases` replaced by `variants[].secrets[]` (`field`, `alias`, `suggested_ref`) in
  commands.md and playbooks.md. Test `the_fields_the_skill_cites_are_in_real_output`: a fixture run (a store server, a
  foreign entry with a literal secret, the skill, a catalog stub) checks every field commands.md cites for `import
  --scan`, `status`, `server ls`, `skills ls`, `catalog search` and `agent status` against real `--json` output
  (listed example values exempt). Fails on the old `aliases` text.
- **P3-1 recheck under the lock**: `refresh_seen` / `replace` re-read meta and content in the transaction and write
  nothing unless the copy is still what was seen. Test `a_run_that_read_an_older_state_never_overwrites_a_newer_copy`
  (core) uses `refresh_seen` with a stale observation; the old code had no recheck (would have downgraded).
- **P3-2 cached verdict**: `startup_refresh` returns before hashing when `agent_skill_notice` is this version. Test
  `the_customized_verdict_is_kept_per_version` (a reverted edit is left for `agent install`, which then updates).
- **P3-3 non-edits and reset**: `normalized_hash` (junk names, BOM, CRLF) in `bundled_meta` and `copy_of`;
  `install(.., reset)` / `--reset` / `reset_agent_skill` / "Restore Loadout's version" keep the client selection.
