## API

- `adapters::ADAPTERS`, `adapters::adapter(id)`: the declarative table (`AdapterSpec { id, display_name, tier, detect, mcp }`, `Tier::{A, B, C, D}`).
- `McpSpec { oses, user, user_mirrors, project, project_local, format, container, project_local_container, mapper, caps }`.
- `AdapterSpec::mcp_targets(env, fs, scope, project) -> Vec<Target>`: the files for a scope (`model::applied::Scope`). Only checks existence; never reads or writes. `Target::container_keys(&Document)` resolves the container in the parsed file, including the `{project_key}` segment.
- `AdapterSpec::suppression_target(env, fs, project)`: the list used to hide a user server in a project (Claude Code `projects["<P>"].disabledMcpServers`), for `Document::set_list_member`.
- `mapper::EntryMapper { to_native, from_native, canonical }` with `RenderedServer { name, launch: Launch::{Stdio, Http, Sse}, passthrough }`, `WriteCx { os, existing }`, `ServerDef { fields, headers_helper, passthrough, unmapped }`, `Canonical`, `MapError::{UnsupportedTransport, UnsupportedField, InvalidName, UnexpectedShape}` (each with an `ErrorCode`; `From<MapError> for CoreError`).
- `mapper::McpServersJson`: the shared `mcpServers.<name>` JSON mapper, configured by the client's `Caps`, whether stdio entries get `type`, and a name rule.
- `detect::detect(spec, env, fs, &dyn RegistryProbe) -> Detection { client, supported, evidence }`; `Probe::{Path, Executable, UninstallEntry, MsixPackage}`; `RegistryProbe::has_uninstall_entry`; `NoRegistry`.

## Tests (16 new on Windows, 17 on Unix; 78 in the workspace on Windows)

`core/tests/adapters_claude.rs`, all through `TempHome`, `RootedFs` and fake `Env`s:

- `claude_code_goldens_per_transport`, `claude_desktop_goldens_per_os`: `to_native` goldens (the resulting file) for stdio, stdio without args or env, http with headers and `headersHelper`, sse; Claude Desktop stdio on Windows (`cmd /c npx`) and macOS (plain `npx`). Each golden also checks that `from_native` reads the entry back as the rendered server and that the canonical form survives a write and re-parse. Shim cases: `npx`, `pnpm`, a `.CMD` path are wrapped; an `.exe` and `uvx` are not.
- `claude_code_reads_a_user_file`, `claude_desktop_reads_a_windows_file`: `from_native` goldens over fixture files: `ws` is `unsupported_transport`, a bare `url` is http, an untyped `command` is stdio, `cwd` and unknown keys are unmapped, a non-list `args` is `unexpected_shape`; `cmd /c npx` reads back as `npx`, `cmd /c start` stays as written and writes back unchanged.
- `remote_servers_are_blocked_on_claude_desktop`: http and sse are `unsupported_transport` on Claude Desktop (and accepted by Claude Code).
- `fields_a_client_cannot_express_block_the_target`: `cwd` is `unsupported_field` on both; a passthrough key outside the allowlist is `unsupported_field`; `notes.v2` is `invalid_id` on Claude Code and fine on Claude Desktop.
- `unmodeled_native_keys_survive_an_update`: updating an entry with `cwd`, `x-note` and an empty `env` changes only the `args` line.
- `canonical_ignores_key_order_and_client_defaults`: `type: "stdio"`, empty `args`/`env`/`headers` and key order do not count; a missing remote `type` does; canonicalization is idempotent.
- `claude_code_targets_per_scope`: user, project and project-local files on every OS; `CLAUDE_CONFIG_DIR` moves the user and project-local file, a relative value is ignored; a project scope without a project is `invalid_path`.
- `claude_desktop_targets_per_os`: Windows Roaming file; an MSIX package dir alone adds nothing; with the MSIX copy present, **two targets** (Roaming, then the copy with `msix_dual_write`); project scopes are `scope_not_supported`; macOS path; Linux is `not_supported_on_os`, also with `~/.config/Claude` present.
- `windows_project_keys_follow_the_file`: an existing `projects` key is found with either slash style, any case and a trailing separator and reused as written; a new key copies the file's slash style (`/` when there is no drive-letter key); Linux keys compare exactly; an upsert through a reused backslash key lands in that project (golden).
- `claude_code_suppresses_user_servers_through_disabled_mcp_servers`: the suppression target is the project-local file and `projects/{project_key}/disabledMcpServers`; adding a member (golden) and removing it restores the fixture bytes, also for a project that had no entry yet.
- `a_target_round_trips_through_the_file_it_names`: resolve, read, upsert, write, re-read, remove gives the original bytes; foreign entries stay.
- `nothing_is_detected_in_an_empty_profile`, `claude_code_detection_per_os`, `claude_desktop_detection_per_os`, and (Unix only) `claude_code_detection_on_a_unix_path`: detection through a fake `Env`, a fake registry probe and a file system that panics on any write. Claude Code by `claude.exe` or `claude.cmd` on `PATH` (via `PATHEXT`), `~/.claude.json`, `~/.claude`, or `$CLAUDE_CONFIG_DIR`; Claude Desktop by uninstall entry, MSIX package dir or Roaming dir on Windows, by Application Support on macOS, never on Linux; the registry is never consulted off Windows. The Unix PATH test is gated because `:`-splitting cannot be exercised with Windows temp paths (`C:`); CI runs it on Linux and macOS.

Snapshots pass with `INSTA_UPDATE=no`. To regenerate after an intended change: `INSTA_UPDATE=always cargo test -p agent-loadout-core --test adapters_claude`, then review the diff.

## Error codes added

`not_supported_on_os`, `scope_not_supported`, `unsupported_transport`, `unsupported_field`, `msix_dual_write` (warning). Name-rule violations reuse `invalid_id`; bad native shapes reuse `unexpected_shape`.

## Spec ambiguities resolved

1. **Containers per scope.** §7.1 has one `container`, but Claude Code's project-local entries live at `projects/{project_key}/mcpServers` in the user file. `McpSpec` has `container` (user and project) and `project_local_container`. The project key is resolved against the parsed file (`Target::container_keys`), since it depends on the keys already there.
2. **"First existing wins" vs "write both".** The MSIX copy is not a candidate but a mirror: `McpSpec::user_mirrors`, each existing match planned as an extra target with `msix_dual_write`. The Roaming file is always a target (created when missing). The copy counts only when the config file exists inside the package; a package dir alone reads the real Roaming file.
3. **Claude Desktop OSes.** Decision 12 says Windows only; §7.3 adds macOS best effort; the brief requires `not_supported_on_os` on Linux. `McpSpec::oses` is Windows and macOS. Detection reports `supported = false` on Linux and skips probes.
4. **`ws` on Claude Code.** The store has no `ws` transport, so `Caps.transports` is stdio, http, sse and a native `ws` entry reads as `unsupported_transport` (left untouched as foreign).
5. **`cwd`.** Neither Claude client documents `cwd`; writing a server with one is `unsupported_field` (blocked), and a native `cwd` is unmapped and carried over.
6. **Bare `url` on Claude Code.** Read as http (§7.5 unified rule), but the canonical form does not fill in `type`, so a bare entry is never "identical" to the typed entry Loadout writes (the client may not load it).
7. **Name rule.** §5.1's Claude Code rule `[A-Za-z0-9_-]` is enforced in `to_native` (`invalid_id`, fix: `native_name`). Claude Desktop has no documented rule; any non-empty name is accepted.
8. **Windows shell shim.** Wrapped commands: `npx`, `npm`, `pnpm`, `pnpx`, `yarn`, `yarnpkg`, `corepack` (any directory, no extension) and any `.cmd`/`.bat`. `from_native` unwraps only `cmd /c <one of those>`, so every entry reads back as it would be written; other `cmd /c` entries stay as written. Claude Code gets no shim, per table 7.4 (`[verify]` CC-9).
9. **`headersHelper`.** Written for http and sse on Claude Code (the caps doc said both; the table says http/ws), `[verify]` CC-8. A rendered helper for a client without `CommandRef::HeadersHelper` is `unsupported_field`.
10. **What an update writes.** `args` is always written for stdio; `env` and `headers` when non-empty or when the existing entry already has the key (no churn on `"env": {}`). Keys the mapper does not model are carried over from the existing entry (§7.2, M3 note 1); allowlisted passthrough keys come only from the store.
11. **Suppression target.** `ProjectDisable::ListMember` lives in the client's project-local file; `suppression_target` returns that file with the list path as its container.
12. **Default Windows project key style.** `/` when the file has no drive-letter key yet (`[verify]` CC-2); otherwise the style of the first drive-letter key. The ledger example in §8.1 shows backslashes; it is illustrative only.
13. **Tool filters.** `RenderedServer` has no tool filter: neither Claude client has a native filter field (`Caps.tool_filter = None`), and choosing between blocking and warning for a filtered server belongs to the renderer (M6, §6.3, §11.4), which reads `Caps`.
14. **`skills` in `AdapterSpec`.** Left out; skill targets (§7.6) arrive with M18, the first milestone that uses them.

## Deviations

- No real `RegistryProbe` implementation. The core must not touch process-global state, nothing calls detection yet, and a Windows registry crate is not in §4; the CLI or app adds one when it first runs detection. Tests use a fake.
- No App Paths probe: neither Claude client registers one. `Probe` gains it when a client needs it.
- `cargo deny check` and CI were not run (no cargo-deny locally, no push). No dependencies were added.
