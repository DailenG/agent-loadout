# M40 Built-in offline scanner (0.5.0, #25)

Not committed (the maintainer commits). Loadout's own rules, shipped as
data, scan every skill install and update (and, through M41, every MCP
server drafted from a Git repository or folder) locally. A `dangerous`
verdict blocks unless the user explicitly installs anyway. Trusting a
source (M39) never skips the scan.

## Contract

Published first for M39 (shared install path), M41 (MCP drafts) and M42
(GUI). Everything here is implemented as written.

### Core API (`agent_loadout_core::scan`)

```rust
pub const SCANNER: &str = "builtin";              // Finding::scanner of the built-in scanner
pub const RULES_OVERRIDE_FILE: &str = "scan-rules.toml"; // <LOADOUT_HOME>/state/<this>
pub const CACHE_DIR: &str = "scan";               // <LOADOUT_HOME>/cache/<this>/<key>.json

pub enum Severity { Info, Warning, Dangerous }    // Ord; as_str(): "info" | "warning" | "dangerous"
pub enum Verdict { Clean, Warning, Dangerous }    // Ord; as_str(); Verdict::of(&[Finding]) = worst (info -> clean)

pub struct Finding {
    pub scanner: String,        // "builtin"
    pub rule: String,           // rule id, kebab-case
    pub severity: Severity,
    pub file: Option<String>,   // relative to the scanned root, '/'-separated; None for a command line
    pub line: Option<u32>,      // 1-based; None for a path rule or a command line
    pub message: String,        // the rule's one-sentence message (English)
    pub excerpt: Option<String>,// matched text, <= 120 chars, secret-shaped tokens masked as ****,
                                // invisible characters spelled out (\u{200B}, [hidden: ...])
}
impl Finding { pub fn label(&self) -> String }   // "rule (file:line)"

pub struct ScanReport {
    pub verdict: Verdict,
    pub findings: Vec<Finding>, // sorted by file, line, rule
    pub rules_version: u32,
    pub content_hash: Option<String>, // skills::content_hash of the files; None for a command line
    pub cached: bool,           // from the cache, not scanned now
}
impl ScanReport {
    pub fn merge(&mut self, other: ScanReport);  // e.g. repository files + command line of one MCP draft
    pub fn dangerous(&self) -> impl Iterator<Item = &Finding>;
}

/// Ok unless verdict == Dangerous && !allow_dangerous: then
/// CoreError(ErrorCode::ScanBlocked, "...found N dangerous findings: rule (file:line), ...").
pub fn gate(report: &ScanReport, allow_dangerous: bool) -> Result<(), CoreError>;

pub struct Scanner<'a> { .. }
impl<'a> Scanner<'a> {
    /// Built-in rules, or state/scan-rules.toml when it loads and its version is higher
    /// (one that does not load is a warning, the built-in rules run); cache in cache/scan.
    pub fn new(fs: &'a dyn Fs, home: &LoadoutHome) -> Self;
    pub fn rules(&self) -> &Rules;
    pub fn warnings(&self) -> &[CoreError];
    pub fn into_warnings(self) -> Vec<CoreError>;
    /// Files by relative '/'-separated path (SkillFiles = BTreeMap<String, Vec<u8>>);
    /// cached by content hash + rules fingerprint + build version.
    pub fn scan_files(&self, files: &SkillFiles) -> ScanReport;
    /// An MCP server's command line: command and args joined by spaces; not cached.
    pub fn scan_command(&self, command: &str, args: &[String]) -> ScanReport;
}
impl Scanner<'static> {
    pub fn builtin() -> Self;                              // no cache
    pub fn with_rules(rules: Cow<'static, Rules>) -> Self; // no cache
}

pub struct Rules { .. }  // Rules::builtin(), Rules::parse(&str) -> Result<Rules, CoreError>, version(), fingerprint(), rules()
pub enum Target { Markdown, Code, Command }
```

M41 usage: read the draft's repository files (or the files that define
the server) into a `SkillFiles`, `scanner.scan_files(&files)`, then
`report.merge(scanner.scan_command(&command, &args))` for the drafted
command, then `scan::gate(&report, allow_dangerous)` before saving the
draft; show `report.findings`.

### Skill install and update (`agent_loadout_core::skills::install`)

```rust
pub struct Decisions { pub allow_dangerous: bool /* M39 adds: pub trust: Option<sources::TrustGrant> */ }
pub struct InstallRequest { .., pub decisions: Decisions }          // Default: nothing let through
pub struct Installed { .., pub scan: ScanReport }

pub struct Prepared { .. }   // name(), files(), source(), scan(); Drop removes an unused temporary clone
pub fn prepare(sx, &InstallRequest) -> Result<Prepared, CoreError>;        // fetch + scan, no store change
/// On an error before the store commit `prepared` stays usable (retry with the user's decisions);
/// once the commit is made it is spent, and a later sync or clone failure is an `Installed.warnings` entry.
pub fn install_prepared(store, sx, &mut Prepared, &Naming, &Decisions) -> Result<Installed, CoreError>;
pub fn install(store, sx, &InstallRequest) -> Result<Installed, CoreError>; // prepare + install_prepared(request.decisions)

pub struct UpdateCheck { .., pub scan: Option<ScanReport> }   // Some when status == Available: the new content
pub struct Updated { .., pub scan: ScanReport }
pub fn update(store, sx, id, &Decisions) -> Result<Updated, CoreError>;
pub fn update_reviewed(store, sx, id, expected, &Decisions) -> Result<Updated, CoreError>;
```

Order of the gates before a store commit: source trust (M39), then
`scan::gate`. Imports of a client's unmanaged folder and agents CLI
vendoring scan and report (`Installed.scan`) but never block: that content
is already on this machine in a folder a client reads.

`ErrorCode::ScanBlocked` (`"scan_blocked"`): nothing was installed or
updated; the user can review the findings and install anyway.

### CLI

- `loadout skills add <SRC> [--allow-dangerous]`: findings printed after
  the result when there are any (human: `Scan: <verdict> (N findings)`
  then one line per finding `  <severity> <rule> <file>:<line>  <message>`,
  and `    > <excerpt>`; a clean scan prints nothing);
  `--json` adds `"scan": {verdict, rules_version, cached, findings:[{scanner,
  rule, severity, file, line, message, excerpt}]}` to the result. A
  `dangerous` verdict without `--allow-dangerous`: nothing installed, the
  findings printed, error `scan_blocked`, **exit 8**.
- `loadout skills update [ID] [--allow-dangerous]`: each available update is
  scanned before it is applied (the content checked is the content
  written); a `dangerous` one is reported `"status": "blocked"` with its
  scan and left as it is; the run exits 8 when one was blocked (1 still wins
  for an unreachable source or a failed update). `--check` reports `scan`
  for each available update.
- Exit code 8: blocked by the scan (SPEC 14).

### IPC (app)

New types (`src-tauri/src/commands/scan.rs`):

```ts
type ScanSeverity = "info" | "warning" | "dangerous";
type ScanVerdict = "clean" | "warning" | "dangerous";
type ScanFinding = {
  scanner: string;        // "builtin"
  rule: string;
  severity: ScanSeverity;
  file: string | null;    // relative to the skill root; null for a command line
  line: number | null;
  message: string;
  excerpt: string | null; // masked, invisible characters spelled out
};
type ScanResult = {
  verdict: ScanVerdict;
  findings: ScanFinding[];
  rulesVersion: number;
  cached: boolean;
};
```

Fields added:

| DTO | Field | Meaning |
|---|---|---|
| `SkillInstalled` | `scan: ScanResult` | The scan of what was installed (warnings and info findings to show after install). |
| `SkillUpdateCheck` | `scan: ScanResult \| null` | Scan of the new content when `status: "available"`; show it in the update review. |
| `SkillUpdated` | `scan: ScanResult` | Scan of what was written. |

Review before install (install from Git and from a picked folder):

```ts
type SkillReviewSource = {
  kind: SkillOrigin;      // "git" | "local"
  url: string | null;     // userinfo masked
  path: string | null;    // folder inside the repository
  gitRef: string | null;
  commit: string | null;  // the commit that would be installed
};
type SkillInstallReview = {
  token: string;          // names the fetched content in install_reviewed_skill / discard_skill_review
  name: string;
  files: SkillFileEntry[];// { path, bytes }
  source: SkillReviewSource;
  scan: ScanResult;
  // M39 adds: trust: SourceTrustInfo | null
};
```

Commands:

| Command | Returns | Notes |
|---|---|---|
| `review_git_skill(url, path, gitRef)` | `SkillInstallReview` | Fetches into a temporary clone and scans; no store change. Same URL rules as `install_git_skill`. |
| `review_local_skill(token)` | `SkillInstallReview` | `token` from `pick_skill_source`. |
| `install_reviewed_skill(token, id, renameIfTaken, allowDangerous)` | `SkillInstalled` | Installs exactly the reviewed content (a later change in the folder or repository is not picked up). `scan_blocked` when the verdict is `dangerous` and `allowDangerous` is false ("Install anyway" sends true). On success the review is consumed; on any error (`scan_blocked`, trust, `already_exists`, ...) it is kept under the same token, so the dialog can retry with the user's choice; `not_found` for an unknown or discarded token. M39 adds a trust parameter. |
| `discard_skill_review(token)` | `null` | Drops the review and its temporary clone (dialog closed). The app keeps at most 8 reviews; older ones are discarded. |
| `update_skill(id, latest, allowDangerous)` | `SkillUpdated` | **Changed:** new `allowDangerous` parameter (the update review's "Update anyway"). `scan_blocked` otherwise for a `dangerous` new content. |

`install_git_skill` and `install_local_skill` keep their signatures; they
apply the scan with no override (`scan_blocked` for dangerous content).

`ErrorCode` gains `"scan_blocked"`.

## Changes since publication (review fixes, local://review-M40.md)

Contract changes (IPC changed again: regenerate the bindings):

- `ScanReport` gains `custom_rules: bool` and `warnings: Vec<String>`
  (rules-loading problems, on every report, never cached);
  `Scanner::into_warnings()` is gone (`Scanner::warnings() -> &[String]`),
  so do `Prepared::warnings()` and `SkillInstallReview.warnings`.
  IPC `ScanResult` gains `customRules: boolean` and `warnings: string[]`;
  CLI `--json` `scan` gains `custom_rules` and `warnings`, and the human
  output prints `warning[scan_rules]: ...` and "Scan: custom rules in use".
- `state/scan-rules.toml` is merged, no longer a replacement: it may add
  rules or raise a built-in rule's severity, never remove or lower one
  (`Rules::with_custom`, `Rules::is_custom`). Its `version` no longer
  matters.
- Rules gain `prose` (severity in Markdown prose outside fenced code);
  rules version 2.
- New engine findings: `not-content-scanned` (info, file `None`, lists
  files read by path only) and `not-fully-scanned` (warning, past 4 MiB).
- `install::sweep_temp_clones(sx, older_than)`.

| # | Finding | Fix | Test (inputs are the review's failing probes) |

## What changed

### Core (`crates/agent-loadout-core`)

- `scan/` (new): `mod.rs` (model, `Scanner`, `gate`, override loading),
  `rules.rs` (rules file parsing and checks, compiled once), `engine.rs`
  (file kinds, matching, line numbers, excerpts), `cache.rs`
  (`cache/scan/<key>.json`, at most 512 entries, then emptied),
  `rules.toml` (the built-in rules, version 1), `tests.rs`.
- `regex` added as a dependency (already in the tree; linear-time, so a
  rule cannot hang on crafted content).
- `skills/install.rs`: `Decisions`, `prepare`/`Prepared`/`install_prepared`,
  `Installed.scan`, `UpdateCheck.scan`, `Updated.scan`, the scan gate in
  `install_prepared` and `commit_update`; `install_files` (import, vendor)
  scans without blocking. Git helpers made `pub(crate)` for M41.
- `error.rs`: `ErrorCode::ScanBlocked`.
