## API (core `skills`)

- `SkillsEnv { env, fs, home, registry, runner, link_kind }`: what every operation runs against (`registry` for `all-detected`, `runner` for git and the agents CLI, `link_kind` junction or symlink on Windows).
- `store`: `list`, `get`, `ids`, `read_meta`, `read_content`, `content_dir`, `meta_path`, `stage_content`/`stage_meta`/`stage_remove`, `prune_empty_dirs`, `free_id`, `settings`, `total_size_warning`. `StoreSkill { id, meta, frontmatter, bytes, has_content, problems }`.
- `frontmatter`: `parse` (YAML through the same reader as client files; every field in file order), `split`, `to_json`; `Frontmatter::{name, description, get, to_json}`.
- `install`: `Source::parse` (URLs, `git@host:path`, GitHub `/tree/<ref>/<path>` and `/blob/<ref>/<path>/SKILL.md`, a bare repository folder, else a local folder or archive); `install(store, sx, &InstallRequest { source, path, git_ref, naming: Naming { id, rename_if_taken } }) -> Installed`; `read_archive`; `check_update -> UpdateCheck { status: up_to_date|available|not_tracked|source_unreachable, current, latest, changes }`; `update -> Updated`; `forget_source`.
- `link`: `CLIENT_SKILLS` (table 7.6, Tier A and B), `skills_dir`, `sync(store, sx) -> SyncReport`, `set_enabled` (user scope), `set_project_enabled` (project scope), `SkillLedger` (`state/ledger.json` `skill_links`), `LinkStatus` (`created`, `adopted`, `unchanged`, `updated`, `removed`, `foreign`, `collision`, `changed`, `blocked`).
- `classify`: `scan(sx, scope, project) -> Vec<ClientDir>` (`managed`, `unmanaged`, `mismatch`), `import` (unmanaged folder into the store), `trash` (to `backups/trash/<time>-<client>-<name>`). These take a client, a scope, a project folder and an entry name, never a free path.
- `agents_cli`: `scan` (`~/.agents/skills`, `~/.agents/.skill-lock.json`, read-only), `enabled` (`agents_cli_compat`, default on), `vendor`, `locate_cli`, `run_cli(Update|Remove)`.
- `skills::remove(store, sx, id)`, `read_folder`, `content_hash`, `slug`, and the limits `MAX_SKILL_BYTES` (100 MB), `WARN_TOTAL_BYTES` (500 MB), `MAX_ARCHIVE_FILES` (500), `MAX_ARCHIVE_FILE_BYTES` (5 MB), `MAX_ARCHIVE_TOTAL_BYTES` (20 MB).

## CLI

```text
loadout skills ls
loadout skills add <URL|FOLDER|ARCHIVE> [--path P] [--ref R] [--id ID]   (--yes: a taken id becomes <id>-2)
loadout skills rm <ID> [--agents]
loadout skills enable <ID> [--client C]... [--copy|--link] [--symlink]
loadout skills enable <ID> --project <PATH>
loadout skills disable <ID> [--client C]... | --project <PATH>
loadout skills update [ID] [--check] [--agents]
loadout skills scan [--project PATH]
loadout skills import <CLIENT> <NAME> [--project PATH] [--id ID]
loadout skills trash <CLIENT> <NAME> [--project PATH]
loadout skills vendor <NAME> [--id ID]
```

Every command takes `--json`. Store changes are one commit each (`skill: add <id> from <source>[@<sha7>]`, `skill: enable <id> for <clients>`, `skill: disable ...`, `skill: update <id> to <sha7>`, `skill: remove <id>`, `skill: enable <id> in project <project-id>`), with `Loadout-Entity: skill/<id>`. Exit 4 when an entry needs a decision (foreign, collision, changed) or could not be made; `update` exits 1 when a source cannot be reached.

## Spec ambiguities resolved

1. **Ledger shape.** SPEC 8.1 shows `skill_link` entries inside `entries`. They are kept in a top-level `skill_links` array of the same `state/ledger.json` (`kind = "skill_link"`, `client`, `scope`, `project_id`, `skill_id`, `path`, `method` = `junction|symlink|copy`, `target`, `written_hash` for copies, `written_at`). The MCP planner deserializes every `entries` item as an MCP entry, so a skill item there would make earlier builds and the apply code fail to read the ledger; the `Ledger` type keeps unknown top-level keys on rewrite, so both live in one file without touching the apply code.
2. **Hashes.** A copy's `written_hash` is `sha256:` over its files (paths and bytes, marker excluded); skill files hold no secrets, so no HMAC. Links are owned by target: an owned link still pointing at its store folder is unchanged.
3. **When links follow.** Every store change commits first, then `link::sync` makes client folders match under the store lock (instant apply): user scope from each skill's `enable.clients`/`enable.method`, project scope from `[skills] enable`/`share` of every known, trusted project, clients from the project's `defaults.clients` (private file over shared, default `all-detected`). Untrusted, missing or invalid projects are left alone; their owned links stay.
4. **Enable without clients** sets `all-detected`; disable without clients turns the skill off everywhere; disabling one client of `all-detected` stores the detected list minus that client.
5. **Project enable** edits `[skills] enable` of `project.local.toml` (or `project.toml` when the project has no private file), with comments kept, commits the mirror (`Loadout-Scope: project/<id>`) and trusts the content it wrote, like `project share`. The project must be known and trusted first; the edit is undone when the commit fails.
6. **Changed owned entries** (an edited copy, a relinked link) are reported `changed`, left in place and dropped from the ledger, so they show as unmanaged afterwards and are never overwritten.
7. **Ids.** From the frontmatter `name`, else the folder, archive or repository folder name, as a slug. A taken id fails with `already_exists` naming the free `<id>-N`; `--yes` takes it.
8. **Git sources.** A path (from `--path` or a GitHub `/tree/` URL) gives `git clone --no-checkout` plus `sparse-checkout set --no-cone /<path>/` and `checkout`; without one the repository is cloned whole and must hold exactly one skill folder (searched four levels deep). Remote URLs get `--depth 1`. A bare repository folder given as a path is a git source. Clones land in `cache/skill-sources/.tmp-<ulid>` and move to `<id>` after the commit. Git runs with the process environment minus git's repository-local variables, and `GIT_TERMINAL_PROMPT=0`. Program lookup (git, the `skills` CLI) reads the real file system, where programs live, also under a confined test view.
9. **Updates** fetch the followed ref into the cache clone and check out `FETCH_HEAD`; any failure to fetch, or a source that no longer holds the skill, is `source_unreachable`; the store and client folders are not touched. `check_update` lists added, modified and removed files (a store copy edited by hand shows as changes too); the merge view is M19 GUI work.
10. **Local sources** record `kind = "local"` without a path (a personal path would be versioned in the store), so they have no update; adding again with `--yes` installs a new copy.
11. **Size.** Folder installs stop at 100 MB (`invalid_value`); the 500 MB total is a warning after the install. Archives use SPEC 17's limits, counted on uncompressed bytes as read (a lying header cannot pass).
12. **Links inside a skill folder** are followed when they resolve inside it (each folder once) and refused when they escape. Archive symbolic link entries are always refused.
13. **Trash** is a rename into `backups/trash/`; a link moves as a link. Managed entries are disabled instead.

## Deviations

- `skill_links` instead of `entries` in the ledger (ambiguity 1).
- `scan --import`/`--trash` are separate subcommands (`import`, `trash`, `vendor`); agents CLI update and remove are `update --agents NAME` and `rm --agents NAME`.
- `ls` does not run update checks (network); `update --check` does.
- No full-text diff in the CLI's update output: changed file names only.
