# M24 MCP page project scope and Discard pending: completion note

Not committed (the maintainer commits). Closes two GUI gaps deferred since M15 and M16: "Project scope of the MCP page" (M15 deviations, M16 deviations: `list_scopes` returns System only) and "Discard pending (review mode)" (M15 deviations: the core had no "drop store edits since the last apply" operation). ## What was built

### MCP page at project scope

- The MCP page toolbar has a scope select: **System (user-wide)** or **Project: NAME** for every known project. It is the M19 Skills page pattern: the Skills page's `AppSelect` scope control moved into a shared component, `src/app/components/ScopeSelect.tsx`, which both pages use (Skills keeps its labels; nothing else about Skills changed). The sidebar switcher of SPEC 13.1 is unchanged (System only); see "Not done".
- Project scope lists the servers of the project's manifests, both files merged (core `layering::project_entries`), one card per name: kind (Project server, Overrides `<from>`, Hidden here), the file(s) defining it (Project, Local), the resolved launch text, problems from the project plan, and per-client pills computed from a project-only plan (`ScopeFilter::Project`, `ProjectSelection::Only(<P>)`). A client without a project or project-local config on this OS is `not_supported` with `scope_not_supported` ("Claude Desktop has no project config"). For a suppression, a selected pill means "hidden for this client".
- **From the store (System)**: store servers the folder inherits (enabled system-wide on this machine and not named by the manifests), each with **Override here** (opens the dialog as an override with `from` set) and **Hide here** (writes `enabled = false` as a suppression).
- Add/Edit dialog (`ProjectServerDialog.tsx`): Name, **Write to: Project (shared, project.toml) / Local (private, project.local.toml)**, Kind (project-only server, override a store server, hide a store server here), Store server (`from`), transport (an override may keep the store's), command and arguments or URL, env or headers (the store editor's chip, key/value and reference-picker components, now exported), and clients: "Use the project's default clients" (no `clients` key) or the client grid; an empty list is "no client". Keys the form does not show (`unset`, `[os.*]`, `[client.*]`, `cwd`, unknown keys) are kept, and comments survive (`TomlDocument`).
- Pill toggles, Enable All and Disable All write the entry's `clients` in its edit layer (the private file when it defines the name, else the shared one). Delete is the store list's two-click delete.
- **Trust.** An untrusted or changed project is read only: the page shows why ("not trusted on this machine" / "changed since it was trusted, for example after a git pull") with **Review & trust**, which opens the M16 trust review (Trust accepts exactly the reviewed hash); Add, Edit, Delete, pills, Override here and Hide here are disabled. The backend refuses every edit of such a project with `trust_required` (as `loadout project` blocks apply with exit 7 until `loadout project trust`).

### Discard pending

- In review mode the drawer shows **Store changes not applied**: each discardable store entity changed since this machine's last apply (`Server <id>` added/changed/removed, `Client preferences`), each with **Discard**, and the footer has **Discard pending** (all). Both ask first (inline confirmation, as "Undo this apply" does), then restore and refetch every store view. Instant mode shows neither (SPEC 13.4: review mode).
- Discarding never applies, so no client file is touched; the plan afterwards is what the restored store and the client files make it.

## Decisions (spec ambiguities resolved; recorded in SPEC 13.2 and 13.4)

1. **"Last applied state"** is this machine's newest apply commit (the newest commit carrying its `Loadout-Apply` trailer and this machine's `Loadout-Machine`), else the initial commit when this machine never applied. It is the base "Undo this apply" already restores to (`apply::rollback::apply_commits`); its tree is exactly what that run applied (an instant edit and its apply are one commit; a review apply commits on top of the edits it applied).
2. **What is discardable**: `servers/<id>.toml` and `clients.toml`, the store edits that wait for an apply in review mode. Not discarded: `settings.toml` (turning review mode on is itself a commit after the last apply; discarding it would silently switch back to instant), `secrets.toml` (catalog edits pair with keyring values outside the store), skills (they sync at once and client folders link into the store), project mirrors (the folder is the source of truth; restoring a mirror would write manifests back and break trust) and the machine overlay (it records known projects, which `project add` commits without an apply, and resolver decisions already applied).
3. **Discard is a restore** of the chosen entities to that base (`store::restore`, SPEC 9.5): `auto/pre-restore/<ts>` tag, one commit, `apply: false`. Core `restore::restore_as` lets it commit as op `store.discard` with summary `discard: server/github` or `discard: N pending changes`; `restore` itself is unchanged (`restore: <short>`). An entity without a pending change is `not_found`; nothing to discard makes no commit; an empty entity list is never passed (it would restore the whole store).
4. **Per item = per entity.** Drawer rows are files, and one file holds entries of many servers, so items are the store entities, listed in their own section.
5. **Project edits are trusted by Loadout** (M9 decision 2: manifests Loadout writes itself are re-trusted in the same operation, as `project share` does). Core `layering::project_servers::edit_server` loads the folder's manifests, requires them to be trusted now and to have the content hash the page showed (`trust_required` otherwise), edits `[servers.<name>]` with `toml_edit` (via `TomlDocument<ProjectManifest>`), validates the file as its layer, writes it, then mirrors, trusts and applies in one commit (`project <id>: add|update|remove|clients <name>`, op `project.server.<verb>`, `Loadout-Scope: project/<id>`, through `projects::commit_project`, which restores `trust.json` on failure). A failed commit puts the manifest bytes back (and removes a local file or `.gitignore` it created). An unchanged file makes no commit.
6. **Write to.** Shared needs an existing `project.toml` (sharing a private project stays `loadout project share`, which also fixes `info/exclude` and `.gitignore`); a private project offers Local only. Local next to a shared file creates `project.local.toml` (`schema = 1`, no id) and makes sure `.loadout/.gitignore` lists it. Editing keeps the table in the file it is in; the dialog does not move entries between files.
7. **Override `from`** must name a store server that loads (`not_found` otherwise, before anything is written); the core would otherwise block the entry with `unknown_template` at apply.
8. **Pill selection at project scope** comes from new core `Detected::project_clients` (selection resolved like the planner, minus machine exclusions and opt-outs); the planner's `plan_entry` now uses the same `Detected::project_selection`, so the pills and the plan cannot disagree.
9. **Paths.** The page shows the project folder under its placeholder root (`project.path`), and every core message of these commands is scrubbed (`<P>`, `~`); tests assert no JSON reply holds the temp root.

## Review follow-up (M24 review)

1. **Concurrent manifest changes (P1).** `edit_server` no longer trusts a reload. The write is a compare-and-swap (`apply::exec::swap_file`) against the bytes that were checked; the other manifest must still hold its checked bytes before the swap, and both files must hash to the edited content after it. What is mirrored, trusted and applied is that checked content plus the new text, built in memory. Any mismatch is `trust_required` with nothing committed, and what this call wrote is put back only where the file still holds it (a change by another program is never overwritten). Test `an_edit_never_trusts_or_overwrites_a_concurrent_change` (a hook in the test's `Fs` rewrites the other manifest, then the same manifest, at the moment the temp file is written): no commit, the other program's bytes kept, the edit put back, the project `changed`, nothing applied.
2. **Toggles kept the machine's opt-outs out of project.toml (P1).** `ProjectServerRow.clients` is now the entry's selection as the manifests write it (its `clients`, else the project's defaults), with `usesDefaults`; pill toggles, Enable All and Disable All start from that explicit list, and from the pill selection only for `all-detected` (the store page's rule). Tests: app crate `rows_carry_the_manifest_clients_not_this_machines_selection` (`clients.toml` opts Cursor out; the row still lists it), frontend "keeps clients this machine opts out of when a toggle writes the manifest's list" (`[claude-code, cursor]` plus Codex is written as `[claude-code, cursor, codex]`).
3. **Partial local tables (P2).** Saving defaults a definition to stdio only on create; an edit keeps no transport. `get_project_server` sets `overShared` for a `project.local.toml` table over a `project.toml` entry of the same name; the dialog labels it "Change the shared entry here", explains that empty fields keep the shared values, and offers "Same as the shared entry" for the transport. Tests: `saving_an_unchanged_partial_local_table_changes_nothing` (a clients-only local table over an http entry: no commit, file byte-identical, still http), frontend "labels a private table over the shared entry as a change of that entry" (saves `transport: null`).
4. **One project edit at a time (P2).** Every project action (pills, Enable/Disable All, Edit, Delete, Override here, Hide here, the toolbar's Add) is disabled while an edit runs and until the project list has been fetched again (the edit awaits the refetch); the backend compare-and-swap of item 1 closes the rest. Test: frontend "runs one project edit at a time and waits for the fresh hash".
5. **Discard base under concurrency (P3).** `discard::PendingStore` carries the HEAD it was read at; `discard` takes that `PendingStore` and the restore refuses another HEAD with `file_changed_during_apply` before anything changes (`restore_as(.., expected_head)`; the transaction re-checks under the lock as before). Test `discard_refuses_a_store_that_moved_on`: a commit lands between reading and discarding; nothing is discarded.
6. **Discard pending sends what it shows (P3).** The drawer sends the listed entities, never `null`, so a change that arrived after the list was shown is not discarded unseen (it is `not_found` if stale); `pending_store_changes` is refetched with the other drift queries. Test: drawer "discards exactly the listed changes after confirming".
7. **`.gitignore` put back.** A pre-existing `.loadout/.gitignore` the failed edit appended to gets its original bytes back (a created one is removed). Test `a_failed_edit_puts_back_an_appended_gitignore`.

Each regression test was checked red. Rust: with the fixes of items 1, 3 and 5 temporarily undone (no compare-and-swap, a reload trusted, stdio on every save, no HEAD check), `an_edit_never_trusts_or_overwrites_a_concurrent_change`, `a_failed_edit_puts_back_an_appended_gitignore`, `saving_an_unchanged_partial_local_table_changes_nothing` and `discard_refuses_a_store_that_moved_on` failed. Frontend: with items 2, 4 and 6 undone (pill selection written, no lock, `null` sent), "keeps clients this machine opts out of...", "runs one project edit at a time..." and "discards exactly the listed changes..." failed. Restored, all pass. (`rows_carry_the_manifest_clients_not_this_machines_selection` pins the new row field; the toggle regression itself is the frontend test.)
