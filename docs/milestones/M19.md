## Spec ambiguities resolved

1. **Scope.** The sidebar switcher still offers System only (as after M16); the Skills page has its own scope select (User, or a known project). Project scope lists every store skill, project-enabled first, with "Turn on/off in project" (a skill the shared `project.toml` enables in a project with a private file cannot be turned off here, SPEC 12.3 / M18 follow-up 3).
2. **Enable All** selects `all-detected`; Disable All turns the skill off everywhere; one pill is one client. "Distribute as" switches link/copy (SPEC 12.1 `enable.method`).
3. **Tags** are a list (SPEC 12.1); the ported tag editor adds, removes and clears.
4. **Update preview** compares the store copy with the cache clone as the last check left it (no second fetch).
5. **Taken ids** install as `<id>-N` only after a confirmation dialog, for installs, imports and vendoring.

## Deviations

- Git install takes the skill's folder as a field (or from a `/tree/` URL); SkillDock's "discover the repository's skills, pick several" list is not ported (the core installs one folder per request).
- No drag and drop on the local install: the drop zone opens the folder picker (commands take no paths).
- File browser and diff are read only; SkillDock's in-place editing, hunk revert and Markdown preview are not ported. File view is plain text.
- The Tools page Manage dialog still has no Skills tab (SPEC 13.7 Tools; the folders are on the Skills page tabs).
- The CSS block was adjusted after the screenshots (scope select fixed at 190 px, compact "Distribute as" select); the screenshots show the wider selects of the first build.
