# M42 GUI for 0.5.0 (#24, #25, #5)

Status: implemented. Not committed (the maintainer commits). No IPC change of its own: the GUI uses the commands
and DTOs of M39 (source trust), M40 (scanner) and M41 (MCP from Git or folder), including their "Changes since
publication" (`movedTrust` on reviews and update checks and as an argument after `trust`; `customRules` and
`warnings` on `ScanResult`; `source_blocked` update status; no `warnings` on `SkillInstallReview` and
`McpSourceReview`).

## What was built

### Shared pieces (`src/app/components`)

- `TrustDialog.tsx`: the trust dialog and `useTrustPrompt()`. `resolveTrust({ trust, movedTrust }, onBlocked)` asks
  about the requested source, then (separately) about the repository the host redirected it to, and resolves to
  the `trust` / `movedTrust` arguments, or null when the user canceled or a source is blocked (a block on either
  refuses before any question). Each prompt is a fresh dialog (keyed) that opens on **Cancel**, so a held or
  doubled Enter or a double-click cannot grant the second prompt. Choices in plain words: **Trust this time only**
  (default; nothing recorded), **Always trust** *repo*, **Always trust everything from** *owner*, **Always trust
  everything on** *host* (only the scopes the backend offers), **Cancel**. It says why it asks (first time, not
  trusted, lapsed after a force-push or a move); the redirect prompt says "{from} now redirects to {to}" with both
  addresses; it warns about unencrypted (`http://`, `git://`) sources, shows the **Official** marker with the note
  that it does not skip the question, and lists skills already installed from the source.
  `TrustSummary` is the one-line state in every review; `OfficialBadge`, `changeText` are shared with Settings.
- `SettingsDialog` (settings route) gained `initialFocus` (review dialogs open on the dialog, not on the
  acknowledgement checkbox) and `dismissible` (Escape, backdrop and the close button do nothing while a write is
  in flight; the reviews also disable Cancel then).
- `ScanFindings.tsx`: verdict, count, "Custom rules in use", rules-load warnings, then each finding with severity
  badge, rule, `file:line` (or "command line"), message and the masked excerpt. `DangerousGate` explains the block
  and holds the checkbox "I read the findings and want to go ahead anyway"; the review's primary action becomes
  **Install anyway** / **Update anyway** / **Save anyway** (a danger button), disabled until it is ticked.
  `isDangerous(...)` decides. The engine's `not-content-scanned` note (no file) shows without a location; other
  file-less findings are on the command line. `ScanFindings.test.tsx` covers these.

### Install skill (`src/app/routes/install`)

- Git and Local now go through the review: `review_git_skill` / `review_local_skill`, `SkillReviewDialog` (source
  facts, trust summary for the URL and a moved-to target, findings, files), then `install_reviewed_skill(token, id,
  renameIfTaken, allowDangerous, trust, movedTrust)`. Install asks the trust question first; a taken id still asks
  before `<id>-2`; errors keep the review (the backend keeps it too); closing without installing calls
  `discard_skill_review`. A blocked source disables Install and says why. The old direct `installGit` /
  `installLocal` actions are gone (`useSkillActions().installReviewed`).

### Skill update (`src/app/routes/skills`)

- `SkillUpdateDialog` shows the trust summary (and the moved-to target), the findings and the gate; changed files
  that look executable carry a **Script** badge. Update asks the trust question when needed and passes
  `allowDangerous` and both answers to `update_skill`. A `source_blocked` check shows **Source blocked** on the card.
  **Update all** sends no trust answer and no override, so those updates fail with a toast and stay for review.

### MCP from Git or folder

- Install > MCP has two tabs: **Form or paste** (the existing cards) and **From Git or folder**
  (`McpSourcePanel.tsx`): Git URL with optional folder and branch, tag or commit, or a folder picked in the OS
  dialog (token only). **Find servers** calls `review_mcp_git_source` / `review_mcp_local_source`. The review shows
  the source facts, trust summaries, the files' scan, then each draft: pick checkbox (a single draft starts
  picked), kind, provenance ("From server.json, packages[0] (registry converter)"), the exact launch line, the plain
  note **"This server runs code from this repository every time a client starts it."** for `runsRepoCode` drafts,
  needed secrets, dropped values, checkout and setup steps, duplicates, and the draft's findings. Skipped entries
  are listed with their reason. **Review and edit** opens the draft in the existing server form (`ServerForm`, now
  exported, `mode="draft"`: id editable, no paste box) with its provenance on top. **Enable for** (the existing
  `ClientGrid`) sets the clients of every draft. **Save** asks trust, then calls `save_mcp_source_drafts(token,
  picks, trust, movedTrust, allowDangerous)` with the drafts as edited (`normalizeDraft`); `scan_blocked` (an
  edited command scans dangerous) turns on the gate; success uses the usual change notice. **Discard** and leaving
  the page discard the review.
- `src/app/routes/mcp/McpSourceUpdate.tsx`, shown in a server's details on the MCP page when `origin` is
  `source:git` or `source:local`: **Check for update** (`check_mcp_source_update`), status line, **Review update**
  (a table of each changed field, now and after; every new launch line, OS overrides included; the setup steps and
  "run them again" when the update replaces the checkout; the runs-repo-code note; changed checkout files with
  Script badges; trust summaries; findings and gate) and **Restore copy** for a missing or out-of-date checkout:
  `review_mcp_checkout` (null: already up to date), then `RestoreCheckoutDialog` (trust summaries, scan, "Restore
  anyway" gate) and `restore_mcp_checkout(token, trust, movedTrust, allowDangerous)`; closing discards the review
  (`discard_mcp_source_review`). Update calls `update_mcp_source_server(id, latest, trust, movedTrust,
  allowDangerous)`. Drafts show every launch line (`LaunchLines`), "Not pinned" when `pinned` is false, and the
  review's `skippedFolders`; the Form goes back as received, so placeholder paths are saved as the real paths.

### Settings > Sources (`src/app/routes/settings/sources/SourcesSection.tsx`)

- What each decision means (trusted, blocked, revoke/unblock; nothing is uninstalled), then every record from
  `list_sources`: key, Trusted/Blocked badge, Official, "Asks again" when lapsed with the reason and date, scope in
  words, when, how (app, prompt, `--trust-source`, `loadout source`) and on which machine. **Revoke** / **Unblock**
  (`revoke_source`) and **Block** (`block_source`) confirm first. **Block a source...** takes a URL, reads its
  scopes with `check_source_trust` (no network), then `block_source_url`. `list_sources` is a store query key, so
  trust recorded by an install or update refreshes the page.

### Mock and demo data

- `src/test/mockTransport.ts`: defaults for the MCP source commands, `MOCK_MCP_DRAFT`, `MOCK_MCP_REVIEW`.
- `src/test/demoData.ts`: a dangerous skill review from an untrusted repository, a lapsed (force-pushed) update
  with a script, three MCP drafts (registry stdio with a secret, hosted http with a dropped value, repository as
  server with a dangerous finding) plus a skipped entry, a `weather` server from `source:git` with an update, and
  the Sources list (M39).

### Styles and strings

- `src/styles/tokens.css` (M42 block): status text tokens only (`--danger-text`, `--warning-text`, `--success-text`,
  `--heading`, `--muted`), so the existing contrast tests cover them; danger actions reuse `.danger-button` on a
  secondary button. `src/i18n/en.ts` (M42 block). Radios carry only their label as accessible name (hints are
  descriptions); every dialog uses `Modal` through `SettingsDialog` or the server editor shell.

  an update.
- The default mocks refuse like the backend: `installReviewedSkill`, `saveMcpSourceDrafts`, `updateSkill`,
  `updateMcpSourceServer` and `restoreMcpCheckout` answer `source_blocked`, `source_trust_required` (per source,
  the redirect target included) or `scan_blocked` for the review or check this transport last answered, so a flow
  that skips the trust question or drops `allowDangerous` fails any test, not only those asserting arguments.
