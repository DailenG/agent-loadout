## Design

- `Store::open` (read-only, `None` when absent) and `Store::open_or_init` (creates the store on the first mutation; §14 has no `init` command). Init takes the lock, re-checks, creates the repo with `external_template(false)` and `initial_head("main")`, writes `loadout.toml` (`schema`, `store_id` ULID, `created_at`) and commits it with `Loadout-Op: store.init`. An interrupted init (repo without commits) is finished on the next mutation and keeps an intact `loadout.toml`.
- `Store::transaction(Operation, |tx| ...)` takes the lock, loads or creates the machine identity, runs the closure (staged writes and removes; reads see staged changes), validates every staged store file with M1's `validate_store_file` (first error aborts, warnings pass), builds the new tree as HEAD's tree plus exactly the staged changes from the bytes in memory (index from buffers: no worktree scan, no git filters), writes the working tree through `Fs`, commits once and writes the index so `git status` stays clean. An unchanged tree makes no commit (`Committed::commit` is `None`).
- The working tree is the source of truth for reads, so hand edits are seen; other uncommitted hand edits stay uncommitted.
- git types stay inside `store` (`CommitId` is a hex newtype). There is one backend, so no backend trait yet (§4.2 mentions one for a future `gix` switch).

## Spec ambiguities resolved

1. **"No git config is read or written."** libgit2 reads the global and system config files whenever it opens a repository (ownership check, `core.*`). Redirecting that needs `git2::opts::set_search_path`, which is `unsafe` and process-global, and the workspace forbids unsafe code. What is guaranteed instead: Loadout never asks git for an identity or any config value and never writes config; author and committer are passed explicitly; libgit2 signs a commit's reflog entries with its committer, so `.git/logs` holds only the Loadout identity; init ignores `init.templateDir` and `init.defaultBranch`. libgit2 still writes the repo-local `.git/config` (`core.*`) that every new repository has. The CLI test plants a bogus identity, branch and template and proves none reaches the store.
2. **Author name.** `loadout <machine-label>` is read as the literal `loadout ` followed by the label (git forbids `<` and `>` in names). Labels are cleaned of `<`, `>` and control characters and fall back to `machine`. Commit times come from `Env::now` in UTC (`+0000`).
3. **Machine identity.** `state/machine.toml` (`schema`, `machine_id`, `label`) is created on the first mutation, not by read-only commands. The label is `Env::hostname`, which the CLI fills from `COMPUTERNAME` on Windows and `HOSTNAME` or `/etc/hostname` elsewhere. The `machines/<id>.toml` overlay is not created in M2.
4. **Trailers.** Scope values are `system` and `project/<id>` (the spec shows only `system`); a bulk change repeats `Loadout-Entity`; the init commit has no entity; unknown `Loadout-*` trailers are kept; line breaks in values become spaces; the CLI's `Loadout-Client` is `loadout-cli/<version>`.
5. **History filters.** The entity filter matches the `Loadout-Entity` trailer or a change to the entity's files (`server/<id>` is `servers/<id>.toml`; skills, projects, machines and `secrets`/`clients`/`settings` are mapped too). The scope filter is in core; the CLI exposes `--entity` and `--limit` as listed in §14.
6. **`server add` flags** (§14 lists only `add <ID>`): `--url`, `--transport` (default stdio, or http with `--url`), repeatable `--env KEY=VALUE` and `--header NAME=VALUE`, `--cwd`, `--display-name`, `--description`, repeatable `--tag`, repeatable `--client` or `--all-detected`, and the stdio command after `--`. `meta.origin` is `manual`. The definition is validated before the store is opened; warnings go to stderr.
7. **`server rm`** accepts several ids and removes them in one commit; a missing id fails the whole removal. `server show` prints the file as stored; `--json` prints the typed value.
8. **`.gitattributes`** with `* -text` is part of the initial commit, so git clients never convert line endings in the store (Git for Windows defaults to `core.autocrlf=true`) and M1's byte-exact CRLF/BOM handling holds.
9. **Sync-folder warning.** Mutating commands repeat `warning[sync_root_detected]` on stderr (§4.5); the GUI's "use anyway" record is not part of M2.
10. **Store identity file.** `StoreIdentity` lives in the store module; it is not exported to `docs/schema` because it is written once by init and never edited by users.

## Deviations

- **Lock primitive.** §4.1 names `fd-lock`; the lock uses `std::fs::File::try_lock`/`unlock` (stable since Rust 1.89, the same `LockFileEx`/`flock` primitives), so no dependency is needed. Polling every 50 ms up to 10 s.
- **Leak scanner** (§9.2 "before commit"): M7. The transaction has the slot documented; nothing scans yet.
- `Loadout-Apply` is parsed and formatted but nothing writes it before M6.
- `cargo deny check` was not run locally (cargo-deny is not installed); every new crate is MIT OR Apache-2.0. CI was not run (no push).
