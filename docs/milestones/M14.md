## API

- Commands (`src-tauri/src/commands.rs`): `app_info() -> AppInfo { version, platform }`, `list_scopes() -> Scope[]` (`{ kind: "system" }` only), `data_home() -> Result<DataHome { path, source }, IpcError>` (the resolved `LOADOUT_HOME`; reads nothing inside it). `IpcError { code: ErrorCode, message }`: the frontend localizes from `code`; `message` is English diagnostic detail and never shown.
- Bindings: `src/ipc/bindings.ts` is generated by tauri-specta (error mode `Result`: fallible commands resolve to `{ status: "ok", data } | { status: "error", error }`) and exports `PRODUCT_NAME`, `APP_ID`, `REPO` and `HOME_ENV_VAR` from `brand.rs`, so the frontend has no brand literals. `npm run bindings` rewrites it (an ignored test); `bindings_are_current` fails when it is stale.
- Transport (`src/ipc/transport.ts`): `Transport { commands: typeof commands, window: WindowControls }`, `tauriTransport`, `unwrap` (throws `IpcFailure { code }`), `TransportContext`/`useTransport`. `src/test/mockTransport.ts`: `createMockTransport(options)` is typed against the generated `commands`, records calls and window actions, and is the only mock. `npm run dev:mock` (`vite --mode mock`) runs the frontend in a browser on the mock; the mock module is imported dynamically behind a build-time mode check, and the production bundle was checked not to contain it.
- `App` props: `transport`, optional `queryClient`, `features` (`{ plugins, publish }`, both off by default).

## Spec ambiguities resolved

1. **Workspace layout.** `src-tauri` declares its own `[workspace]` instead of joining the root one. As a member, `cargo clippy --workspace` and `cargo test --workspace` would build Tauri, WebView2 bindings and, on Linux, need WebKitGTK development packages on every CI leg, for a crate with two tests. SPEC 4.1 places the crate in the repository without saying it must be a workspace member; the root gates stay as they were, and the app crate has its own lock file and gates (`--manifest-path src-tauri/Cargo.toml`).
2. **Errors across IPC.** Commands return `Result<T, IpcError>` with core's `ErrorCode` as a typed string union, and `src/i18n/en.ts` has a `Record<ErrorCode, string>`, so a new core code fails `tsc` until it has an English sentence.
3. **Window chrome from the backend.** `app_info().platform` (not user-agent sniffing) picks custom Windows controls, the macOS overlay layout or Linux native decorations, which makes all three testable with the mock. The Tauri side matches: `decorations: false` only in `tauri.windows.conf.json`, `titleBarStyle: Overlay` only in `tauri.macos.conf.json`.
4. **CSP without inline code.** `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self' ipc: http://ipc.localhost; object-src 'none'; base-uri 'self'; form-action 'none'; frame-ancestors 'none'`. SkillDock's inline theme script and inline page style in `index.html` are gone: the theme is applied by the app, and a `prefers-color-scheme` rule in `tokens.css` keeps a system dark theme from flashing light first. The window title comes from `tauri.conf.json`; `document.title` is set from `PRODUCT_NAME`.
5. **Theme preference** is a local UI choice in the webview's storage (`loadout.settings.theme`; Settings > App Preferences > Appearance). SPEC 4.5 puts portable UI preferences in `store/settings.toml`; moving it there belongs with the Settings page milestone.
6. **Header toolbars** render through `HeaderToolbar`, a portal into a host element held in React context (SPEC 4.3), not `document.getElementById` slots.
7. **Empty pages.** Every page shows an empty state; Skills and MCP put SkillDock's "Install" toolbar button in the header (it opens Install). Settings has the Appearance row; About shows version, platform, app id, repository and the data directory. Route modules (`src/app/routes/**`) start with the milestones that fill them (M15).
8. **Scope switcher.** System only (SPEC 13.1 for M14): closed it reads "System", open "System (user-wide)"; "Add folder..." comes with projects (M16).
9. **Feature flags.** Plugins and Publish are routes behind `features.plugins`/`features.publish`, off by default. Nothing sets them yet (`local-settings.toml` feature flags are later work).
10. **TanStack Query** holds the three queries (no retries; IPC is local). Every failed query shows an error toast localized from its code. Invalidation on core change events waits for the core's event module (SPEC 4.1 `events.rs`, not built yet), so no event is declared in the bindings.
11. **Ported components.** `AppSelect`, `AppTooltip`, `BatchActions`, `SearchFieldIcon` are verbatim; `ToolbarGoInstallButton`, `ListGridViewToggle` and `notifications` only swapped the i18n hook for the English catalog. `tokens.css` is verbatim except a marked Loadout section at the end (dark pre-paint color, scope switcher, and window control colors for the dark theme: SkillDock draws them near-black on the dark background, where they are invisible).
12. **Brand and icon.** Brand strings come from `brand.rs` (bindings constants; a test compares `tauri.conf.json`). The app icon is new artwork (`src-tauri/icons/icon.svg`, also inline in the sidebar), not SkillDock's.
