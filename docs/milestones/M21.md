## Spec ambiguities resolved

1. **Gemini's project suppression lives in the shared file.** SPEC 7.4 names project `mcp.excluded`; Gemini has no private project file, so the list member goes to `<P>/.gemini/settings.json`. `suppression_target` chooses the project file for a list mechanism when a client has no project-local file, and a suppression from `project.local.toml` follows SPEC 6.5 like any private entry in a shared file (blocked when tracked, else excluded from git).
2. **Gemini's typed spellings.** SPEC 7.3 says "no `type` field", but newer Gemini releases accept `type` next to `url`. Loadout never writes `type`, reads an explicit one first (SPEC 7.5 "explicit type wins") and treats `{"type":"http","url":u}` as the same server as `{"httpUrl":u}`, so such entries adopt without a rewrite. A `url` beside `httpUrl` is ignored in the canonical form, since Gemini runs `httpUrl`.
3. **Gemini entries with several keys** run in Gemini's order: `httpUrl`, then `url`, then `command`. This differs from the shared JSON mapper, where `command` wins.
4. **OpenCode SSE.** A `remote` entry is SSE only when its URL path ends in `/sse` (SPEC 7.5). An SSE server is written as `remote` too: OpenCode tries Streamable HTTP and then SSE, so the entry works whatever the path.
5. **OpenCode project suppression** writes the whole entry with `enabled: false`, not `{ "enabled": false }` alone: OpenCode validates each file on its own, and an entry without `type` fails that. With DeepMerge the effect is the same.
6. **OpenCode files.** `opencode.json` is the default; `opencode.jsonc` is used when it exists and `opencode.json` does not. SPEC's "reads `<P>/.opencode/` too" became two later project candidates, `<P>/.opencode/opencode.json[c]`, used only when they exist and the root files do not. Both are written as JSONC, and a new file starts with OpenCode's `$schema` line.
7. **Grok's compatibility sources** are Claude Code's user file (top-level `mcpServers` only, not `projects[...]`), then Cursor's project file, then `<P>/.mcp.json`, below Grok's own project and user files, in SPEC 6.4's order of mention.
8. **Grok's mapper** is the shared `McpServersJson` (no `type`, bare `url` is http): Grok's TOML shape is the JSON clients' `mcpServers` shape, and the TOML editor spells the tables.
9. **Antigravity's `[verify]` capabilities** take the conservative value: no variable expansion (`env` delivery unavailable), no native disable (an existing `disabled` or `disabledTools` is kept as an unmapped key), `ProjectSemantics::Unknown`, no project suppression, no trust gate.
10. **Name rules.** All four accept any non-empty name; SPEC 5.1's "Gemini recommends no underscores" is a recommendation, not a rule, so `native_name` stays optional.

## Review follow-up

The Tier C/D review found two literal-text problems in M21's clients (findings 1 and 2; findings 3 to 5 belong to M22), fixed without a commit yet:

1. **OpenCode and MiMo Code guarded the wrong token.** The literal guard (`Renderer::check_literal` in `secrets/render.rs`) now follows the client's `EnvRefSyntax` through `expanded_token`: for `BraceEnv` it refuses literal text holding `{env:` or `{file:` (OpenCode substitutes both anywhere in the file) and no longer refuses `${`, which OpenCode leaves alone; `DollarBrace` and `DollarBraceEnv` keep refusing `${`. Import matches: `native_to_template` reads an OpenCode `${` as the literal `$${` and returns `None` for `{file:...}` and for a `$` right before `{env:...}` (`brace_env_to_template` in `apply/render.rs`).
2. **Gemini and Qwen Code expand a bare `$NAME`.** `EnvRefSyntax::DollarBrace` gains `bare: bool` (`true` for Gemini and Qwen Code, `false` for Claude Code, omp, Copilot and Grok). With `bare`, literal text holding `$` before `[A-Za-z0-9_]` is refused (`delivery_unavailable`) until GEM-6 records what Gemini does with it, and import reads a bare `$NAME` as `${env:NAME}` (`bare_dollar_to_template`). GEM-6 and OC-7 in `scripts/verify-clients.md` now name these cases.
3. **Inline values** go through the same check: a resolved secret holding a token the client would expand is refused for that target, and the message names the reference, never the value. Before, inline values were not checked for any client but Pi (which escapes them).
