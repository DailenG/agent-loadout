# M41 MCP servers from a Git repo or local folder (0.5.0, #5)

Status: implemented (see Completion notes). Not committed (the maintainer commits).

A Git URL (https, ssh, `file://`, a local bare repository; branch, tag or commit optional) or a local folder is
resolved into one or more **drafts**: proposed store servers the user reviews, edits, picks clients for and saves.
Nothing runs or installs while resolving: the system git clones (shallow at the ref, no hooks, no submodules) into a
temporary folder below `LOADOUT_HOME/cache/mcp-sources/`, files are read and scanned, and the clone is removed unless
a saved draft runs from it. Every save goes through source trust (M39) and then the built-in scan (M40).

## Contract

Stable for M42 (GUI). Changes after publication are listed at the end of the section.

### What is recognized (in priority order)

Files are read in the folder the request names (the repository root, or `path` inside it).

| Kind | Files | Converter (`meta.source.converter`) | Draft |
|---|---|---|---|
| `registry` | `server.json` (MCP Registry schema; camelCase and the older snake_case keys) | `registry` | each `packages[]` entry: npm `npx -y <id>@<version>`, PyPI `uvx <id>==<version>`, NuGet `dnx <id>@<version> --yes`, OCI `docker run -i --rm [-e NAME]... <image>`; runtime/package arguments kept in order. Each `remotes[]` entry: an `http` (`streamable-http`) or `sse` server. Variables marked secret become `${secret:<ALIAS>}`; others take their default or `${env:<NAME>}`. `mcpb` packages are skipped (`unsupported_field`). |
| `bundle` | `manifest.json` with `manifest_version` or `dxt_version` and `server.mcp_config` (MCPB/DXT) | `bundle` | `command`/`args`/`env`; `${__dirname}` is the folder (a git source then runs from a checkout, below); `${user_config.KEY}`: sensitive entries become `${secret:<ALIAS>}`, others the default or `${env:<KEY>}`; `${HOME}` is `${home}`; `platform_overrides` become `[os.*]`. |
| `client_config` | `.mcp.json`, `mcp.json`, `.vscode/mcp.json`, `.cursor/mcp.json`, `.codex/config.toml`, `.omp/mcp.json`, `claude_desktop_config.json` | `client:<client id>` | one draft per entry, through the import converter (`apply::import::read_native`, the same one Paste config uses). Literals the classifier flags become `${secret:<ALIAS>}`; **the value is dropped**, never stored or sent (the input says `valueDropped`). A project variable (`${workspaceFolder}`, `${CLAUDE_PROJECT_DIR}`, ...) and a relative path that exists in the folder make the draft run from the folder. VS Code `${input:...}` entries are skipped (`needs_manual_secret`). |
| `package` | only when nothing above gave a draft: `package.json` with `bin`, `pyproject.toml` with `[project.scripts]`, `Dockerfile` | `npm`, `python`, `docker` | **the repository is the server**; the command is pinned: GitHub `npx -y github:<owner>/<repo>#<sha>`, other git `npx -y git+<url>#<sha>`; `uvx --from git+<url>@<sha>[#subdirectory=<path>] <script>`; `docker run -i --rm --pull=never loadout-local/<id>:<sha12>` with the build step listed in `setup` (`docker build -t ... <url>#<sha>[:<path>]`). A local folder: `node <folder>/<bin>`, `uv run --directory <folder> <script>`, `docker run -i --rm --pull=never loadout-local/<id>:<content-hash12>` (build step in `setup`). `loadout-local/` is no registry's namespace and `--pull=never` refuses to pull a missing image. |

- Identical definitions (same transport, command, args, URL, cwd, env, headers) collapse into the first; the others'
  files are listed in `alsoIn`.
- Draft ids come from the server or entry name (lower case, `-` for other characters), made unique against each
  other and the store (`-2`, `-3`).
- `runsRepoCode` is true for `package` drafts and for any draft that runs from the folder or checkout: the review
  must say plainly that this runs code from that repository every time the client starts the server, and show the
  exact command (`launch`).

### Checkouts and provenance

- Source folders are read without dependency and build folders (`node_modules`, `.venv`, `venv`, `__pycache__`,
  `.git`, `target`, `dist`, `build`): not read, scanned, counted against the size cap or diffed; the review lists
  them (`skippedFolders`, info).
- A git draft that runs from the repository's files (`checkout: true`: a bundle's `${__dirname}`, a committed config
  with a relative path, a `path` inside the repository for npm) is saved with its clone moved to the machine-local
  `LOADOUT_HOME/servers/<id>/` at the resolved commit (never synced), under the store lock; the command names it as
  `${loadout_home}/servers/<id>/...`. The clone's `origin` is the URL without credentials. The checkout is marked
  (`.git/loadout-checkout`: commit and URL): an entry of a server whose checkout is missing or at another commit or
  URL is blocked (`checkout_out_of_date`) until `loadout server checkout <id>` or the app's
  `review_mcp_checkout` + `restore_mcp_checkout` brings it there (the same trust and scan gates as a save). `loadout
  server rm` and the app's delete move the folder aside under the lock and delete it once the removal commits.
- A local folder source runs from the folder itself, written with `${home}` when it is under the home folder. It is
  bound to the machine that added it (`meta.source.machine`): elsewhere its entries are blocked
  (`folder_on_other_machine`) and the update check says so. Commit messages name a folder outside home by its name
  only.
- Only provenance goes into the synced server file:

```toml
[meta]
origin = "source:git"                    # new origins: source:git | source:local

[meta.source]
kind = "git"                             # git | local
url = "https://github.com/acme/weather"  # git; userinfo removed
folder = "${home}/code/weather"          # local
machine = "<machine id>"                 # local: the machine the folder belongs to
path = "servers/weather"                 # folder inside the repository (optional)
ref = "main"                             # branch or tag followed (optional)
commit = "<40 hex>"                      # git: the resolved commit
file = "server.json"                     # the file the definition came from, relative to the folder
converter = "registry"                   # registry | bundle | client:<id> | npm | python | docker
entry = "packages[0]"                    # which definition in the file (optional)
checkout = true                          # runs from LOADOUT_HOME/servers/<id> (optional, default false)
```

### Gates before a save (one store commit)

1. Source trust (M39 `sources::admit`): git sources through `SourceRef::from_git_url`, local folders through
   `SourceRef::from_local_path` (offers the `repo` scope only), and a redirect target with its own answer.
   Errors `source_trust_required`, `source_blocked`.
2. The built-in scan (M40): the folder's files (`Scanner::scan_files`) merged with every launch line of each picked
   server as saved (the base definition and each `[os.*]` override merged over it, after the user's edits), then
   `scan::gate` (`scan_blocked` unless allow-dangerous). Secret extraction, the review's launch lines and the
   update diff cover each override the same way. A registry package without a concrete version is marked
   `pinned: false` (and the scan's `mcp-unpinned-package` fires); a non-default `registryBaseUrl` goes into the
   command (`--registry=`, `--index-url=`, `--source`, or the image's host). Passthrough values (`[client.*]`) the
   classifier flags are left out (`client.<id>.<key>` inputs with `valueDropped`). Skip messages never quote a file:
   `could not parse <file> (line N)`.

Commit: `server: add <id> from <url|folder>@<sha7>` (several: `server: add N servers (a, b) from ...`), op
`server.add`, entities `server/<id>`, with the instant apply like `loadout server add`.

### Update check

Re-resolves the source (a fresh temporary clone; the folder again for local sources) and finds the draft with the
same `file`, `converter` and `entry`. `changes` lists the definition fields that differ (`transport`, `command`,
`args`, `url`, `cwd`, `env.NAME`, `headers.NAME`, each also `os.<name>.`-prefixed; values as stored, references
only). An update keeps the server's id and the aliases of its secret references (in `args` and the URL too);
`env` and `headers` keys present before and after keep the stored value; the display name, enablement, tools,
`[client.*]` stay. A checkout is replaced atomically: the new one is placed under the store lock with the old one
aside, committed, then the old one deleted (restored when anything fails); `files` lists the changed files of a
checkout (`SkillFileChange`, with `script`); `setupAgain` says the setup steps must run again. Force-push and moved
repositories are detected as for skills (trust lapses, `change` in the trust info). Whatever stops the read
(unreachable, gone, too large, a folder of another machine) is the server's status (`source_unreachable` with the
error), never a failure of the whole check. For a local folder `latest` is its content hash: the update refuses
another one (`entry_changed`).

### CLI

- `loadout server add [ID] --from <GIT-URL|PATH> [--path <DIR>] [--ref <REF>] [--pick <KEY|ID>]... [--all]
  [--client <CLIENT>]... [--all-detected] [--trust-source[=once|repo|owner|host]] [--allow-dangerous] [--dry-run]`.
  `ID` renames the one draft saved; `--url`, `--env`, `-- COMMAND` and the other manual fields are not used with
  `--from` (`--display-name`, `--description`, `--tag` apply to the saved drafts). Without `--pick`, a single draft is saved; several drafts
  list and need `--pick` (or `--all`). `--dry-run` (the issue's `--scan`) lists drafts, inputs and findings and
  saves nothing. The trust prompt and `--trust-source` work as for `skills add` (`--yes` never answers it).
  Human output shows each OS's launch line, "Not pinned", the folders not read, and setup steps with the paths
  written out. `--json`: `{schema, source: {kind, url, folder, path, ref, commit}, skipped_folders, drafts: [{key,
  kind, id, file, converter, entry, launch, launch_lines: [{os, line}], runs_repo_code, checkout, pinned, setup,
  also_in, inputs: [...], scan}], skipped: [{file, entry, error}], saved: [ids] | null, commit, apply}`. Exit 8 when
  the scan blocked, 1 for trust errors.
- `loadout server update [ID] [--check] [--trust-source[=...]] [--allow-dangerous]`: servers with `meta.source`; a
  server whose check fails is reported (`status: "failed"`) and the others are still checked.
- `loadout server checkout <ID> [--trust-source[=...]] [--allow-dangerous]`: re-creates a missing checkout or brings
  a stale one to the commit the server file names, behind the trust prompt (the source and a redirect target) and
  the scan of its files and saved launch lines (exit 8).
- Server commands sweep temporary clones older than an hour when they start; the app does it at startup.

### IPC (`src-tauri/src/commands/mcp_source.rs`; camelCase in TypeScript)

```ts
type McpDraftKind = "registry" | "bundle" | "client_config" | "package";
type McpSourceInfo = {
  kind: "git" | "local";
  url: string | null;        // userinfo masked
  folder: string | null;     // local folder under its placeholder root ("~/code/weather")
  path: string | null;       // folder inside the repository
  gitRef: string | null;
  commit: string | null;
};
type McpDraftInput = {
  field: string;             // "env.API_KEY", "headers.Authorization", "args[3]"
  description: string | null;
  secret: boolean;           // the draft holds ${secret:alias}; set the secret after saving
  required: boolean;
  alias: string | null;
  valueDropped: boolean;     // the file held a literal value here; it was not kept
};
type McpLaunchLine = { os: string | null; line: string };   // null: the base definition
type McpDraft = {
  key: string;               // names the draft in save_mcp_source_drafts
  kind: McpDraftKind;
  file: string;              // relative to the folder
  converter: string;
  entry: string | null;
  draft: ServerDraft;        // the Form (clients empty); paths under placeholders (`~`, `<folder>`): sent back
                             // unchanged, they save the real paths
  launch: string;            // the base command line or URL, as saved (placeholders as in `draft`)
  launchLines: McpLaunchLine[]; // the base, then each OS override as it runs there: show them all
  inputs: McpDraftInput[];   // fields may be `os.<name>.`-prefixed, or `client.<id>.<key>` (left out, no alias)
  runsRepoCode: boolean;
  checkout: boolean;
  pinned: boolean;           // false: show "not pinned" (no package version)
  setup: string[];           // steps the user runs (docker build ...); Loadout never runs them; placeholders
  alsoIn: string[];
  scan: ScanResult;          // the folder's files + every launch line
};
type McpSkipped = { file: string; entry: string | null; problem: IpcError };
type McpSourceReview = {
  token: string;
  source: McpSourceInfo;     // folder: "~/..." or "…/<name>" outside home
  drafts: McpDraft[];
  skipped: McpSkipped[];     // problem messages never quote the file ("could not parse <file> (line N)")
  skippedFolders: string[];  // dependency and build folders not read or scanned: an info note
  trust: SourceTrustInfo | null;   // M39: the requested source (git sources and local folders)
  movedTrust: SourceTrustInfo | null; // the redirect target, when the host moved the repository (ask too)
  scan: ScanResult;                // the folder's files (rules-load warnings ride on ScanResult, M40)
};
type McpDraftPick = { key: string; draft: ServerDraft };
type McpSourceSaved = { ids: string[]; change: ChangeResult; scan: ScanResult };
type McpFieldChange = { field: string; old: string | null; new: string | null };
type McpUpdateCheck = {
  id: string;
  status: SkillUpdateStatus;       // "up_to_date" | "available" | "not_tracked" | "source_unreachable" | "source_blocked"
  current: string | null;
  latest: string | null;           // the commit, or a folder's content hash: pass back to update
  changes: McpFieldChange[];       // fields may be `os.<name>.`-prefixed
  files: SkillFileChange[];
  launch: string | null;           // the new base command line or URL
  launchLines: McpLaunchLine[];
  runsRepoCode: boolean;
  setup: string[];
  setupAgain: boolean;             // the update replaces the checkout: say "run the setup steps again"
  checkoutOutOfDate: boolean;      // entries blocked (`checkout_out_of_date`): offer Restore
  scan: ScanResult | null;
  trust: SourceTrustInfo | null;
  movedTrust: SourceTrustInfo | null;
  error: IpcError | null;          // e.g. `folder_on_other_machine`
};
type McpCheckoutReview = {
  token: string;                   // for restore_mcp_checkout / discard_mcp_source_review
  id: string;
  commit: string;
  trust: SourceTrustInfo | null;
  movedTrust: SourceTrustInfo | null;
  scan: ScanResult;                // the repository's files + the saved launch lines
};
```

### What was built

- Model: `[meta.source]` (`ServerSource`, `ServerSourceKind`) in `model/server.rs`, validated (git needs `url`,
