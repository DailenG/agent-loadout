# M28 Polish and design review: completion note

Not committed (the maintainer commits). Issue #1 (header toolbar alignment, design review, installer branding) and the #5 note on the Install card header. M28 lands in three parts: **M28a** (this part: toolbar and installer), M28b (the design review) and M28c (review fixes).

## M28a Header toolbar and installer

### What was built

#### Header toolbar (contract C4)

- The toolbar host (`.mcp-header-toolbar-slot`, the element `HeaderToolbar` portals into) is a flex row: `align-items: center`, one gap (`--header-toolbar-gap`, 8px), `justify-content: flex-end`, wrapping. Before, it was a block, so Projects' buttons sat inline with no gap between Add folder and Init manifest..., and Tools' Refresh sat on the left next to the title.
- One control height token, `--header-control-height` (34px), for every header action: `.skills-toolbar-button`, `.tools-refresh-button`, `.secondary-button--compact` in the header, the header search field, the Skills/MCP view toggle (its buttons are the token minus 6px), the batch-select button, and an `AppSelect` trigger in the header (History's scope filter, the Skills and MCP scope selects). Before: 33px toolbar buttons, 32px plain compact buttons, 40px selects, 60px Install tabs.
- Plain compact buttons in the header get the toolbar buttons' padding, gap, font and line height, so Refresh, Add folder and Init manifest... are one style.
- Toolbars that wrap their actions in an element (Skills and MCP `.skills-header-bar__tools`, History's toolbar section, Install's tab row) keep the host's row rules, so nested and direct actions share the same gap and alignment. Pages add no margins to toolbar buttons.
- A loading Refresh no longer moves down 1px (`.is-loading` kept `translateY(1px)` for as long as the refresh ran, which is the "Refresh sits off the line" effect). Hover lift and press feedback are unchanged and shared by all buttons.
- The title row aligns to the top and the title is one control height tall, so the title's center is the toolbar's center, the same on every page, including Settings and About, which have no toolbar (the host keeps the control height). When a long toolbar wraps in a small window, the title and the pending-changes pill stay level with its first row.
- Install's Skill/MCP switch in the header is a segmented control of the control height (2px shell, like the Skills view toggle) instead of a 60px floating pill, right-aligned like every other toolbar.
- The sidebar's edge toggle (`.sidebar-toggle--edge`, Windows and macOS) sits at the start of the main panel, level with the title, and the title started 4px after it. The main panel's left padding is now the handle width plus 16px, so the title and content clear it in both sidebar states.
- Install > MCP: the card title "Add an MCP server" ran straight into its description (a flex row); the Install card header is now title above description with a 4px gap (#5 note). The Local tab already did that.

Measured with `npm run dev:mock` and the eval browser at 1280x800 (dark theme): on Skills, MCP, Projects, Tools, Install and History every toolbar item is 34px tall, every gap is 8px and every item's center and the title's center are at the same y (55px); Settings and About put the title at the same y. Screenshots: `M28-header-skills.png`, `-mcp`, `-projects`, `-tools`, `-install`, `-history`, `-settings`, `-about` (window top, sidebar edge to window controls). At 960x560 the Skills toolbar wraps to two right-aligned rows with the title level with the first.

#### Installer

- New `src-tauri/windows/sidebar.bmp` (164x314) and `header.bmp` (150x57), uncompressed 24-bit, set as `bundle.windows.nsis.sidebarImage` and `headerImage` in `tauri.windows.conf.json`. The uninstaller's header defaults to `headerImage`. Both show the app icon (`src-tauri/icons/icon.svg`) and the "Loadout" wordmark on the icon's dark indigo (`#22184f` to `#140e33`); the sidebar adds a soft violet glow behind the icon.
- `scripts/render-installer-images.mjs` renders them: a headless Edge or Chrome draws each image from HTML (the SVG inlined as a data URI), the script crops the PNG screenshot and writes the BMP, then checks size and depth. No npm dependency. `--check` only checks the committed files; `LOADOUT_BROWSER` picks the browser. Text uses grayscale antialiasing (`--disable-lcd-text`), since NSIS stretches the image on high-DPI screens.
- `installer.nsi`: the finish page checkbox reads **Also add a desktop shortcut** (`LOADOUT_DESKTOP_SHORTCUT_TEXT`, a `!define` next to the template's others; it was Tauri's `$(createDesktop)`, "Create desktop shortcut"). The Start menu shortcut no longer logs NSIS's bare "Create shortcut: <path>": the line is suppressed and **Start menu shortcut created** (`LOADOUT_STARTMENU_SHORTCUT_DONE`) is logged once the `.lnk` exists. Both strings are English only, as the hooks' messages are.

### Decisions

1. **Header scope.** The height token applies to the toolbar-only classes everywhere (they appear only in toolbars and the apply drawer) and to `.secondary-button--compact` and `AppSelect` only inside the header, so compact buttons in cards and dialogs keep their 32px.
2. **No markup change.** `RefreshButton` keeps its classes: the mismatch was the host (block, no gap) and the 33/32px heights, both fixed in CSS, and the same classes are the Skills page's own Refresh. `HeaderSlots.tsx` needed no wrapper. Nothing is recorded for S6.
3. **Install's tabs follow C4** (right-aligned, control height) rather than the old centered floating pill, so the header reads the same on every page.
4. **Installer strings are `!define`s**, not language strings: the template's other Loadout messages (hooks) are English only, and the bundled language files do not have these strings.
