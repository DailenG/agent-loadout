# M39 Source trust (0.5.0, #24)

Status: implemented. Not committed (the maintainer commits). IPC changed: Main regenerates `src/ipc/bindings.ts`.

Trust in a source is an explicit, recorded decision, like project trust (SPEC 17). Installing or updating from a
git source asks once per source unless the user trusted it before; a block overrides any trust; a renamed,
transferred or force-pushed repository makes trust lapse so the user is asked again. Trust is never implicit: only
the app dialog, an interactive CLI prompt, `loadout source trust` or an explicit `--trust-source=...` flag answer.
The last two need no terminal, so an agent with a shell can use them too (explicit opt-ins, recorded as
`cli-command`/`cli-flag`; keeping agents out of trust approval is #8's narrower scope).

## Contract

This section is stable for M41 (MCP from Git or folder) and M42 (GUI). Changes after publication are listed at the
end of the section.

### Sources and keys

A source is identified by its **repo key**, built from a git URL by `SourceRef::from_git_url`:

| URL | Repo key | Owner key | Host key |
|---|---|---|---|
| `https://github.com/Acme/Skills.git`, `git@github.com:acme/skills`, `ssh://git@github.com/acme/skills`, `https://github.com/acme/skills/tree/main/x` | `github.com/acme/skills` | `github.com/acme/*` | (none: aggregator) |
| `https://git.acme.corp:8443/team/sub/tools` | `git.acme.corp:8443/team/sub/tools` | `git.acme.corp:8443/team/*` | `git.acme.corp:8443/*` |
| `https://git.acme.corp/tools.git` (no owner segment) | `git.acme.corp/tools` | (none) | `git.acme.corp/*` |
| `file:///C:/repos/x.git`, `C:\repos\x.git` (a local repository), a local folder (`SourceRef::from_local_path`) | `file:///C:/repos/x.git` (the absolute path with `/` separators, as given; `file:///home/me/x` on Unix) | (none) | (none) |

- Host: lowercased; userinfo (`user@`, tokens) dropped; a port is kept. Path: trailing `/` and `.git` dropped; on
  case-insensitive hosts (`github.com`, `gitlab.com`, `bitbucket.org`, `codeberg.org`) lowercased. GitHub keeps only
  `owner/repo` (`/tree/...`, `/blob/...` dropped); GitLab drops everything from `/-/`.
- Scopes, narrowest first: `repo` (always), `owner` (when the path has an owner segment), `host` (only for hosts that
  are not public aggregators: `github.com`, `gitlab.com`, `bitbucket.org`, `codeberg.org`, `gitee.com`, `git.sr.ht`,
  `huggingface.co` never offer `host`). Local sources offer `repo` only. `repo` is the default choice.
- Official marker (shown, never skips the prompt): `github.com/anthropics/*`, `github.com/modelcontextprotocol/*`.
- Precedence: any matching `block` (repo, owner or host) wins. Otherwise the most specific matching record decides:
  a `trust` record without a lapse is trusted; a lapsed one asks. No record asks.

### Store file `store/sources.toml` (synced with remotes; schema `docs/schema/sources.schema.json`)

```toml
schema = 1

[sources."github.com/acme/skills"]
decision = "trust"                      # trust | block
scope = "repo"                          # repo | owner | host (must fit the key's shape)
decided_at = 2026-11-23T10:00:00Z
via = "app"                             # app | cli-prompt | cli-flag | cli-command
machine = "laptop"                      # label of the machine that decided (optional)
url = "https://github.com/acme/skills"  # the URL it was decided for, userinfo removed (optional)

[sources."github.com/acme/skills".lapsed]  # present when trust lapsed; any "always trust" clears it
reason = "history_rewritten"            # history_rewritten | moved
at = 2026-11-24T08:00:00Z
detail = "github.com/other/skills"      # moved: the new repo key (optional)
```

Entity `sources` (history filter, restore `--path sources`). Commits: `source: trust <key> (<scope>)`
(op `source.trust`), `source: block <key>` (`source.block`), `source: untrust <key>` (`source.untrust`),
`source: trust lapsed for <key> (<reason>)` (`source.lapse`).

### Core API (`agent_loadout_core::sources`)

```rust
pub const SOURCES_FILE: &str = "sources.toml";

pub enum SourceScope { Repo, Owner, Host }            // as_str: "repo" | "owner" | "host"
pub enum TrustGrant { Once, Always(SourceScope) }      // the user's answer to the prompt
pub enum TrustVia { App, CliPrompt, CliFlag, CliCommand }

pub struct SourceRef { .. }
impl SourceRef {
    pub fn from_git_url(url: &str) -> Result<Self, CoreError>;   // invalid_value for no host / bad URL
    pub fn from_local_path(path: &Path) -> Result<Self, CoreError>; // absolute folder or repository
    pub fn key(&self) -> &str;                                  // repo key
    pub fn url(&self) -> &str;                                  // userinfo removed
    pub fn is_local(&self) -> bool;
    pub fn scopes(&self) -> Vec<SourceScope>;                   // offered for "always", narrowest first
    pub fn scope_key(&self, scope: SourceScope) -> Option<String>;
    pub fn is_official(&self) -> bool;
}

pub enum TrustState {
    Trusted { key: String, record: SourceRecord },
    Blocked { key: String, record: SourceRecord },
    Ask { reason: AskReason, lapse: Option<Lapse> },          // AskReason: FirstTime | NotTrusted | Lapsed
}
pub struct TrustCheck {
    pub source: SourceRef,
    pub state: TrustState,
    pub scopes: Vec<SourceScope>,
    pub official: bool,
    pub installed_skills: Vec<String>,                        // store skills whose git source has this repo key
}

/// Read-only: what the trust dialog shows. Never contacts the source.
pub fn check(store: &dyn StoreRead, source: &SourceRef) -> Result<TrustCheck, CoreError>;

/// The gate. Trusted: Ok. Blocked: `source_blocked`. Ask without a grant: `source_trust_required`.
/// `Once`: Ok, nothing recorded. `Always(scope)`: records trust at `scope` (one commit, clears lapses of
/// this source at every scope), then Ok. A grant never overrides a block.
pub fn admit(store: &Store<'_>, source: &SourceRef, grant: Option<TrustGrant>, via: TrustVia)
    -> Result<Admission, CoreError>;            // Admission { recorded: Option<CommitId> }

pub fn list(store: &dyn StoreRead) -> Result<Vec<(String, SourceRecord)>, CoreError>;  // sorted by key
pub fn trust(store, source: &SourceRef, scope, via) -> Result<Option<CommitId>, CoreError>;
pub fn block(store, source: &SourceRef, scope, via) -> Result<Option<CommitId>, CoreError>;
pub fn block_key(store, key: &str, via) -> Result<Option<CommitId>, CoreError>;   // an existing record
pub fn untrust(store, key: &str) -> Result<Option<CommitId>, CoreError>;           // removes trust or block
pub fn lapse(store, source: &SourceRef, change: &SourceChange) -> Result<Option<CommitId>, CoreError>;

pub enum SourceChangeKind { HistoryRewritten, Moved }
pub struct SourceChange { pub kind: SourceChangeKind, pub detail: Option<String> }  // Moved: new repo key
```

Rules for callers (skills here; M41 for MCP drafts):
- Call `admit` before anything from the source is saved to the store (after fetching and scanning is fine: the
  fetch runs no code). Order with M40: trust gate first, then the scan gate.
- `lapse` is called by update checks that detect a change (below); it writes only when a `trust` record currently
  admits the source, so untrusted sources ask anyway and blocked ones stay blocked.
- Local folders and archives installed as skills are not gated (picked on this machine; the M40 scan still runs).
  Local repositories (`file://`, a bare repository path) are gated like remote ones.

### Change detection on update (skills: `skills::install::latest`)

- **Force-push**: after fetching, the old source commit must be an ancestor of the new one
  (`git merge-base --is-ancestor`; a shallow cache clone is deepened with `--shallow-since` to the old commit's date
  first, `--unshallow` when the old commit is not in the clone). Anything not proven fast-forward is
  `history_rewritten`.
- **Renamed or transferred**: git's `warning: redirecting to <url>` on fetch or clone gives the new URL; a different
  repo key is `moved` (detail: the new key).
- The check result carries the change and the trust check; trust lapses (`lapse`) and the update needs a grant again.

### Skills integration

- `skills::install`: the decisions struct shared with M40 gains `trust: Option<TrustGrant>` and `via: TrustVia`;
  git installs and updates (`update`, `update_reviewed`) go through `admit`.
- `UpdateCheck` gains `trust: Option<TrustCheck>` (git skills) and `source_change: Option<SourceChange>`.
- `FileChange` gains `script: bool`: an added or modified file that looks executable (`.sh`, `.bash`, `.zsh`,
  `.ps1`, `.psm1`, `.bat`, `.cmd`, `.py`, `.js`, `.mjs`, `.cjs`, `.ts`, `.rb`, `.pl`, `.exe`, `.dll`, `.so`,
  `.dylib`, or content starting with `#!`), highlighted in the update review.

### Error codes

- `source_trust_required`: the source is not trusted and no grant was given; open the trust dialog
  (`check_source_trust`) and retry with the user's answer. CLI: exit 1 with a hint about `--trust-source`.
- `source_blocked`: a block matches; nothing is fetched or written. Unblock with `loadout source untrust <key>` or
  Settings > Sources.

### CLI

- `loadout source ls` (`--json`: `{schema, sources: [{key, decision, scope, decided_at, via, machine, url,
  lapsed: {reason, at, detail}|null, official}]}`).
- `loadout source trust <URL|KEY> [--scope repo|owner|host]`, `loadout source block <URL|KEY> [--scope ...]`,
  `loadout source untrust <KEY>` (removes a trust or a block record; nothing is uninstalled).
- `loadout skills add <URL>` and `loadout skills update [ID]`: on an untrusted source an interactive terminal prompts
  `[o]nce / [a]lways / [c]ancel` (always then asks the scope, repo default). Without a terminal, or with `--json`,
  the command fails with `source_trust_required` unless `--trust-source[=once|repo|owner|host]` is given
  (`--trust-source` alone is `once`). `--yes` never answers a trust prompt.

### IPC (app, `src-tauri/src/commands/sources.rs`; camelCase in TypeScript)

```ts
type SourceScope = "repo" | "owner" | "host";
type TrustGrantArg = { kind: "once" } | { kind: "always"; scope: SourceScope };
type SourceLapse = { reason: "history_rewritten" | "moved"; at: string; detail: string | null };
type SourceChange = { kind: "history_rewritten" | "moved"; detail: string | null };
type SourceScopeOption = { scope: SourceScope; display: string };   // "github.com/acme" for owner
type SourceTrustState =
  | { kind: "trusted"; scope: SourceScope; display: string; decidedAt: string }
  | { kind: "blocked"; scope: SourceScope; display: string; decidedAt: string }
  | { kind: "ask"; reason: "first_time" | "not_trusted" | "lapsed"; lapse: SourceLapse | null };
type SourceTrustInfo = {
  display: string;              // repo key; a local source under its placeholder root ("~/repos/x")
  official: boolean;
  scopes: SourceScopeOption[];  // narrowest first; "repo" is the default
  state: SourceTrustState;
  installedSkills: string[];
  change: SourceChange | null;  // set by update checks
};
type SourceRecordInfo = {
  id: string;                   // opaque handle (hash of the key); never a path
  display: string;
  scope: SourceScope;
  decision: "trust" | "block";
  decidedAt: string;
  via: "app" | "cli-prompt" | "cli-flag" | "cli-command";
  machine: string | null;
  lapse: SourceLapse | null;
  official: boolean;
};
```

- `block_source(id: string) -> string | null` (turns a listed record into a block at the same scope)

### Changes since publication

- Owner and host keys end in `/*` (`github.com/acme/*`, `git.acme.corp/*`) so a repository at a host's root
  (`git.acme.corp/tools`) is never mistaken for an owner. Local keys keep the path as given (`.git` included).
- Core: `sources::would_admit(read, &source, grant)` (the gate's errors, records nothing; `skills::install`
  calls it before cloning), `sources::record_key(store, key, decision, via, url)` (CLI keys),
  `sources::record_id(key)` / `key_of_id(read, id)` (the IPC ids), `SourceRef::local_path()`.
- Skills: `skills::install::Decisions { allow_dangerous, trust, via }` (shared with M40);
  `Prepared::trust_source()` (the redirect target when the host moved the repository) and
  `Prepared::source_change()`; `install_prepared` admits before M40's scan gate. `pub fn looks_executable`.
- App helpers for M41 (all `pub` in `commands/sources.rs`): `trust_info(env, &TrustCheck, Option<&SourceChange>)`,
  `check_source(core, &SourceRef, Option<&SourceChange>)`, `grant_of(Option<TrustGrantArg>) -> (Option<TrustGrant>,
  TrustVia)`, `change_of`. `SourceRecordInfo.via` is nullable (hand-written records may lack it). The ask reasons
  are their own enum `SourceAskReason`; lapse and change kinds share `SourceLapseReason`.
- M44 review (#26): `SourceRef::whole_host(url)` keys a remote MCP server by its host (`host/*`, trusted or
  blocked at the host scope only). A registry server's drafts are gated on what each runs (its package on its
  package registry, or its remote's host), never on the publisher-written repository; one review can ask about
  several keys (`Draft.trust_source`, `Pick.trust`; IPC `McpDraft.trust`, `McpDraftPick.trust`).

Review fixes (local://review-M39.md, Main's decisions):

- **URL parsing and keys (P0-1, P1-1, P2-4).** `SourceRef` parses with the `url` crate (plus scp-style). Refused
  (`invalid_value`): `?`, `#`, `\`, `.`/`..` segments, percent-encoded `.`, `/`, `\`, empty segments, control
  characters and spaces, more than one `@`, `@` in a path, malformed `%`. Normalized: host case, one trailing `.`,
  each scheme's default port, escaped unreserved characters, uppercase hex escapes, trailing `.git` (key only), path
  case on case-insensitive hosts. The whole path is checked before the GitHub `owner/repo` and GitLab `/-/` cuts.
  Git is always handed `SourceRef::fetch_url(given)`: the canonical URL rebuilt from the parsed parts, with the
  user's userinfo re-attached only for the fetch (never stored or shown). Keys in `sources.toml`, `record_key` and
  CLI `source trust|block|untrust` must be canonical (`github.com/Evil/*` becomes `github.com/evil/*`; validation
  refuses non-canonical keys). The stored `url` is the canonical URL (ssh username kept, no other userinfo).
  New API: `SourceRef::{fetch_url, is_insecure, block_keys, from_key_or_url, canonical_key, redact_userinfo}`,
  `model::sources::{INSECURE_KEY_PREFIXES, without_insecure_prefix}`.
- **Insecure transports (P3-2).** `http://` and `git://` sources have their own keys with a scheme prefix
  (`http://host/path`, `http://host/owner/*`, `git://host/*`). HTTPS/SSH trust doesn't admit them, but a block on
  the plain key does (`block_keys`). `official` is false for them. `TrustCheck`/`SourceTrustInfo.insecure`; the CLI
  prompt and dialog say the connection is unencrypted; CLI trust JSON adds `insecure`.
- **Credentials (P3-1).** Every message from `SourceRef`, `unreachable()`, `git_failed()` and the history check
  shows userinfo as `***` (`redact_userinfo`).
- **Redirects (P1-2, P1-3, P2-2, P2-6).** Gated clone and fetch run with `--no-progress` (not `--quiet`) and
  `LC_ALL=C`, `LANGUAGE=C`. Only a line starting with `warning: redirecting to ` counts, only for http(s)
  (`detect::redirect_target(url, stderr)`, `target_of`, `moved_to`); `remote:` lines never do. A redirect only adds
  a question: `Prepared::trust_source()` is always the URL the user typed and `Prepared::moved_to()` the new
  location; both are checked; `Decisions::trust` answers for the typed source and `Decisions::moved_trust` for the
  new location (`--trust-source` never carries over; the CLI prints `note: X moved to Y` and prompts again).
  `install()` fails with `source_trust_required` naming the new location when it is untrusted. An update of a moved
  repo checks both, then rewrites `meta.source.url` to the new canonical URL, so later checks see no redirect and
  record no new lapse. `UpdateCheck.moved_trust`.
- **Rollback force-push (P2-1).** A failing deepen fetch with a reachable remote (`git ls-remote`) is a rewrite.
- **Blocked sources are never contacted (P2-5).** `sources::refuse_blocked(read, &SourceRef)` runs before any
  clone or fetch in CLI `skills add`, `check_update`, `update` and the app's `review_git_skill`.
  `UpdateStatus::Blocked` (`source_blocked`): not contacted, `error` is `source_blocked`; apply-mode CLI update
  counts it as failed, `--check` doesn't.
- **Sync (P2-3).** `store/merge.rs` merges `sources.toml` record by record: a side that only recorded a lapse
  yields to the other side's decision (untrust wins over lapse), two lapses keep the earlier, any other record both
  sides changed is a whole-record conflict; a merge never writes a broken record.
- **`skills update --check`** still records the lapse of a trusted source that was force-pushed or moved (no skill
  is updated); the CLI help says so.
- **CLI (P3-3).** `--trust-source` takes a value only with `=` (`--trust-source=repo`); `--trust-source repo` means
  "skill `repo`, trusted once".
- **IPC.** `SkillInstallReview` and `SkillUpdateCheck` are camelCase and gain `movedTrust: SourceTrustInfo | null`;
  `install_reviewed_skill(..., trust, movedTrust)` and `update_skill(..., trust, movedTrust)`;
  `SkillUpdateStatus` gains `source_blocked`; `SourceTrustInfo.insecure: boolean`; `review_git_skill` returns
  `source_blocked` before fetching; `install_git_skill` is unchanged (a moved, untrusted target fails; use the
  review flow). App helper `commands::sources::refuse_blocked`; `check_source`, `trust_info`, `grant_of` and
  `TrustGrantArg` are unchanged.
