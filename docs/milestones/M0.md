## Spec ambiguities resolved

1. **`paths::loadout_home` signature.** The brief says `loadout_home(&Env)`. Sync-root detection needs file access and the CLI has `--home`, so it is `loadout_home(&Env, &dyn Fs, Option<&Path>)`. Precedence: `--home`, then `LOADOUT_HOME`, then the per-OS default. The "or Settings" override in 4.5 waits for the settings store (M1/M2).
2. **Windows profile source.** 19 item 1 has CLI tests set `USERPROFILE`, `APPDATA` and `LOCALAPPDATA`, and they only isolate the binary if it honors them. The CLI therefore reads those variables first and falls back to the Known Folders (`dirs`, which calls `SHGetKnownFolderPath`). `HOME` is never read on Windows.
3. **Relative overrides.** A relative `LOADOUT_HOME` fails with `invalid_path`; `--home` is made absolute against the working directory first. A relative `XDG_DATA_HOME` is ignored, as the XDG spec requires.
4. **Sync-root detection boundary.** `Fs::root()` exposes the confinement root; the ancestor walk stops there, so core tests never probe above the temp root. With `RealFs` the walk goes to the file system root.
5. **Provider roots.** OneDrive from the `OneDrive`, `OneDriveConsumer` and `OneDriveCommercial` variables (Windows fills them from the registry); Dropbox from `info.json` (`%LOCALAPPDATA%`/`%APPDATA%\Dropbox` on Windows, `~/.dropbox` elsewhere); Google Drive from `~/My Drive`, `~/Google Drive`, a `<drive>:\My Drive` stream mount and `~/Library/CloudStorage/GoogleDrive-*` on macOS (which also covers OneDrive and Dropbox there). The core gets no registry access, so a Google Drive mirror folder at a custom location is not detected.
6. **`doctor` output.** `loadout doctor` prints findings only; `--paths` adds the OS folders and the data layout. `sync_root_detected` is a warning and exits 0. `--json` documents carry `"schema": 1`; errors go to stdout as `{"schema": 1, "error": {code, message, path}}` with `--json`, else to stderr as `error[code]: ...`, exit 1.
7. **Baked-id allowlist.** `SPEC.md` and `LANDSCAPE.md` name the SkillDock id and dead upstream on purpose; both checks skip them. The patterns are assembled from fragments so the checkers do not match themselves. Files scanned: tracked plus untracked, non-ignored.
8. **Toolchain.** `rust-toolchain.toml` uses `stable` (plus rustfmt and clippy) instead of a pinned version, so local builds never download a toolchain; the MSRV is `rust-version = "1.100"` in the workspace manifest.

## Deviations and deferrals

- Global flags: only `--home` and `--json` (both global). `--yes`, `-v` and `--identify` wait for commands that use them.
- CI: no `npm test`, `tsc` or bundle steps until M14. `cargo deny` runs once on Ubuntu.
- CLI tests use the real file system, so the sync-root walk probes `.sync` and `.stfolder` (existence only) in the ancestors of the OS temp directory. A machine whose temp directory sits inside a sync folder would fail the CLI tests.
- `RootedFs` checks paths lexically; a symlink inside the root that points outside is not caught.
