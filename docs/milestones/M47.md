# M47 Optional external scanner: Snyk Agent Scan (0.7.0, #27)

Status: backend, CLI and app commands implemented (this slice); GUI in M49. Not committed (the maintainer commits).

**Disabled since 0.7.1 (2026-11-24):** Snyk's free tier refuses new accounts by every path, so the maintainer dropped
Snyk. The switch `scan::external::AVAILABLE` (and `EXTERNAL_SCANNER_AVAILABLE` in `src/app/components/ExternalScan.tsx`)
is `false`: nothing runs, downloads or shows; only `loadout scanner remove` (cleanup of a 0.7.0 install) and
`scanner status` work. The contract below is kept as history; flip the switch to re-enable.

Off by default. When the user turns it on, installs it and sets a token, Loadout runs a pinned, verified build of
Snyk Agent Scan on a skill before it is installed or updated (or on a library skill on request) and shows its
findings beside the built-in scan's. The content is sent to Snyk's analysis API: the user is told so before turning it
on. 0.7.0 scans skills only; MCP scanning stays open in #27.

## Contract

Published first for the GUI slice. Everything here is implemented as written; later changes go to "Changes since
publication" below.

### Core API (`agent_loadout_core::scan::external`)

```rust
pub const SCANNER: &str = "snyk-agent-scan";       // Finding::scanner and ExternalReport::scanner
pub const VERSION: &str = "0.7.1";                 // the pinned release (tag v0.7.1)
pub const SIGNING_FINGERPRINT: &str = "EF4FF9D18D82D5629B82491D2A20F86E4EF131B1"; // dev script only
pub const DEFAULT_TIMEOUT: Duration = Duration::from_secs(60);
pub const MAX_DOWNLOAD: u64 = 64 * 1024 * 1024;

/// One pinned release asset (compiled in; the SHA-256 comes from the release's signed sha256sums.txt.asc).
pub struct Asset { pub name: String, pub sha256: String, pub size: u64 }
pub fn pinned_asset() -> Option<Asset>;            // this build's OS and architecture; None = unsupported
pub const PINNED: &[PinnedAsset];                  // the 5 platforms (Windows x64, Linux x64/arm64, macOS arm64/x64)

/// `[snyk_agent_scan]` in state/local-settings.toml (machine-local, never synced).
pub struct Settings { pub enabled: bool, pub token: Option<String>, pub timeout_secs: Option<u64> }
pub fn settings(fs, home) -> Result<Settings, CoreError>;
pub fn set_enabled(fs, home, enabled: bool) -> Result<(), CoreError>;
/// A secret REFERENCE, never a value: a secrets.toml alias (`SNYK_TOKEN`) or a provider reference
/// (`env:NAME`, `keyring://service/account`, `op://vault/item/field`). `op-env://` is refused
/// (Loadout never reads 1Password Environment values). `None` clears it.
pub fn set_token(fs, home, reference: Option<&str>) -> Result<(), CoreError>;  // invalid_ref
pub enum TokenRef { Alias(String), Provider(SecretRef) }   // TokenRef::parse(&str)

/// <LOADOUT_HOME>/tools/snyk-agent-scan/<version>/: the binary and installed.json, written last.
pub struct Tool { .. }
impl Tool {
    pub fn pinned(home: &LoadoutHome) -> Result<Tool, CoreError>;   // not_supported_on_os without an asset
    pub fn new(home: &LoadoutHome, version: &str, asset: Asset) -> Tool;  // tests: a stub with its own hash
    pub fn dir(&self) -> PathBuf;  pub fn binary(&self) -> PathBuf;
    pub fn installed(&self) -> bool;                // installed.json matches the asset and the binary has its size
    /// Downloads into a temporary file in dir(), verifies size and SHA-256, then renames and writes
    /// installed.json. A mismatch deletes the download: `scanner_verification_failed`; HTTP problems:
    /// `scanner_download_failed`. `progress(received, total)`.
    pub fn install(&self, download: &dyn Download, progress: &mut dyn FnMut(u64, u64)) -> Result<(), CoreError>;
    pub fn remove(&self) -> Result<bool, CoreError>;  // the whole tools/snyk-agent-scan folder
}
pub fn download_url(version: &str, asset: &str) -> String; // https://github.com/snyk/agent-scan/releases/download/v<version>/<asset>
pub trait Download { fn fetch(&self, url: &str, out: &mut dyn Write, max: u64,
                              progress: &mut dyn FnMut(u64, u64)) -> Result<u64, CoreError>; }
pub struct UreqDownload;  // UreqDownload::new(env): https only; redirects followed by hand, only to
                          // github.com, objects.githubusercontent.com, release-assets.githubusercontent.com

pub struct Status { pub supported: bool, pub installed: bool, pub enabled: bool, pub version: &'static str,
                    pub token: Option<String> /* the reference text */, pub binary: Option<PathBuf> }
pub fn status(fs, home) -> Result<Status, CoreError>;

/// Per run override: `--external` / `--no-external` (CLI); the app always uses Default.
pub enum Choice { Default, On, Off }
pub fn wanted(settings: &Settings, choice: Choice) -> bool;   // On, or Default and enabled

/// A run that is ready (installed, token resolved), or the not-scanned report explaining why not.
pub fn prepare_run(env, fs, home, store: Option<&Store>, delivery: &DeliveryEnv) -> Result<Runner, ExternalReport>;
pub struct Runner { .. }
impl Runner {
    pub fn new(tool: Tool, token: SecretValue, timeout: Duration) -> Runner;
    /// Writes `files` into a fresh folder below <LOADOUT_HOME>/cache/scan-external/, runs
    /// `<binary> scan --json --storage-file <run dir>/storage.json <abs skill folder>` with stdin closed, a scrubbed
    /// environment (SNYK_TOKEN plus the variables listed under "Child environment") and the timeout; the whole
    /// process tree is killed on timeout or cancel (Windows job object, Unix process group); the folder is removed.
    pub fn scan_files(&self, env, home, files: &SkillFiles, cancel: Option<&AtomicBool>) -> ExternalReport;
}

pub struct ExternalReport {
    pub scanner: String,                // "snyk-agent-scan"
    pub version: String,                // "0.7.1"
    pub status: ExternalStatus,         // Scanned | NotScanned | NotUnderstood
    pub reason: Option<NotScanned>,     // Some iff status == NotScanned
    pub verdict: Verdict,               // from findings; Clean when none (never read it alone: check status)
    pub findings: Vec<Finding>,         // scanner = "snyk-agent-scan"; rule = Snyk's risk name
    pub content_hash: Option<String>,   // skills::content_hash of what was scanned
    pub detail: Option<String>,         // English, one line, no paths or tokens (e.g. Snyk's limit message)
}
pub enum ExternalStatus { Scanned, NotScanned, NotUnderstood }   // as_str(): "scanned" | "not_scanned" | "not_understood"
pub enum NotScanned {   // as_str() snake_case
    NotInstalled, UnsupportedPlatform, NoToken, TokenUnavailable, TokenRejected, LimitReached, TooLarge,
    Unreachable, Timeout, Canceled, WouldStartServer, Failed,
}
/// Ok unless verdict == Dangerous && !allow_dangerous: scan_blocked ("Snyk Agent Scan found N dangerous
/// findings: ..."). A NotScanned or NotUnderstood report never blocks.
pub fn gate(report: &ExternalReport, allow_dangerous: bool) -> Result<(), CoreError>;
/// The JSON adapter (pub for tests): stdout of one run, the exit code, the scanned folder (to make paths relative).
pub fn parse(stdout: &[u8], exit: Option<i32>, root: &Path) -> ExternalReport;
```

Mapping (Snyk JSON `scan_path_responses[].skill_risks[].risk_indexes`): score >= 600 or `malicious_code` is
`dangerous`; >= 300 `warning`; otherwise `info`. One finding per location (`file` relative to the skill folder,
`line`), message = Snyk's evidence (<= 400 chars), excerpt = `malicious_urls` / `unverifiable_urls` (<= 120 chars).
Errors with `is_failure`: "Daily usage limit reached" = `limit_reached`, 413 / "too large" = `too_large`,
"Unauthorized" = `token_rejected`, "Could not reach" / "Tried calling" = `unreachable`, `user_declined` =
`would_start_server`, anything else = `failed` (with Snyk's message as `detail`). Empty stdout = `no_token`
(the CLI exits 1 without printing JSON when the token is missing). Output that is not the v0.6+ schema:
`not_understood` ("scanner output not understood (version 0.7.1)"), never clean.

### Skill install and update (`agent_loadout_core::skills::install`)

```rust
impl Prepared {
    pub fn set_external(&mut self, report: Option<ExternalReport>);  // the external scan of files()
    pub fn external(&self) -> Option<&ExternalReport>;
}
pub struct Decisions { .., pub external: Option<ExternalReport> }    // update: the external scan of the reviewed content
pub struct Installed { .., pub external: Option<ExternalReport> }
pub struct Updated   { .., pub external: Option<ExternalReport> }
```

Gates before a store commit: source trust, built-in `scan::gate`, then `external::gate` with the same
`allow_dangerous`. `install_prepared` gates `Prepared::external()`; `update`/`update_reviewed` gate
`Decisions::external`, which must have the content hash of what is written (`entry_changed` otherwise: check again).
`UpdateCheck` is unchanged: the caller runs the external scan on `cached_latest(..)` after the check.

### CLI

`loadout skills scan` already exists (it classifies client skill folders), so the scanner commands get their own noun,
`loadout scanner`. There is one optional scanner, so its subcommands take no scanner name; `ls` lists the built-in
scanner too.

| Command | Does |
|---|---|
| `loadout scanner ls` | Both scanners: `builtin` (always on) and `snyk-agent-scan` (supported, installed, enabled, token set). |
| `loadout scanner status` | Snyk Agent Scan: pinned version, platform asset, installed, enabled, token reference, binary path, what is sent. |
| `loadout scanner install` | Download and verify the pinned build (progress on stderr). Installing does not turn it on. |
| `loadout scanner remove` | Delete `tools/snyk-agent-scan`; settings are kept. |
| `loadout scanner enable` / `disable` | The machine-local switch. `enable` prints what is sent to Snyk. |
| `loadout scanner token [REF] [--clear]` | Show, set or clear the token reference (an alias or provider reference, never a value). |
| `loadout scanner run <SKILL>` | Scan a library skill's store content now (report only, exit 0; exit 1 when it could not run). |

`loadout skills add` and `loadout skills update` gain `--external` / `--no-external` (one run; default: the switch).
Human output adds `Snyk Agent Scan: <verdict> (N findings)` with the finding lines, or
`Snyk Agent Scan: not scanned (<reason>)`; `--json` adds `"external": {scanner, version, status, reason, verdict,
detail, findings}` (absent when the scanner did not run). A dangerous external verdict without `--allow-dangerous`:
error `scan_blocked`, exit 8, as for the built-in scan.

### IPC (app)

Types (`src-tauri/src/commands/scanner.rs`):

```ts
type ExternalScanStatus = "scanned" | "not_scanned" | "not_understood";
type ExternalNotScanned = "not_installed" | "unsupported_platform" | "no_token" | "token_unavailable"
  | "token_rejected" | "limit_reached" | "too_large" | "unreachable" | "timeout" | "canceled"
  | "would_start_server" | "failed";
type ExternalScanResult = {
  scanner: string;              // "snyk-agent-scan"
  version: string;              // "0.7.1"
  status: ExternalScanStatus;
  reason: ExternalNotScanned | null;
  verdict: ScanVerdict;         // meaningful only when status is "scanned"
  findings: ScanFinding[];      // ScanFinding.scanner = "snyk-agent-scan"
  detail: string | null;        // English, no paths or values
};
type ScannerTokenKind = "alias" | "env" | "keyring" | "one_password";
type ExternalScannerStatus = {
  scanner: string;              // "snyk-agent-scan"
  version: string;              // pinned version
  supported: boolean;           // a pinned build exists for this OS and architecture
  installed: boolean;
  enabled: boolean;
  tokenRef: string | null;      // the reference text, never a value
  tokenKind: ScannerTokenKind | null;
  sizeBytes: number | null;     // download size of this platform's build
};
type ScannerTokenCheck = { ok: boolean; reason: ExternalNotScanned | null }; // resolves the reference; never returns it
// Event (tauri-specta): scannerInstallProgress
type ScannerInstallProgress = { received: number; total: number };
```

Commands:

| Command | Returns | Notes |
|---|---|---|
| `scanner_status()` | `ExternalScannerStatus` | No network, no secret resolution. |
| `install_scanner()` | `ExternalScannerStatus` | Emits `ScannerInstallProgress` events. `scanner_download_failed`, `scanner_verification_failed`, `not_supported_on_os`. Does not enable. |
| `remove_scanner()` | `ExternalScannerStatus` | |
| `set_scanner_enabled(enabled)` | `ExternalScannerStatus` | Machine-local. |
| `set_scanner_token(reference)` | `ExternalScannerStatus` | `reference: string \| null`; `invalid_ref`. Use an alias from the Secrets page or a provider reference. |
| `check_scanner_token()` | `ScannerTokenCheck` | Resolves the reference (may show the 1Password prompt); Snyk is not contacted. |
| `external_scan_review(token)` | `ExternalScanResult` | Runs on an install review's content (`token` from `review_*_skill`) and attaches the result to the review: `install_reviewed_skill` then needs `allowDangerous` for a dangerous external verdict. |
| `external_scan_update(id, latest)` | `ExternalScanResult` | Runs on the content `check_skill_updates` fetched (`latest` = its commit; `entry_changed` when the cache moved on) and remembers it for `update_skill(id, latest, allowDangerous)`. |
| `external_scan_skill(id)` | `ExternalScanResult` | A library skill's store content; report only. |
| `cancel_external_scan()` | `null` | Cancels every running external scan (result `not_scanned` / `canceled`). |

Each `external_scan_*` command runs only when the scanner is enabled and installed and a token is set; otherwise it
returns `not_scanned` with the reason (`not_installed`, `no_token`, ...) without running anything. A disabled
scanner returns `scanner_unavailable` (error), so the GUI calls these only when `enabled`.

Fields added: `SkillInstalled.external: ExternalScanResult | null`, `SkillUpdated.external: ExternalScanResult | null`
(the external report the install or update was gated on).

`ErrorCode` gains `scanner_unavailable` (the scanner is off), `scanner_download_failed` (the download failed: network,
HTTP status, a redirect to another host, too large) and `scanner_verification_failed` (the download's size or SHA-256
is not the pinned one; nothing was installed).

### Child environment

Only these reach the scanner: `SNYK_TOKEN` (the resolved value), `PATH`, `SYSTEMROOT`, `WINDIR`, `TEMP`, `TMP`,
`TMPDIR`, `HOME`, `USERPROFILE`, `USERNAME`, `APPDATA`, `LOCALAPPDATA`, `LANG`, `LC_ALL`, the proxy variables
(`HTTPS_PROXY`, `HTTP_PROXY`, `ALL_PROXY`, `NO_PROXY`, any case), `SSL_CERT_FILE`, `SSL_CERT_DIR`,
`REQUESTS_CA_BUNDLE`, plus `PYTHONIOENCODING=utf-8` and `PYTHONUTF8=1`. Never `MACHINE_SERIAL`, `SNYK_API`,
`AGENT_SCAN_*`, `SNYK_CLI_USE` or any other variable.

## Changes since publication

- **Install is cancelable** (asked by the GUI slice): `cancel_external_scan()` also stops a running
  `install_scanner()`; the partial download is deleted, nothing is installed, and the command fails with the new
  `ErrorCode` `canceled` (not `scanner_download_failed`). Core: `Tool::install(download, progress, cancel:
  Option<&AtomicBool>)` and `Download::fetch(.., cancel)`.
- `parse(stdout, exit, root, version)` takes the scanner version (the report names it).
- `external_scan_update(id, latest)`: `latest` is accepted for the GUI's bookkeeping; the scan reads the cache clone
  the last check left. If the source moved on in between, `update_skill` answers `entry_changed` (the report's content
  hash must equal the content written), not the scan command.
- Core helpers added: `resolve_token(..)` (also used by `check_scanner_token`), `Settings::timeout()`,
  `ExternalReport::summary()`, `DISCLOSURE` (the CLI's "what is sent" text), `PASSED_VARS`, `child_env`, `RUNS_DIR`.
- App: `skills::update(.., external: Option<ExternalReport>)` gained the report parameter; `update_skill` takes the
  remembered report and puts it back when the update fails (so "Update anyway" is still gated on it).
- **Review of M49 (local://review-M49.md), IPC changed again (bindings regenerated):**
  - F1: `external_scan_update` drops the report remembered for `id` before it runs, so a failed or canceled run never
    leaves an older one; `set_scanner_enabled(false)` drops every remembered update report and the external reports
    attached to install reviews (a review being installed at that moment keeps its own).
  - F7: a second `install_scanner` while one runs fails with `locked`.
  - F10: `ExternalScannerStatus.timeoutSecs: number` (the effective timeout); `open_help` topics `snyk_terms` (the
    v0.7.1 `TERMS.md`) and `snyk_privacy` (Snyk's privacy policy).
  - F12: per-run cancel: `external_scan_review(token, runId)`, `external_scan_update(id, latest, runId)`,
    `external_scan_skill(id, runId)`; `cancel_external_scan(runId: string | null)` cancels that run only, or every run
    and the install with `null`.
  - F8: `remove_scanner` keeps the token reference; since the M47 review it also turns the switch off (below).
- **Review of M47 (local://review-M47.md), IPC changed (bindings regenerated):**
  - New `ErrorCode` `external_scan_required` (F10): `install_reviewed_skill` of a git or catalog review, and
    `update_skill`, refuse while the scanner is on, installed and has a token reference but no external report is
    attached / remembered (a `not_scanned` or `canceled` report counts). A local folder/archive review is exempt (the
    GUI scans it only on request). `install_git_skill` (no review) refuses in that state too.
  - `remove_scanner` (and `loadout scanner remove`) also turns the scanner off; core `external::remove(fs, home,
    &tool)`. In the app it also cancels runs and drops reports, as `set_scanner_enabled(false)` does.
  - F7: `set_scanner_enabled(false)` cancels every running external scan (not the install). `external_scan_*` check
    the switch before resolving the token, again just before the scanner starts and once more after it ends; a run
    the switch went off for fails with `scanner_unavailable` and attaches / remembers nothing.
  - F1: `set_scanner_token` / `loadout scanner token` refuse an alias the secrets catalog does not define, and no
    error repeats the input (it may be a pasted token); `resolve_token` details no longer name the alias. Core:
    `set_token(fs, home, store: Option<&dyn StoreRead>, reference)`.
  - F2: `prepare_run` hashes the installed binary once per command (new `Tool::verify()`); a mismatch deletes
    `installed.json` and reports `not_installed` with a detail; `Tool::install` re-verifies an installed binary and
    downloads again on a mismatch. New `prepare_run_with(tool, ..)` (tests and the CLI's debug-only
    `LOADOUT_TEST_AGENT_SCAN` stub override) and `status_of(fs, home, tool)`; `required(fs, home)` for F10.
  - F3: the child's `TEMP`/`TMP`/`TMPDIR` are `<run>/tmp` (new `TEMP_VARS`; they left `PASSED_VARS`);
    `child_env(env, token, tmp)`.
  - F4: a run sweeps `run-*` folders whose `started` file is over an hour old; an install deletes
    `.agent-scan*.loadout-*.tmp` partial downloads first.
  - F5: on Windows a job object that cannot be created or assigned stops the scanner at once (`not_scanned` /
    `failed`); pipe readers are waited for at most 5 s after the tree is killed.
  - F6: the CLI handles Ctrl+C / SIGTERM / SIGHUP (`ctrlc` crate, new dependency) during a run or download: the
    cancel flag kills the tree, removes the run folder or partial download, then the command exits 130.
  - F8: `parse(stdout, stderr, exit, root, version)`: empty stdout after a failure is `token_rejected` when the last
    4 KiB of stderr name the token (`SnykTokenError`, 401), else `failed` with the last stderr line (token value
    masked) as the detail; `no_token` now means only "no reference / empty value". Stdout over 16 MiB is
    `not_understood`.
  - F9: the CLI settles source trust before the external run: `skills add` checks a moved repository's trust first,
    `skills update` runs the scan after the trust answer and never for a blocked source, and `update --check` scans
    only updates whose sources are already trusted.

## Known limits

- Unix: a CLI run interrupted with Ctrl+C leaves the scanner's process group running until Snyk's own timeouts end
  it (the group does not receive the terminal's SIGINT). Windows kills it with the job.
- Windows: the child joins its job right after it starts; the PyInstaller bootloader unpacks before it starts its own
  child, so that child is in the job.
- `cargo deny` is not available locally; CI runs it (no new crates: `win32job` and `rustix` were already in the tree).
