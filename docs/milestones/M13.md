## Error codes added

`remote_rejected` (the push was refused for another reason than a non-fast-forward, such as a protected branch or a hook, or again after the pull and one retry), `remote_auth_failed`, `tool_not_found` (git or gh missing). `remote push` exits 4 when the retry's pull conflicts (`merge_conflict`), 1 for other failures.

## Spec ambiguities resolved

1. **Isolation in tests, not in use.** The git Loadout runs gets the user's environment (through `Env`, as for `op`) without git's repository-local variables (`GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE` and the rest of `git rev-parse --local-env-vars`), plus `GIT_TERMINAL_PROMPT=0` (with stdin closed a terminal prompt could only hang) and `LOADOUT_HOME` set to the data directory in use, so the token helper reads the right `remotes.toml` under `--home`. Tests isolate git through environment variables only.
2. **Progress and idle timeout.** `--progress` lines (split on `\r` and `\n`) go to the caller; the CLI shows them on one updating stderr line only when stderr is a terminal. Any output on stdout or stderr resets the 120 s idle timer. When it runs out, git and everything it started are stopped (`taskkill /T /F` on Windows, where `git.exe` on `PATH` is a launcher; elsewhere git itself), the pipe readers are never waited for, and the run is `remote_unreachable`. A credential manager window left open for 120 s without git output is stopped too.
3. **Rejection and retry (SPEC 9.8).** Only a non-fast-forward rejection (`[rejected]` with `non-fast-forward` or `fetch first`) runs a pull, then one more push. If that pull conflicts, nothing is pushed and the push fails with `merge_conflict` (the conflicts are in `MERGE_STATE.json`); if its merge fails otherwise, that error is returned; a second rejection is `remote_rejected`. `[remote rejected]` (protected branch, hook) is `remote_rejected` at once. The URL follows `--` in git's arguments, and names and URLs are checked again when read from `remotes.toml`.
4. **Fetch.** SPEC 9.6's refspecs, plus `--no-write-fetch-head`, run under the store lock. A remote with no `main` yet (a new repository) has nothing to pull. The remote-tracking ref `refs/remotes/<name>/main` stays in the store repository; merge state entries for a git remote use the remote's name as source.
5. **Tags can move.** SPEC 9.6 fetches `+refs/tags/*:refs/tags/*`, which replaces a local tag of the same name, while SPEC 9.4 says tags never move. The spec's refspec is kept, and every moved tag is reported (`tags_moved` in `remote pull --json`, `warning[tag_moved]` in text).
6. **The token helper.** Git runs `!` helpers through a POSIX shell (Git for Windows' too), so the binary's path is written with forward slashes inside double quotes; a path holding `"`, `$`, a backtick or a backslash is refused rather than quoted. `get` answers only when the request's protocol and host equal the remote URL's (so a redirect or a submodule on another host never receives the token); `store` and `erase` read the request and do nothing. The token is in the OS keyring under `git-remote/<name>`; `remote token` reads it from stdin only; `remote rm` deletes it.
7. **`auth = gh`** is accepted only for github.com URLs (SPEC: "offered only for GitHub URLs"). A missing `gh` is a warning when adding; at push time git's helper call then fails and the push reports `remote_auth_failed`.
8. **`create-github`** runs `gh auth status`, then `gh repo create <name> --private`, takes the URL gh prints (adding `.git`), and adds it as a git remote named `github` (or `--name`) with `auth = gh`. Names are checked first, so nothing that looks like a flag reaches gh.
9. **Schedules are stored, not run.** `remote add git` writes SPEC 9.6's example `push = "on-commit"`, `pull = "on-start"`; as for folder remotes, pushes happen on `backup` and `remote push` until a scheduler exists (GUI/daemon work).

## Deviations

- **No REST API fallback and no device flow** for "Create private repository" (SPEC 9.7). Both need an HTTP client the workspace does not have, and the device flow's client id lives in GUI settings. Without `gh`, `create-github` is `tool_not_found` and says to add any repository with `remote add git`.
- **No remote status** (`ahead N`, `behind N`, `last error`, SPEC 9.8): that is History page and Settings work.
- **Git 2.29 or later** is needed (`--no-write-fetch-head`).
- **Outside Windows only git itself is stopped** by the idle timeout; its helpers end when their pipes close (the runner no longer waits for them).
- **The token helper end to end runs through `git credential fill`**, not through a push: no local transport asks for credentials, and an HTTP server is not in the test kit.
- **No warning for a shared `file://` bare repository** (SPEC 9.6 remark): not implemented.
- `cargo deny check` and CI were not run (no cargo-deny locally, no push).

## Review follow-up

A review of the milestone diff found two should-fix items and two safety gaps, fixed in a follow-up commit:

1. **The idle timeout could hang** waiting for pipes held by git's helpers; the runner now never joins the readers after a timeout and stops the whole process tree on Windows (`the_idle_timeout_stops_git_and_its_helpers`).
2. **`auth = token` ignored `--home`**: every spawned git now gets `LOADOUT_HOME` for the data directory in use.
3. **Inherited `GIT_DIR` and friends** are removed from git's environment (`an_inherited_git_dir_never_redirects_a_push`).
4. **Hand-edited `remotes.toml`**: names are checked again before they reach the helper command line, URLs starting with `-` are refused, and the URL follows `--` (`hand_edited_names_and_urls_never_reach_git`). Remote names are also refused when they make an invalid ref (`..`, trailing `.`, `.lock`).
5. Smaller items taken: `create-github` checks the remote name before gh runs; the retry's pull returns its own error; a push stopped by conflicts exits 4; only non-fast-forward rejections are retried; moved tags are warned about in text; auth failures no longer match any `401`/`403` or `permission denied` in a message; `remote add git --json` lists its warnings; the timeout message no longer quotes a fixed number of seconds.
