## Commands (typed IPC)

`list_servers` (rows with one pill per MCP client: `enabled`, `disabled`, `pending`, `drift`, `blocked` with its reason, `not_supported`; row problems such as `missing_secret`), `get_server` (Form draft and the file text; a file that does not load returns only the text and its error, so the TOML tab can fix it), `save_server` (create or update, keeping comments and keys the Form does not show), `save_server_toml`, `remove_servers`, `set_server_clients`, `preview_server` (each enabled client's native entry rendered by the core into its container, `inline` values masked, or why the client cannot have it), `convert_snippet` (paste-anything), `list_secret_aliases`, `pending_plan` (files with masked unified diffs, entries needing decisions, the header count, apply mode), `run_apply` (all, or the selected files' clients), `list_applied_runs`, `undo_apply` (`loadout rollback`, with confirmation), `list_tools`, `reveal_tool_folder` (takes a client id, never a path). Every change is one store transaction with its instant apply (`instant_apply`), so the app and `loadout server add|rm` produce the same commit and apply; changes report the apply outcome and status (the CLI's exit codes 0/1/4/5/7 as an enum). Commands run off the main thread. No secret value crosses IPC: store values are references or literals the leak scanner accepts; rendered entries and diffs are masked by the core; a pasted literal that may be a secret comes back as `needs_secret_extraction` without its value.

## Spec ambiguities resolved

1. **Pills.** One pill per writable client with an MCP config; the page shows detected, selected or non-disabled ones. `pending` covers pending create/update/remove and missing; `drift` covers drifted, conflict and collision (the click opens the drawer; the three-column resolver is M16); `blocked` carries the planner's problem; `not_supported` the OS.
2. **New servers start with no client** (as `loadout server add` without `--client`); "All detected clients" is an explicit choice. Enable All writes an explicit list of detected, supported clients.
3. **Undo this apply** is offered in the change toast and in the drawer's "Recent applies" (the History page comes later); an older run with later changes asks first (`confirmation_required`).
4. **Paste-anything** tries every client container of the snippet's format family in table order, then a bare map or a single entry (Claude Code's mapper for JSON, Codex's for TOML).
5. **Tools page** paths: user files from the adapter table (all candidates, marking missing ones); project files as `<P>/...`. Open folder opens the user file's folder (or its nearest existing parent).
6. **No profile paths in the GUI** (review follow-up): every file the GUI shows (drawer rows and diff headers, apply results, Tools page paths, the About page's data directory) is sent under Loadout's placeholder roots (`placeholder_path`: `~/...`, `<P>/...`, `%APPDATA%/...`, `%LOCALAPPDATA%/...`, client override variables, else `%EXTERNAL%/<name>`), so the user name never appears. The only command that opens something, `reveal_tool_folder`, resolves the path itself from the client id. Tests: the drawer's file and diff header are `~/.claude.json` with no temp-root path (app crate), Tools paths are `~/.claude.json`, and the frontend fixtures use placeholder paths.

## Incident (2026-11-22, during the e2e attempts)

- **What happened.** To get a WebDriver session I ran the e2e with the real `USERPROFILE` and `LOCALAPPDATA` and only partial overrides (`HOME`, `APPDATA`, `XDG_*`, `LOADOUT_HOME`, `CLAUDE_CONFIG_DIR`). The new server was saved as "All detected clients" (the dialog's default then; the spec's uncheck step did not take), and its instant apply at 04:53:33 -05:00 wrote a stdio entry `e2e-fake` (command `fake-mcp-command`, no arguments, no secrets) into real client files:
  - `~\.omp\agent\mcp.json`: entry appended;
  - `~\.grok\config.toml`: `[mcp_servers.e2e-fake]` table appended;
  - `~\.codex\config.toml`: created (only that table);
  - `~\.hermes\` and `~\.hermes\config.yaml`: created.
  Claude Desktop and OpenCode files went to the temp `APPDATA`/`XDG_CONFIG_HOME`; Claude Code to the temp `CLAUDE_CONFIG_DIR`. A second run at 04:54 found the identical entries and adopted them without writing. The run's temp `LOADOUT_HOME` (`%TEMP%\loadout-e2e-*`), including its pre-write backups, was deleted by the spec's cleanup.
- **Revert.** By hand: the entries removed from the omp and grok files (the omp file re-parsed as JSON), the created codex file and `.hermes` folder deleted; a scan of the profile found no leftovers, and the main agent verified it independently. Also: three msedgedriver probes launched the app with the real profile without any UI action (read-only startup queries); an empty `%LOCALAPPDATA%\dev.dailen.loadout` folder (Tauri's app data, 04:46:44) remains from one of them and was left for the maintainer.
- **Cause.** Running the app against the real profile with a partial redirect list, plus a default ("All detected clients") that enabled every detected client.
- **Now enforced.** The app runs only with `USERPROFILE`, `HOME`, `APPDATA`, `LOCALAPPDATA` and `WEBVIEW2_USER_DATA_FOLDER` under `%TEMP%`; the e2e spec checks this before starting the driver (`assertProfileInTemp`), refuses to save if any client is selected, and keeps its temp root (with backups) when a run fails; new servers start with no client; the screenshot script checks the same variables. When WebView2 cannot start that way, the run is recorded as not run.

## Review follow-up (M15 review of 903fc96)

1. **e2e guard (P1).** The guard is `tests/e2e/profileGuard.ts`. `appEnv` builds the app's whole environment from an allowlist (`PATH`, `SystemRoot`, `TEMP`, `TMP`, `ComSpec`, `PATHEXT`, `DISPLAY`) plus the temp profile folders; the spec no longer spreads `process.env`. `assertProfileInTemp` checks `USERPROFILE`, `HOME`, `APPDATA`, `LOCALAPPDATA`, `LOADOUT_HOME`, `XDG_CONFIG_HOME`, `XDG_DATA_HOME` and `WEBVIEW2_USER_DATA_FOLDER`. It refuses any client override variable (`CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `COPILOT_HOME`, `PI_CONFIG_DIR`, `PI_CODING_AGENT_DIR`, `GOOSE_PATH_ROOT`) and any other `XDG_*` variable, comparing names case-insensitively. Before Save, the spec reads every client checkbox in the dialog ("All detected clients" and each client's box) through `Session.selectedAll`. It refuses to save if one is checked or the boxes are not found. `tests/e2e/profileGuard.test.ts` runs in `npm test`, which now also includes `tests/e2e/**/*.test.ts`. The e2e spec itself was not run.
2. **Edit dialog (P2).** `TomlEditor` follows its `value` (`value={tomlText}`; a new value replaces the text and is not reported as an edit). Tab switches sync the two sides. Opening TOML after Form edits writes them into the text with the new `server_draft_to_toml` command, which keeps comments and other keys. Leaving TOML after TOML edits reads the text back into the Form with `server_toml_to_draft`. A text that does not parse, or names another id, shows the error and keeps the TOML tab open. Save therefore always has every edit. Both commands share `parse_server` with `save_server_toml`. Tests: app crate (`edits_keep_comments_and_the_toml_tab_checks_the_id`) and two dialog tests, one per direction, including the stale-editor case.
3. **Pill selection (P2).** The core's `Detected` is now public, with `Detected::system_clients`: `select` (forced on in `clients.toml`, detected, fitting the transport) minus machine exclusions and `clients.toml` opt-outs. `system_entries` uses the same method. `list_servers` pills and `preview_server` take `selected` from it, so `toggledChoice` and `enableAllChoice` turn the core's own set into the explicit list. Test: `pills_and_preview_follow_the_core_selection` covers an SSE server on all-detected. Cursor is forced on but not installed and is selected and written. Codex is forced on without SSE and is neither selected nor pending. Turning Claude Code off keeps Cursor's entry.
4. **Apply selected (P2).** The core adds `PlanOptions.targets` (`TargetFilter`: scope, project folder, file); the planner drops every other target before planning. `PlannedFile` gains `project` (the project folder under its placeholder root). `run_apply` takes `FileRef`s (project id, scope, placeholder path) and matches them to the current plan's targets, so the frontend never sends a real path. The drawer keys and selects rows by `(projectId, scope, file)`, shows the project, and names it in the checkbox label. Tests: `apply_selected_writes_only_the_selected_files` uses two projects' `<P>/.mcp.json` and a pending `~/.claude.json`, and only the selected project file is written. The drawer test checks two identical paths in different projects.
5. **Preview of a stored server (P2).** `preview_server` starts from the stored server when the id exists (keeping `[client.*]`, `[os.*]` and other keys) and applies the draft to it, as `save_server` does. Test: `preview_of_a_stored_server_keeps_its_other_fields` (`native_name` and an `[os.<os>]` command).
6. **Paste conversion (P3).** Core `server_from_native` names a flagged argument by position (`argument 2`), never by value. The paste test gains an args case asserting the message and the literal's absence from the reply.
7. **Drawer diffs (P3).** `PlannedFile.diff` goes through `mask_diff`, which masks every line of the diff, context lines included. It masks `find_in_text` hits (token formats, URL credentials), literal values under sensitive keys as the import classifier sees them (JSON, TOML and YAML pairs), and `--token=VALUE` arguments. Client references (`${NAME}`, `$NAME`, `{env:NAME}`, `%NAME%`, `Bearer ${TOKEN}`), booleans and numbers stay readable. Test: `drawer_diffs_mask_secrets_of_other_entries` puts an unowned entry next to the insertion point with a token assembled at run time, a password and an `--auth-token=` argument. It also asserts what stays readable.
8. **Tools Open folder (P3).** `folder_of` loads the desired state and uses the same `clients.toml` preferences as `list`. Test: `open_folder_follows_the_listed_profile` sets omp `profiles = ["work"]`.

Other changes for these fixes: core `ApplyEnv::render_cx` is public (the app builds the render context for selection and preview), and the CLI's `apply` sets `targets: None`. `src/ipc/bindings.ts` was regenerated.
