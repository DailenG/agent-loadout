# M38 Read-only contexts: GUI (0.4.0, #4): completion note

Not committed (the maintainer commits). Frontend slice of 0.4.0 against the M37 IPC contract (`docs/milestones/M37.md`, "IPC contract"). Loadout shows client files, skill folders and projects that this account cannot write, says why in plain words, and disables (never hides) the controls that would write them. Viewing, diffing, copying a definition and importing a definition stay available.

## Bindings

M37 has not regenerated `src/ipc/bindings.ts` yet. The contract's fields are hand-added there, each marked `/* M38 TEMPORARY */`:

- types `ReadOnlyKind`, `ReadOnly`, `ReadOnlyFile`, `ReadOnlyLayer` (after `ErrorCode`);
- `ErrorCode` gains `"read_only_target"`;
- `readOnly: ReadOnly | null` on `AppliedFile`, `ClientPill`, `DiscoveredProject`, `ImportSource`, `LayerRef`, `PlannedFile`, `ProjectRow`, `ProjectScopeInfo`, `SkillClient`, `SkillLinkNote`, `SkillProject`, `ToolFile`, `ToolSkillDir`, `UnmanagedGroup`;
- `readOnlyFiles: ReadOnlyFile[]` on `ProjectRow`, `readOnlyLayers: ReadOnlyLayer[]` on `ProjectScopeInfo`.

`npm run bindings` replaces the whole file. Diff the result against these fields; nothing else in the frontend reads the markers.

## Shared component (`src/app/components/ReadOnlyBadge.tsx`)

- `ReadOnlyBadge`: `text` form (lock + "Read only", `status-badge tone-warning`, focusable, `aria-describedby` with the reason, `data-tooltip`) and `mark` form (lock alone with `role="img"` named "Read only", for chips; the chip's control is described by the hidden reason, as `RecommendedBadge` does). `focusable={false}` inside a card's summary button. Renders nothing for `null`.
- `readOnlyReason(kind)`: `acl` "its permissions do not let your account write it", `attribute` "it is marked read only", `owner` "another user owns it and your account has no write permission", `share` "the network share or drive it is on does not allow writing".
- `readOnlyTooltip(readOnly, path?)`: "`<path>` is read only: `<reason>`. Loadout shows it and does not change it."
- `ReadOnlyNote`: a lock and the explanation next to disabled controls (`role="note"`).
- `errorMessage("read_only_target")`: "This file or folder is read only for your account; Loadout left it as it is."

## Decisions and open questions

1. MCP row badge: shown only when a *selected* client's file is read only (an unselected read-only client shows only on its pill), to keep the list quiet. Kept (Main).
2. Bulk actions (MCP and skills): decided by Main. They send what they always did; the backend reports the read-only client as blocked. Only the single read-only pill is disabled, with its lock and reason.
3. Drawer checkbox of a read-only file stays enabled (ledger-only work still applies). Kept (Main).
4. `AppliedFile.readOnly`: shown only as a count in the apply result toast that already summarizes the run (Main).
