# M36 Compact not-managed notice (0.3.1, #9): completion note

Not committed (the maintainer commits). Frontend fix B of the 0.3.1 plan, from the real-app sandbox check of 0.3.0: at the default window size the M33 notice (the whole message plus Review and Dismiss) pushed Import, History, Settings and About below the fold.

## What changed

### Notice (`src/app/routes/import/UnmanagedNotice.tsx`)

- **Expanded sidebar**: one line, a button with a warning icon and the short text "N not managed" (N = MCP entries plus skill folders not acknowledged yet; `import.notice.short`). It is a disclosure (`aria-expanded`, `aria-controls`) inside the same `region` "Not managed by Loadout".
- **Details**: a click, Enter or Space opens the full message ("omp has 2 MCP servers not managed by Loadout. 5 skill folders are not managed by Loadout.") with **Review** and **Dismiss** in a panel that floats above the line (`position: absolute`), so opening it never makes the sidebar taller. Tab moves from the line into the panel. Escape closes it and returns focus to the line; a press outside the notice closes it too. Opening and closing acknowledge nothing.
- **Collapsed sidebar**: unchanged count badge only (its name and tooltip are the whole message plus "Review"; a click reviews).
- **Kept**: the polite live region mounted while the app runs and announcing the whole message; Review and Dismiss acknowledging exactly what was shown (MCP ids through `acknowledge_unmanaged`, skill folder keys in the webview's storage); the Settings switch; the drift triggers.

### Sidebar CSS (`src/styles/tokens.css`, `/* M36 … */` block)

- The notice rules moved out of the M33 block into M36 and were rewritten for the one-line toggle, the floating panel and the badge. Colors only from existing tokens (`--line`, `--surface-strong`, `--heading`, `--muted`, `--warning-soft`, `--warning-text`); the hover and open background lays `--warning-soft` over `--surface-strong` so nav items under the sticky line never show through.
- **Short windows**: since M33 added Import, nine nav items no longer fit at 600px tall even with S6's 40px items (finding 20), and at 1088x680 the notice line covered About. Two tiers replace S6's `max-height: 600px` rule (removed from the M28c block):
  - `max-height: 720px`: 40px nav items (expanded and collapsed sidebar);
  - `max-height: 650px`: 32px items with 24px icons, 4px gaps, tighter brand block, scope switcher, divider and bottom padding, and a smaller margin above the notice.

### Other

- `src/i18n/en.ts`: `/* M36 */` block with `import.notice.short`.
- `CHANGELOG.md`: Unreleased > Changed entry.

## Tests

`src/app/routes/import/UnmanagedNotice.test.tsx` (10, was 7): the existing tests now expand the line before reading the message or pressing Review/Dismiss (`openNotice`), plus:

## Layout check (mock build)

jsdom does no layout, so the "never pushes nav items out of view" check ran in the mock screenshot pass: `vite build --mode mock` into a temp folder, `vite preview` on port 4736, the eval browser (headless WebKit, Windows chrome so the 32px sidebar top bar is drawn), the mock's notice "7 not managed" (omp's two MCP entries and five skill folders). For each height the last nav item's bottom, the notice's box and the sidebar's overflow (`scrollHeight - clientHeight`) were measured, expanded and collapsed sidebar:

| Height | Sidebar | About bottom | Notice | Overflow |
| --- | --- | --- | --- | --- |
| 560 | expanded | 504 | 510-540 | 0 |
| 560 | collapsed | 474 | 480-516 | 0 |
| 600-650 | both | same as 560 | same as 560 | 0 |
| 651-720 (incl. 1088x680) | expanded | 586 | 598-628 | 0 |
| 651-720 (incl. 1088x680) | collapsed | 572 | 584-620 | 0 |
| 721, 760, 900 | expanded | 658 | 670-700 | 0 |
| 721, 760, 900 | collapsed | 652 | 664-700 | 0 |

No overlap and no sidebar scrolling at any height from the 560px minimum up; the short text is never truncated. With the details open the panel sits above the line (1088x680: 371-592; 960x560: 283-504) and the overflow stays 0. A project scope (web-shop) at 960x560 measured the same. Before the change, 960x560 overflowed by 86px (About at 586) and 1088x680 by 36px. Server stopped, temp build removed.
