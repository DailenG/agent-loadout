## Spec ambiguities resolved

1. **Read-only adapter.** SPEC 7.3 says `vscode-legacy` is "never written" but it is a client id in the table. It is a registered adapter with `McpSpec::read_only`: the one choke point `writable` refuses it, so system and project planning (including a server added with `server add --client vscode-legacy`) and the effective view's explicit selection report `read_only_client`; `all-detected`, for store servers and for unresolved project entries alike, never selects it; adopt never enables it.
2. **Variants and profiles.** `import_variants` (default `["Code"]`) times `import_profiles`: `default` is `User/mcp.json`; `all` adds every `User/profiles/<id>/` holding an `mcp.json`, sorted; a list names ids, with `default` meaning `User/mcp.json` (as omp's `profiles` list does) and ids that are not one plain path component refused. The first file (Code, default profile) stands for VS Code in the effective view.
3. **Import from a read-only source.** SPEC 8.6 enables an imported server "for the clients where it was found". A read-only client is left out: a server found in VS Code and Copilot is enabled for Copilot; one found only in VS Code is imported without an enable list. Enabling `copilot` for it was not assumed.
4. **`${input:...}`.** Checked before the variable conversion, in every imported field, as `needs_manual_secret` naming the field. Other VS Code variables (`${workspaceFolder}`, `${userHome}`) stay `unsupported_field`, as for Cursor.
5. **Shared `<P>/.mcp.json` (SPEC 6.5).** The planner already joins clients whose target is the same file and container. Copilot writes `type` on every entry and Claude Code's field names, so plain entries are identical for both; when they differ (a tool filter, `cwd`, a URL reference only Claude Code expands) the entry is blocked as `collision` naming both clients. The ledger records the first client that wanted the entry.
6. **Copilot spellings.** The Copilot CLI writes `"type": "local"` and `"tools": ["*"]`; both read as Loadout's stdio entry without a filter, so adopt sees them as equal. Loadout writes `stdio` and omits `tools` when there is no filter.
7. **"Never emits" editor-only fields.** Copilot's mapper removes `inputs`, `envFile`, `dev` and `sandbox` even when an existing entry has them; such an entry differs canonically, so the plan shows the change (collision or drift) before overwriting.
8. **Compatibility sources and readers.** SPEC 6.4 lists readers like `copilot` and omp's `.cursor/`/`.vscode/` reads; the Tier A filter M9 applied is replaced by "has an adapter in this build", for both compatibility sources and `also_visible_to`. Copilot reads `vscode-legacy` project and user files as `client-compat`.
9. **Copilot project semantics.** SPEC 7.4 has `[verify]`; the adapter declares precedence project over user with `ProjectSemantics::Unknown` (only `DeepMerge` changes the effective view).
10. **Detection.** Copilot: `$COPILOT_HOME` or `~/.copilot`, `copilot` on `PATH`, the `~/.vscode/extensions/github.copilot-chat-*` dir. Cursor: `~/.cursor`, `<AppData>/Cursor`, `cursor` on `PATH`, uninstall entry `Cursor`. VS Code: each variant's `User` dir, `code`, `code-insiders`, `codium`.
