# M49 Optional external scanner: the app (0.7.0, #27)

Status: implemented against the M47 contract (docs/milestones/M47.md). Not committed (the maintainer commits).

The GUI for Snyk Agent Scan: Settings > Security, the External scan section of the skill install and update
reviews, and Scan with Snyk on a library skill. The backend, CLI and app commands are M47.

## What was built

- **Settings > Security** (`src/app/routes/settings/security/SecuritySection.tsx`), between Sources and Catalogs:
  - **Snyk Agent Scan (optional)**: the disclosure, always shown before anything is on. It says what it does
    (a second opinion on skills before install or update, and on a library skill on request; skills only, never
    MCP servers), that the skill goes to Snyk's analysis service in the cloud, and the list of what is sent: every
    file of the skill (Snyk redacts secrets it detects), the path of the scanned folder (a temporary copy in
    Loadout's data folder), the user name, the host name on macOS and Linux (the scanner reports none on Windows),
    the scanner version. Loadout doesn't pass a machine serial number, other environment variables or Loadout
    data and never starts or contacts MCP servers. It needs a Snyk API token (`SNYK_TOKEN`); the free tier has a
    daily limit, after which skills are "Not scanned" and nothing is blocked; nothing is sent while it's off.
  - **Status**: Not available (no build for this platform), Not installed, Needs a token, Off or On, with a line
    saying what that means.
  - **Scanner**: Install (the pinned version and its download size, "from Snyk's GitHub releases ... checks it
    against the SHA-256 built into Loadout. It isn't added to PATH."). While installing: a progress bar fed by
    `ScannerInstallProgress` events ("Downloading: 6.4 MB of 25.5 MB") and **Cancel** (`cancel_external_scan`,
    which also cancels an install; error `canceled` = "Install canceled; nothing was installed."). Installed: the
    verified-version line "Snyk Agent Scan 0.7.1, installed and verified: its SHA-256 matches the build pinned in
    Loadout." and **Remove**, confirmed in an alert dialog that starts on Cancel (settings are kept).
    `scanner_download_failed`, `scanner_verification_failed` and `not_supported_on_os` are toasts in words.
  - **Snyk token**: the reference and its kind ("Environment variable: `env:SNYK_TOKEN`"), never a value.
    **Set token... / Change...** opens a dialog: where the token is (a secret from the Secrets page, picked from
    `list_secret_aliases` with the app's select; an environment variable name; a 1Password reference
    `op://vault/item/field`; an OS keyring entry `keyring://service/account`). Save is enabled only for a
    well-formed reference (`op-env://` is not one); `invalid_ref` is shown in the dialog. There is no field for
    the token itself: to keep it in the keyring, add it as a secret on the Secrets page and pick that secret.
    **Check** (`check_scanner_token`) says whether the reference resolves, never what it resolves to; **Clear**.
  - **Use Snyk Agent Scan**: the switch, disabled until the scanner is installed and a token is set (it can
    always be turned off).
- **External scan in reviews** (`src/app/components/ExternalScan.tsx`): `useScannerStatus`, `useExternalScan`
  and `ExternalScanSection`, used by the install review (`SkillReviewDialog`, `external_scan_review(token)`)
  and the update review (`SkillUpdateDialog`, `external_scan_update(id, latest)`).
  - Only when `scanner_status().enabled`: otherwise there is no section and no `external_scan_*` call.
  - One run when the review opens; "Scanning with Snyk Agent Scan (up to a minute)..." with **Cancel scan**;
    Install / Update (and "... anyway") are off while it runs. Closing the review while it runs cancels the run.
  - The section, below the built-in findings: "External scan", "Snyk Agent Scan 0.7.1", a badge (the verdict,
    "Not scanned" or "Not understood") and the count; "Snyk Agent Scan sends this content to Snyk's analysis
    service. Turn it off in Settings > Security." Findings: the severity badge (mapped from Snyk's score by the
    core), Snyk's risk in words ("Suspicious download", "Prompt injection in the instructions", ...; an unknown
    risk shows as sent), `file:line`, Snyk's explanation, and "Malicious URL" / "Unverifiable URL" over the URL.
  - `not_scanned`: "Not scanned (<reason>)." for every `ExternalNotScanned` reason (Snyk limit reached, timed
    out, canceled, Snyk couldn't be reached, too large for Snyk, no Snyk token set, ...), Snyk's `detail` line if
    any, and "A skill that wasn't scanned isn't blocked; the built-in scan's findings still apply."
    `not_understood`: "Scanner output not understood (version 0.7.1)." and that it doesn't count as clean. Both
    offer **Scan again**; neither gates.
  - A `scanned` + `dangerous` result gates like the built-in scan: Install / Update become **Install anyway** /
    **Update anyway**, enabled only after "I read the findings and want to go ahead anyway". When only the
    external verdict is dangerous the box says "Snyk Agent Scan rated this content (the new version) dangerous
    ...". The tick is reset whenever the result shown changes (a new run), so it always covers the exact scan on
    screen, which is also the one the backend remembered for the install or update.
- **Scan with Snyk** (`src/app/routes/skills/SkillExternalScan.tsx`): a button in a skill's details (list and
  grid) while the scanner is on, for a skill with content; it opens "Snyk Agent Scan: <skill>" running
  `external_scan_skill(id)` once, a report that changes nothing.
- **Transport**: `TransportEvents.onScannerInstallProgress` (`events.scannerInstallProgress`). The install
  subscribes before calling `install_scanner` and unsubscribes when it ends.
- **Errors**: `scanner_unavailable`, `scanner_download_failed`, `scanner_verification_failed` and `canceled`
  in words; `scan_blocked` now says "A scan (Loadout's built-in scan or Snyk Agent Scan) found dangerous
  content ...", as either gate can refuse.
- **Mock** (`src/test/scannerData.ts`, wired into `createMockTransport({ scanner })`): a stateful scanner
  (supported, installed, enabled, token reference, token check), install with progress events, delay, cancel
  and failure, external scans with delay and cancel, `scanner_unavailable` while off, `not_installed` /
  `no_token` without running; fixtures for every state (clean, warning, dangerous, every not-scanned reason via
  `externalNotScanned`, the limit with Snyk's message, not understood). The mock gate adds a `scanned` external
  result to the review's or update's gate, so a dangerous one refuses without `allowDangerous` like the core.
  `npm run dev:mock` takes `?scanner=on|fresh|ready|limit|garbled|slow|unsupported` (default `on`).

  doesn't block, Scan again runs again and the box starts unticked; the limit, a timeout, no token and
  unreadable output never block and never read "Clean"; Snyk's limit message shown; Install off while

  Snyk offered only while on and reports the store copy's result; the mock gate refuses a dangerous external
  result without `allowDangerous` and never a not-scanned or not-understood one.

## Review fixes (local://review-M49.md, frontend; backend parts by M47)

IPC changes (M47, bindings regenerated): `external_scan_review(token, runId)`, `external_scan_update(id, latest,
runId)`, `external_scan_skill(id, runId)`, `cancel_external_scan(runId | null)`; `ExternalScannerStatus.timeoutSecs`;
`open_help` topics `snyk_terms` and `snyk_privacy`; a second `install_scanner` is `locked`; `external_scan_update`
drops the remembered report first and `set_scanner_enabled(false)` forgets every external report. M47Fixes then
added `external_scan_required` (install / update of Git or catalog content while the scanner is on and no report is
attached; local reviews are exempt, a canceled run attaches its `canceled` report), which the app words as "Snyk
Agent Scan is on but hasn't scanned this content yet ...", and `remove_scanner` turning the switch off itself (the
app's extra `set_scanner_enabled(false)` is then skipped, as the returned status is already off).
